## ⚠ BLOCKER — half the screen follows the setting and half does not

**Darkness is snapshot-carried**, so the lightmap and FoV half is nearly free: `codec.rs:264`
packs `world.darkness()`, and the two `serverDarkness ||` sites read it. Change `World::darkness()`
(`world/mod.rs:3314`) and that half follows.

**The sky does not.** `sky.ts:128` computes `const u = cycleU(roundTime)` **locally** and
derives `skyPhase(u)`/`skyColors(u)` from it — its own doc comment says *"`darkness` is the
server's scalar; the sky only uses it to fade the stars."* So under night-only **the lightmap
goes black while the sky paints a noon gradient with the sun up**, and every simulation
assertion passes. `sky-math.ts` has **five** independent `cycleU(u * CYCLE_LENGTH)`
derivations (`:51, :84, :116, :153, :206`) — this is not one call site.

**And day-only is broken on the client before anyone writes a line.**
`this.serverDarkness || darknessAt(...)` treats a legitimate darkness of **0 as falsy**.
Today that is invisible because at true noon the local fallback also returns ~0. Under
day-only the server says 0 all round, the `||` falls through to the local cycle every frame,
and **the client goes to night at `u > 0.5` while the server holds day.** Make it `??`, or an
explicit `hasServerDarkness` flag. No server test would ever notice.

**And the sandbox is the T20.05 shape again:** `SandboxScene.ts:670,839` compute darkness
locally with **no server value at all**, so a server-side mode is invisible to every check
driven by `?sandbox=1` — including `night-combat`.

## This is not `round_seconds`' shape

`round_seconds` is a number the server reads. `cycle_at`/`darkness_at` are **pure functions of
`round_time` alone** that the client **independently reimplements** in `sky-math.ts`, with
their agreement pinned by `cycle.rs:284 cycle_matches_the_client`. Threading a mode through
them is a signature change across three Rust call sites (`world/mod.rs:841,1026,3315`), the
wasm bridge (`game-wasm:1669 core_darkness_at`), the TS copy, and that parity test.

## Deliverable

- A three-way setting — **cycle / day only / night only** — following `round_seconds`'
  established path exactly: a `constants.rs` bound, four-place exposure, a `ReplayCommand`
  variant with the **next free tag**, a `check_settings_change` gate, and the lobby panel row.
- **Private lobbies only**, like the other three. Public matches take the default.
- **A randomisation hook, off by default.** The brief asks for the *ability* to randomise
  public matches later — so build the seam, not the behaviour: a config flag that, when set,
  draws the mode from the room's seeded RNG at match start. Default off, and **one test that
  it is off by default**.

## Notes

- **The mode is simulation state, so it belongs in the replay header, not only as a command.**
  T20.07's own follow-up learned this the hard way: a setting that lives only as a lobby
  command is **lost across a round restart**, because round two's file gets a fresh header and
  a command stream that starts after the restart. Read
  `T20.07 follow-up: a lobby setting belongs on Config, not on Room` before choosing where the
  field lives.
- **If it goes in the header, that is a `REPLAY_VERSION` bump** — and T20.07 and T20.08 may
  already have moved it. **Check `HEAD` before bumping**; the version must not move twice for
  one release.
- Randomisation drawn from the room's seeded RNG is fine. Drawn from anything else breaks
  determinism, and `game-core` forbids ambient randomness outright.
- Night is not merely darker: `fov_radius` reads it, and T20.07's flashlight work reads
  `fov_radius`. **Night-only makes the flashlight matter and day-only makes it inert** — worth
  a line, because a day-only match plus a flashlight buff is a dead item.

## Tests

- Each of the three modes produces the light level it claims, sampled **across** the cycle —
  not at one instant, which passes for a clock that is stuck.
- **Rendered pixels (§C2), and specifically the sky.** "The light level it claims" is
  satisfied by `debug().darkness` on a page whose sky is painting noon — which is exactly the
  blocker above. Assert the sky region, with a control region and a control frame.
- **Day-only holds day for a whole round on the client**, which is the `||`-vs-`??` defect
  asserted directly.
- The control: cycle mode still moves.
- The randomisation flag is **off by default**, asserted directly; and when on, a fixed seed
  gives the same mode twice.
- The setting survives a round restart — the T20.07 follow-up's test is the model.

## Tests at risk — none of the M21 files had this section; this one now does

- `cycle.rs:114 a_round_starts_in_full_daylight` asserts `darkness == 0` at t=0.
- `darkness_follows_the_phase_table_not_the_old_transition`,
  `the_curve_is_continuous_across_a_whole_round`, `each_ramp_is_monotonic` all assert the
  **cycling** curve.
- `cycle.rs:284 cycle_matches_the_client` is the TS↔Rust parity pin and moves if either copy
  does.

Whether these break depends on **where** the mode is threaded. **Say which way you intend to
go before you start**, and replace rather than delete: each of them asserts something true of
cycle mode, which still exists.
