## Deliverable

```rust
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub enum EffectKind { ToxicRain, MeteorShower, LavaBurst, HeavyFog }

#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub enum EffectPhase { Telegraph, Active, Done }

pub struct ActiveEffect {
    pub id: u32,
    pub kind: EffectKind,
    pub phase: EffectPhase,
    pub started_at: f32,
    pub phase_started_at: f32,
    pub seed: u64,           // for cosmetic client-side variation only
}

pub enum EffectEvent {
    Started { id: u32, kind: EffectKind, seed: u64, duration: f32 },
    PhaseChanged { id: u32, phase: EffectPhase },
    Ended { id: u32 },
}

pub struct EffectScheduler {
    rng: ChaCha8Rng,
    next_at: f32,
    active: Vec<ActiveEffect>,
    last_kind: Option<EffectKind>,
    next_id: u32,
}

impl EffectScheduler {
    pub fn new(seed: u64, round_start: f32) -> Self;

    /// Called once per tick during Playing. Advances phases and may start one.
    pub fn tick(&mut self, now: f32, round_ends_at: f32) -> Vec<EffectEvent>;

    pub fn active(&self) -> &[ActiveEffect];
    pub fn is_active(&self, kind: EffectKind) -> bool;
}

pub fn active_duration(kind: EffectKind) -> f32;
```

Weights: `ToxicRain` 3, `MeteorShower` 3, `LavaBurst` 2, `HeavyFog` 2.

## Notes

Three-phase machine per effect: `Telegraph` for `EFFECT_TELEGRAPH` (3 s), then
`Active` for the effect's own duration, then `Done`.

The telegraph is not decoration — three seconds is exactly enough to get out of the
open, so being caught becomes a decision rather than bad luck.

**Never repeat the same kind twice in a row**: if the weighted roll matches
`last_kind`, re-roll once (once, not until it differs — a loop biases the
distribution).

Two suppression rules:
- no effect starts during `Warmup` (the caller gates this, but assert it);
- no effect starts if `now + EFFECT_TELEGRAPH + active_duration(kind) >
  round_ends_at`. An effect running past the round end is confusing and can kill
  someone after the scoreboard has appeared.

`next_at` advances from the previous scheduled time, not from `now` — the same
anti-drift rule as T4.05.

The `seed` on each effect is for **cosmetic** client-side variation only (particle
jitter, sprite variants). All gameplay-relevant hazard positions are broadcast
explicitly (`docs/13-weather-effects.md` §7), because a client rolling its own lava
positions means someone standing in fire they cannot see.

Uses `substream(seed, "weather")`.

## Tests

- Determinism: the same seed produces the same `(time, kind)` sequence over a full
  round, 20 times.
- The first effect fires between `EFFECT_INTERVAL_MIN` and `EFFECT_INTERVAL_MAX`.
- Intervals stay within that band across 100 effects.
- The same kind never fires twice consecutively, over 1000 effects.
- Weighted distribution over 10 000 rolls matches 3:3:2:2 within 3 % (accounting for
  the no-repeat rule).
- Phase transitions: `Telegraph` for exactly `EFFECT_TELEGRAPH`, then `Active` for
  exactly `active_duration(kind)`, then `Done`.
- Events fire once per transition, never twice.
- No effect starts within `EFFECT_TELEGRAPH + active_duration` of `round_ends_at`.
- `is_active` is true only during the `Active` phase, not during `Telegraph`.
- Overlapping effects are supported: force two and assert both appear in `active()`.
- `tick` called twice with the same `now` does not double-advance.
- Cadence does not drift over 100 intervals.
