## Deliverable

```rust
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub enum DayPhase { Day, Night }

#[derive(Copy, Clone, Debug)]
pub struct CycleState { pub phase: DayPhase, pub darkness: f32 }

/// Darkness at a given round time. Pure — the client computes this locally too.
pub fn cycle_at(round_time: f32) -> CycleState;

/// The one FoV formula, shared by the client renderer and (later) server culling.
pub fn fov_radius(darkness: f32, fog_mult: f32, health: f32, flashlight_on: bool)
    -> f32;
```

The formula, exactly as `docs/14-daynight-visibility.md` §3:
```
fov = lerp(FOV_DAY, FOV_NIGHT, darkness / NIGHT_DARKNESS)
    * fog_mult
    * lerp(FOV_HEALTH_MIN_MULT, 1.0, clamp01(health / BASE_HEALTH))
    * if flashlight_on { FLASHLIGHT_AMBIENT_MULT } else { 1.0 }
```

## Notes

The cycle: `DAY_DURATION` (60) then `NIGHT_DURATION` (60), repeating, with
`CYCLE_TRANSITION` (8 s) split evenly across each boundary — 4 s before, 4 s after.
Use `smoothstep` across the transition so there are no visible corners.

**A round always starts in day.** The first 60 seconds are a fair fight and players
have time to find a flashlight before the first night. A 240 s round therefore
contains exactly two days and two nights.

`darkness` is a single scalar in `0.0 ..= NIGHT_DARKNESS` (0.82). It is quantised to
one byte in the snapshot header (`docs/40-net-protocol.md` §3) — the client also
computes it locally and uses the server value only to correct drift, so precision
here is not critical, but continuity is.

**`fov_radius` is the single implementation.** T3.10 has a TypeScript copy for
rendering; that one must be replaced by, or verified against, this. State in a
comment that this is the authority. Later, server-side visibility culling
(`docs/14-daynight-visibility.md` §8) uses it unchanged.

`fog_mult` is passed in rather than read from a fog object, so this function stays
pure and testable without constructing an effect.

This file computes; it does not decide anything. The server broadcasts
`phase_change` on each flip (T6.07).

## Tests

- `cycle_at(0)` is `Day` with `darkness == 0.0`.
- `cycle_at(64)` (60 + half the transition) is `Night` with
  `darkness == NIGHT_DARKNESS`.
- `cycle_at(124)` is back to `Day` with `darkness == 0.0`.
- **Continuity**: sampling every tick across a full 240 s round, no consecutive pair
  differs by more than one tick's worth of change. This is the test that catches an
  off-by-one in the transition windows.
- Monotonic within each transition.
- A 240 s round contains exactly two `Day` spans and two `Night` spans.
- The transition is symmetric: darkness at `60 - 4` equals darkness at `60 + 4`
  mirrored around 0.5.
- **`fov_radius` endpoints**: day/full health/no fog/no light → exactly `FOV_DAY`.
- Full night, full health → exactly `FOV_NIGHT`.
- Full night + fog → `FOV_NIGHT * FOV_FOG_MULT`.
- 0 health at day → `FOV_DAY * FOV_HEALTH_MIN_MULT`.
- Flashlight on → the ambient radius shrinks by exactly `FLASHLIGHT_AMBIENT_MULT`.
- All four modifiers together equal the explicit product.
- Health of 150 (overheal) gives the same as 100 — the clamp holds.
- `fov_radius` is never negative or NaN for any input in range.
