# T11.10 — Draw the ordnance the server already sends (v3)

Milestone: M11 · Depends on: T11.05, T11.06, T11.07 · Size: ~250 lines

## Why this task exists

T11.05–T11.07 completed the **simulation** of melee, the flamethrower and mines,
and each task's **Done when** (`cargo test -p game-core …`) passes. Their client
rendering did not land. So `game-server` now emits four events that **nothing
subscribes to**:

| event | emitted by | consumed by |
|---|---|---|
| `melee` | `world::fire` | nothing |
| `cone` | `world::fire` | nothing |
| `mine_placed` | `world::fire` | nothing |
| `mine_ended` | `emit_blast`, `Mines::step` | nothing |
| `hazard_spawn` (Fire/Toxic/Smoke) | T11.08's `burst_zone`/`burst_smoke` | counted, never drawn |
| `hazard_ended` | T11.08's smoke expiry | nothing |

That is §A39's shape — the tenth instance on this project, and this time
self-inflicted with the pattern fully documented. It matters more than usual
because the design says so explicitly:

- §B6: *"a mine must be **visible** at close range — invisible instant death is
  not fun; a trap you could have spotted is."* A mine nobody can see is the exact
  failure that section names.
- T11.05's notes: *"a melee hit you cannot see reads as damage from nowhere."*
- T11.08 added three hazard kinds on the same channel. `GameScene` already
  *counts* `hazard_spawn` for its observation record and plays a sound for some
  kinds, but nothing draws any of them — so a molotov's fire, a toxic zone and a
  smoke cloud are all invisible ground you take damage on or cannot see through.
  Smoke is the worst of the three: it changes what you can see (the server sends
  the multiplier in the snapshot's vision byte, so the *effect* is real) while
  showing you nothing that explains why.

The sandbox's WASM fire path already returns explicit
`melee_not_in_sandbox` / `cone_not_in_sandbox` / `placed_not_in_sandbox`
rejections rather than a silent no-op, so the gap is visible there rather than
looking like a misfire. This task closes it in the networked client.

## Touch only
- `client/src/render/{melee,flame,mines,hazards}.ts` (+ their `-math` halves and tests, §A8)
- `client/src/net/worldMirror.ts` (subscribe)
- `client/src/scenes/GameScene.ts` (mount the layers)
- `crates/game-wasm/src/lib.rs` (the sandbox path, once the layers exist)

## Deliverable

Three pooled layers, fed from the events above:

- **Melee** — a swing arc at the event's `aim`, `reach` and `arc`, ~0.15 s,
  brighter when `hits > 0`. Pool it: a knife at 0.35 s cooldown must not allocate.
- **Cone** — a flame spray for `particle_life`, plus the burning ground it leaves.
  Both are **light sources** at night, like every other emitter (§A3).
- **Mines** — a placed marker that reads at 40 px and not at 300, with a distinct
  armed state after `MINE_ARM_TIME`, removed on `mine_ended` and **differently**
  for `Detonated` vs `Destroyed` vs `Expired`.

## Notes

- §A8: pure bookkeeping in a `-math` file, the Phaser class imports it.
- §B12: render through the same paths the game uses; do not grow a second one.
- A layer that receives an event for an id it never saw placed must not throw —
  a mid-round joiner has exactly that history.

## Tests

- **Count at both ends** (§A39): a round in which a mine is placed and destroyed
  must show the client's live-mine count going 0 → 1 → 0, asserted against the
  server's. That is the assertion whose absence let this ship.
- Melee arcs expire; the pool does not grow under sustained swinging.
- `mine_ended` with an unknown id is a no-op.
- Falsify each by removing its subscription — the count assertion must go red.
