# T11.12 — One spec breaks the next one (v3)

Milestone: M11 · Depends on: T11.09 · Size: investigation, then a harness fix

## The repro, which is cheap and deterministic

```sh
node scripts/e2e.mjs m5-weather two-clients     # two-clients FAILS
node scripts/e2e.mjs two-clients                # PASSES
```

Three standalone runs pass; every run with `m5-weather` (72 s) ahead of it fails.
It is **not** a flake and it is **not** CPU contention, which is what the T10.07
and T11.07 journal entries assumed.

`ordnance` fails the same way when placed directly after `m5-weather`, and passes
in the full suite where `death` sits between them.

## The symptom points at the client, not the server

- `two-clients`: `bo held D and moved only 0.0 px locally`, and `no terrain was
  destroyed (ana removed 0 px)`. **Exactly zero**, not "less than expected".
- `ordnance`: `timed out waiting for the rocket to end the mine`.
- In both, the page is otherwise healthy — the map decodes, items draw
  (`9 drawn of 9 tracked`), checksums match.

So the client renders and receives, and its **fixed-timestep loop does not
advance**. The leading hypothesis is Chromium throttling `requestAnimationFrame`
on pages that are not foreground: the suite holds its own page open while a
standalone spec opens two or three more contexts, and only one can be frontmost.
That would explain zero movement, zero firing and a healthy-looking frame at once.

**Verify the hypothesis before fixing it.** Sample a frame counter across the
pages and show which ones are advancing; do not assume.

## Not caused by the T11.09 session — controlled

`git stash` of that session's two script edits, then `node scripts/e2e.mjs
m5-weather two-clients`, still fails. The edits are exonerated and the bug
predates them.

## Candidate fixes, cheapest first
- Launch Chromium with the backgrounding flags off
  (`--disable-background-timer-throttling`,
  `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding`).
- Have standalone specs run with the suite's own page closed.
- Drive the sim from a timer the harness controls when `?e2e=1`, so a check never
  depends on the browser choosing to animate.
