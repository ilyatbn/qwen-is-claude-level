# T11.11 — Art for the arsenal (v3)

Milestone: M11 · Depends on: T11.08 · Size: ~180 lines

## Read first
- `docs/71-amendments-v3.md` §B20
- `docs/50-sprites-skins.md` §8, `docs/51-assets.md` §9

## Why

Thirteen new items reference sprite keys absent from `atlas-map.json`. They fall
back to placeholders, so nothing breaks — and **every new weapon looks identical on
the ground and in the inventory**. In a game whose pitch is "tons of weapons", a
pickup you cannot identify is the feature not working.

## Touch only
- `assets/atlas-map.json`, `scripts/build-atlas.mjs`
- `client/src/render/weaponSprites.ts` if a procedural fallback is needed
- `scripts/verify-assets.mjs`

## Deliverable

Every item in the registry resolves to a distinct frame. Kenney's `pixel-platformer`
is already vendored; where it has nothing usable (side-view lasers, a flamethrower,
a whip), draw procedurally as T7.04 already does for the original three weapons —
`skins.json` records that as `atlas: null` so muzzle and pivot survive.

## Notes

- **Distinct by silhouette, not by palette.** At 16×16 on the ground, outline is all
  a player can read — the same conclusion T10.05 reached for tombstones.
- A weapon in the hand, on the ground, and in the inventory slot uses the **same**
  frame, so what you picked up is what you are holding.
- `verify-assets` must reject a terrain tile used as an item sprite, the way §A32's
  opacity rule already rejects one used as a decoration.

## Tests

- **Point the check at the live registry, not a fixture** (§B20): every
  `ItemDef.sprite` in the actual registry resolves in the actual manifest, and the
  test names any that do not.
- Falsify by removing one frame — the test must name that item.
- No two items resolve to the same frame.
- With `assets/atlas/` emptied, the game still boots and every fallback logs exactly
  once (`docs/51` §9).

## Done when

```sh
npm --prefix client test -- --run itemSprites && node scripts/verify-assets.mjs
```
