## Deliverable

```rust
/// Roll an item id from a weight column.
pub fn roll_item(rng: &mut ChaCha8Rng, col: WeightColumn) -> ItemId;

/// Stack size for a fresh spawn: max_stack for weapons, 1 for everything else.
pub fn spawn_count(item: ItemId) -> u8;

/// Place the round's starting items on the ground. Called once, after map
/// generation and before players spawn.
pub fn place_initial(
    world: &mut WorldItems,
    map: &Map,
    seed: u64,
    now: f32,
);
```

Rules from the doc's §2:
- `INITIAL_ITEMS` items (8 / 14 / 20 by scale).
- Positions drawn from `map.meta.surface_points`, so everything starts on ground.
- At least 96 px from every other initial item.
- At least 64 px from every spawn point.
- Rejection sampling, capped at 200 attempts; then place wherever fits.

## Notes

Use `substream(seed, "items")`. This is the first consumer of that stream, and the
order in which items are rolled defines the stream position for every later spawn —
so `place_initial` must run before any periodic or crate roll, always
(`docs/32-item-spawning.md` §7).

The 64 px exclusion around spawn points exists so nobody starts standing on a
bazooka. The 96 px separation between items spreads the opening across the map,
which turns the first thirty seconds into a race outward rather than a scrum in the
middle.

When the attempt cap is hit, place the item anyway at the last sampled point rather
than dropping it. Under-placing on a cramped map is worse than a slightly tight
cluster, and silently spawning fewer items than the scale specifies would be
invisible in play and confusing in tests.

`spawn_count` returning `max_stack` for weapons is what makes a bazooka pickup worth
4 rockets — a single-rocket pickup would make weapons feel worthless.

Do not log — `game-core` is pure. If placement under-delivers, that is visible in
the item count, which the server logs.

## Tests

- `place_initial` produces exactly `INITIAL_ITEMS` items for each scale.
- Every placed item is at a valid surface point (`is_standable` at its position).
- All pairwise distances are at least 96 px — or, where the cap was hit, report how
  many placements were forced (assert the forced count is 0 on 20 real medium maps).
- No item is within 64 px of a spawn point.
- Determinism: the same seed produces the same layout, 20 times.
- **Stream isolation**: draining `substream(seed, "weather")` heavily does not change
  the item layout.
- Every rolled item has a non-zero `spawn_weight` (items with weight 0 never appear).
- `spawn_count` returns `max_stack` for all three weapons and 1 for medkit, shield
  and flashlight.
- Weighted distribution over 100 000 rolls matches `spawn_weight` ratios within 2 %.
- On a tiny hand-built map with only 3 surface points, placement does not hang and
  does not panic.
