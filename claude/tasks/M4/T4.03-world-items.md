```rust
pub type WorldItemId = u32;

#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub enum SpawnSource { Initial, Periodic, Crate, Buried, Death }

pub struct WorldItem {
    pub id: WorldItemId,
    pub item: ItemId,
    pub count: u8,
    pub pos: Vec2,
    pub vel: Vec2,
    pub grounded: bool,
    pub spawned_at: f32,
    pub pickup_locked_until: f32,
    pub source: SpawnSource,
}

pub struct WorldItems { items: Vec<WorldItem>, next_id: WorldItemId }

impl WorldItems {
    pub fn spawn(&mut self, item: ItemId, count: u8, pos: Vec2, vel: Vec2,
                 source: SpawnSource, now: f32) -> WorldItemId;

    /// Gravity + terrain collision for every ungrounded item.
    pub fn step(&mut self, map: &Map, dt: f32);

    /// TTL and MAX_WORLD_ITEMS eviction. Returns despawned ids.
    pub fn cull(&mut self, now: f32) -> Vec<WorldItemId>;

    /// Resolve pickups. Players MUST be passed in ascending id order.
    pub fn resolve_pickups(&mut self, players: &mut [(PlayerId, Vec2, &mut Inventory)],
                           now: f32) -> Vec<(WorldItemId, PlayerId)>;

    pub fn iter(&self) -> impl Iterator<Item = &WorldItem>;
    pub fn remove(&mut self, id: WorldItemId) -> Option<WorldItem>;
}
```

## Notes

Item physics reuses the player resolver from T2.05 with a small AABB (16×16 for
loose items, `CRATE_W × CRATE_H` for crates). **Do not write a second collision
path** — an item that falls through terrain a player cannot walk through is a
confusing and entirely avoidable bug.

Once an item is grounded, stop stepping it. Idle items should cost nothing.

`resolve_pickups` **must iterate players in ascending id order**, and the signature
forces the caller to think about it. Two players contacting the same item on the
same tick must always resolve to the same winner, in a live round and in a replay
(`docs/41-server-loop-rooms.md` §2). Hash-map iteration order here is a real
nondeterminism bug that only shows up under load.

Pickup is refused when `Inventory::is_full_for` — the item stays on the ground.
When `add` returns `Partial`, the item stays with the reduced count. Do not delete
the remainder.

`pickup_locked_until` covers death drops (1.0 s, `docs/32-item-spawning.md` §6) so
the killer cannot instantly hoover the corpse and a self-killed player does not get
their own loot back on respawn.

`cull`: TTL applies to everything except crates; `MAX_WORLD_ITEMS` eviction removes
the **oldest non-crate** item first. Crates are exempt from both — they are the
reward for contesting a drop and having one time out mid-fight would be maddening.

## Tests

- A spawned item with downward velocity falls and comes to rest on a floor,
  `grounded` true.
- A grounded item is not stepped further (assert its position is bit-identical
  across 100 ticks).
- An item spawned over a hole falls into it.
- An item never passes through a 1 px floor (the sub-step guarantee, re-tested here).
- A player within `PICKUP_RADIUS` picks the item up; at `PICKUP_RADIUS + 1` px, does
  not.
- **Tie resolution**: two players equidistant on the same tick — the lower player id
  always wins, across 100 runs.
- A full inventory refuses the pickup and the item remains in the world.
- A partial pickup reduces the item's count and leaves it on the ground.
- `pickup_locked_until` blocks pickup before the deadline and allows it after.
- TTL despawn fires at `WORLD_ITEM_TTL` and not at `TTL - 1`.
- A crate is never despawned by TTL.
- At `MAX_WORLD_ITEMS`, the oldest non-crate item is evicted and no crate is.
- `remove` returns the item and removes it; a second `remove` returns `None`.
- Ids are never reused after removal.
