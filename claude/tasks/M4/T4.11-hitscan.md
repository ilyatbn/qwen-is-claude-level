## Deliverable

```rust
pub struct HitscanShot {
    pub from: Vec2,
    pub to: Vec2,
    pub hit: Option<HitscanHit>,
}

pub enum HitscanHit { Player(PlayerId), Terrain }

/// Resolve one trigger pull: `shots` rays with `spread` jitter.
pub fn fire_hitscan(
    map: &mut Map,
    players: &mut [PlayerHitTarget],
    weapon: &WeaponDef,
    owner: PlayerId,
    origin: Vec2,
    aim: f32,
    rng: &mut ChaCha8Rng,
    now: f32,
) -> Vec<HitscanShot>;
```

Per shot:
1. Jitter the aim by `±spread` (0.03 rad for the smg).
2. March 1 px at a time out to `weapon.range` (700).
3. Stop at the first solid pixel or player AABB.
4. On a player: apply `weapon.damage` (8), **no knockback**.
5. On terrain: `carve_circle(hit, weapon.blast_radius)` — 3 px.

## Notes

The 3-px carve per bullet is the point of the SMG's identity: sustained fire
genuinely tunnels through a thin wall, slowly and loudly. Do not skip it because it
seems small.

**No knockback on hitscan hits.** The SMG is chip damage, not displacement. Adding
knockback would make it a crowd-control weapon, which is the bazooka's job.

The owner is excluded from their own rays — start the march at
`origin + dir * MUZZLE_OFFSET` and skip the owner in the player test.

Use `collide::raycast` from T2.02 for the terrain march rather than writing a second
ray stepper. Player AABB testing has to interleave with it, so you will step
manually — but call the same `solid_at` and use the same 1-px step, so the two agree.

The RNG for spread comes from the caller and must be the server's per-round stream,
so a replay reproduces the same spread pattern. Do not create an RNG here.

There is **no lag compensation** in v1 (`docs/31-weapons-combat.md` §8). Rays
resolve against the server's current world state on the tick the input arrives. At 8
damage a shot, a missed bullet is cheap. Note this in a comment so it is a recorded
decision rather than an oversight.

## Tests

- A ray fired at a wall 100 px away hits terrain at ~100 px.
- A ray fired into open air within range returns `hit: None` and `to` at exactly
  `range`.
- A ray fired at a player hits `Player(id)` with the right id.
- A player **behind** a wall is not hit — the wall stops the ray first. This is the
  ordering test and it is the important one.
- A player beyond `range` is not hit.
- The owner is never hit by their own shot, at any angle including straight down.
- Terrain hits carve exactly `blast_radius` (3 px) — `count_solid` drops by roughly
  `π * 9`.
- A player hit takes exactly `weapon.damage` and their velocity is **unchanged**
  (no knockback).
- `shots = 3` produces exactly 3 `HitscanShot` entries.
- Spread: over 1000 shots, the angular deviation stays within `±spread` and is not
  always zero.
- Determinism: the same RNG state produces the same spread pattern, 20 times.
- Firing into the map edge does not panic.
- **Wall breach**: firing repeatedly at a 10-px wall breaches it after a predictable
  number of hits (assert a bound, not an exact count).
