pub type ProjectileId = u32;

pub struct Projectile {
    pub id: ProjectileId,
    pub weapon: WeaponId,
    pub owner: PlayerId,
    pub pos: Vec2,
    pub vel: Vec2,
    pub spawned_at: f32,
    pub fuse_at: Option<f32>,
    pub age_ticks: u32,
}

pub enum ProjectileOutcome {
    Alive,
    Exploded { at: Vec2 },
    HitPlayer { at: Vec2, victim: PlayerId },
}

pub struct Projectiles { list: Vec<Projectile>, next_id: ProjectileId }

impl Projectiles {
    pub fn spawn(&mut self, weapon: WeaponId, owner: PlayerId, origin: Vec2,
                 aim: f32, now: f32) -> ProjectileId;

    /// Step every projectile. Returns outcomes for the caller to act on.
    pub fn step(&mut self, map: &Map, players: &[(PlayerId, Aabb)],
                wind: f32, now: f32, dt: f32)
        -> Vec<(ProjectileId, ProjectileOutcome)>;

    pub fn remove(&mut self, id: ProjectileId);
    pub fn iter(&self) -> impl Iterator<Item = &Projectile>;
}

/// Estimate the surface normal at a contact point from the mask.
pub fn surface_normal(map: &Map, at: Vec2) -> Vec2;

Muzzle: `origin = player_center + dir(aim) * MUZZLE_OFFSET` (18, defined in
`docs/02-constants.md` → Weapons).

## Notes

Per tick, per projectile: gravity (`gravity_scale`), wind
(`wind * wind_scale * dt` on x), then **sub-stepped movement at `MAX_SUBSTEP_PX`**,
testing at each sub-step for solid terrain and then player AABB overlap.

The owner is excluded from player hits for the **first 3 ticks**, so the muzzle
offset does not need to be large enough to clear the shooter's own hitbox at every
firing angle.

**If the muzzle point is already inside solid terrain**, spawn at the player centre
instead and let it explode on its first step. Firing a rocket into a wall you are
touching should hurt.

**Bouncing** (grenades). Estimate the normal by sampling solid density in the 8
neighbours within a small radius and taking the negated gradient. Then:
```
vn  = dot(vel, n)
vel = vel - n * (1 + restitution) * vn
vel *= friction
```
If the resulting speed is under ~30 px/s and the grenade is resting on ground, zero
the velocity and let it sit until the fuse expires. **A grenade that jitters forever
on a slope is the classic bug in this system** — the rest threshold is what prevents
it, and the test for it is non-negotiable.

`PROJECTILE_MAX_LIFETIME` (8 s) forces an explosion so nothing leaks, even with
`gravity_scale = 0`.

This file does not carve or damage. It reports outcomes; T4.10 acts on them.

## Tests

- A bazooka fired horizontally at a wall 100 px away explodes within one tick of
  `100 / muzzle_speed` seconds.
- A projectile follows a parabola: sample its y at several times and compare against
  the analytic value within 1 px.
- Wind visibly deflects a bazooka and deflects a grenade half as much
  (`wind_scale` 1.0 vs 0.5).
- **No tunnelling**: a projectile at 10× `muzzle_speed` is stopped by a 1 px wall.
- A projectile hitting a player AABB reports `HitPlayer` with the right victim.
- The owner is not hit during the first 3 ticks; the owner **is** hit at tick 4.
- A grenade dropped on flat ground comes to rest within 2 s and its position is then
  bit-identical across the remaining ticks — **the anti-jitter test**.
- A grenade dropped on a 30° slope also comes to rest, and does not slide forever.
- A grenade fired into a corner bounces out and does not tunnel or stick.
- A grenade's fuse explodes it mid-air when it never touches anything.
- A projectile despawns at `PROJECTILE_MAX_LIFETIME` even with `gravity_scale = 0`.
- Firing with the muzzle inside rock explodes on the first step.
- `surface_normal` on a flat floor points up; on a left wall points right; in open
  air returns a zero or arbitrary unit vector without NaN.
- Determinism: same inputs, same trajectory, 20 times.
