## Deliverable

```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct Stack { pub item: ItemId, pub count: u8 }

#[derive(Clone, Debug, Default)]
pub struct Inventory { slots: [Option<Stack>; INVENTORY_SLOTS], selected: u8 }

pub enum AddResult { Added, Partial(u8), Full }   // Partial carries the leftover

impl Inventory {
    /// Merge into existing stacks first, then take free slots.
    pub fn add(&mut self, item: ItemId, count: u8) -> AddResult;

    /// Remove `n` from a specific slot. Clears the slot at 0 and re-selects.
    pub fn consume(&mut self, slot: u8, n: u8) -> bool;

    pub fn slot(&self, slot: u8) -> Option<Stack>;
    pub fn selected(&self) -> u8;
    pub fn selected_stack(&self) -> Option<Stack>;
    pub fn select(&mut self, slot: u8) -> bool;         // false if out of range
    pub fn select_next_non_empty(&mut self);
    pub fn count_of(&self, item: ItemId) -> u32;        // across all stacks
    pub fn is_full_for(&self, item: ItemId) -> bool;
    pub fn drain_all(&mut self) -> Vec<Stack>;          // for death drops
    pub fn clear(&mut self);
}
```

## Notes

`add` **merges before it allocates a slot**. The doc's example is the test to
satisfy: with `max_stack = 3`, adding 2 grenades then 2 more gives a stack of 3 and
a stack of 1 — not a stack of 4, and not two stacks of 2. Fill existing stacks in
slot order, then take the first free slot, repeating until the count is exhausted
or nothing is left.

`AddResult::Partial(leftover)` matters: the caller (T4.03) must leave the remainder
on the ground rather than deleting it. Returning a bare bool would silently
destroy items.

When `consume` empties a slot, selection moves to the next non-empty slot, or stays
put if the inventory is now empty. A dangling selection on an empty slot means
firing silently does nothing, which reads as a bug to the player.

`drain_all` is for death drops (`docs/21-player-stats.md` §4) — one `Stack` per
occupied slot, then clear.

No validation of *what* an item is here. The verb/kind check ("you cannot fire a
medkit") lives in T4.13's use path, because it needs the registry and the player
state. This file is purely a container.

Eight slots for six item types is deliberately generous — the pressure in this game
is ammo and finding things, not slot management. Do not add slot-shuffling
mechanics.

## Tests

- A new inventory is empty, `selected == 0`, `selected_stack()` is `None`.
- `add` into an empty inventory takes slot 0.
- **The merge case**: `max_stack = 3`; add 2, then add 2 → slot 0 has 3, slot 1
  has 1.
- Adding beyond `max_stack` spills into a second slot.
- Filling all 8 slots then adding returns `Full` and changes nothing.
- Partially filling the last free slot returns `Partial(leftover)` with the correct
  remainder.
- `consume` decrements; consuming the last one clears the slot.
- `consume` on an empty slot returns false.
- `consume` more than the stack holds returns false and changes nothing.
- Consuming the selected slot to empty moves selection to the next non-empty slot.
- Consuming the last item in the whole inventory leaves selection valid and
  `selected_stack()` `None`.
- `select(8)` returns false; `select(7)` returns true.
- `count_of` sums across multiple stacks of the same item.
- `is_full_for` is false while any stack has room.
- `drain_all` returns one stack per occupied slot and empties the inventory.
- Round-trip: add a mixed load, `drain_all`, re-add it all — the result matches.
