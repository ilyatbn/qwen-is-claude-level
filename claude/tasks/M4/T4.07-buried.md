## Deliverable

```rust
/// Roll the item for every buried slot. Called once, at round start, right
/// after place_initial.
pub fn assign_buried_items(map: &Map, seed: u64) -> Vec<ItemId>;

/// Turn slot ids revealed by a carve into real world items.
pub fn reveal_buried(
    world: &mut WorldItems,
    map: &Map,
    buried_items: &[ItemId],
    revealed: &[u16],
    now: f32,
) -> Vec<WorldItemId>;
```

`CarveResult.revealed` (T1.14) feeds `reveal_buried` directly.

## Notes

This is the mechanic that ties items to destruction, and it is one of the more
distinctive things in the game. Getting the feel right matters more than the code
size suggests.

Items are rolled from the `Buried` weight column at **round start**, not at reveal
time. Rolling at reveal would make the `"items"` sub-stream's consumption depend on
where players happened to shoot, which breaks reproducibility — the whole point of
`docs/32-item-spawning.md` §7 is that a replay reproduces the same items.

Use `substream(seed, "buried")`, not the `"items"` stream. Buried assignment happens
once and should not shift the periodic spawn sequence.

The revealed item spawns at the **slot's position**, with zero velocity. It may be
mid-air inside the new crater; the normal item physics drops it to the crater floor,
which looks right.

Emit `source: Buried` so the client can play the sparkle. That association —
digging produces treasure — is what teaches players to shoot the ground, and it is
learned entirely from the visual feedback.

An already-revealed slot must never produce a second item. T1.14 sets
`revealed = true` and only returns each id once, but assert it here too — a double
reveal duplicates items and is the kind of thing that only shows up when someone
carpet-bombs one spot.

Unrevealed slots simply never appear. At round end some items were never found. That
is intended, not a leak.

## Tests

- `assign_buried_items` returns one id per buried slot.
- Every assigned item has a non-zero `buried_weight`.
- The distribution over many seeds matches the `buried_weight` ratios within 3 %.
- The flashlight is the most commonly buried item (it has the highest buried
  weight) — assert this over 1000 seeds, since it is a deliberate design choice
  worth protecting from an accidental weight edit.
- Determinism: the same seed assigns the same items, 20 times.
- **Stream isolation**: buried assignment does not shift the periodic item sequence
  (generate the periodic spawns with and without buried assignment and compare).
- A carve covering a slot produces exactly one world item at that slot's position.
- A carve missing a slot by one pixel produces nothing.
- Carving the same slot twice produces exactly one item, not two.
- The revealed item's `source` is `Buried`.
- A revealed item mid-air falls to the crater floor.
- Revealing every slot on a map produces exactly `BURIED_SLOTS` items.
