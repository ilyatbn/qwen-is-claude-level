## Deliverable

```rust
pub type ItemId = u16;

pub struct ItemDef {
    pub id: ItemId,
    pub key: &'static str,
    pub name: &'static str,
    pub kind: ItemKind,
    pub max_stack: u8,
    pub sprite: &'static str,
    pub spawn_weight: u16,
    pub crate_weight: u16,
    pub buried_weight: u16,
}

pub enum ItemKind {
    Weapon(WeaponId),
    Heal { amount: f32 },
    Shield { duration: f32 },
    Utility(UtilityId),
}

pub enum UtilityId { Flashlight }

pub static ITEMS: &[ItemDef] = &[ /* the six from the doc's table */ ];

pub fn def(id: ItemId) -> Option<&'static ItemDef>;
pub fn by_key(key: &str) -> Option<&'static ItemDef>;

#[derive(Copy, Clone)]
pub enum WeightColumn { Spawn, Crate, Buried }
pub fn weights(col: WeightColumn) -> Vec<u16>;   // parallel to ITEMS
```

The six v1 items and their exact numbers are in `docs/30-items-inventory.md` §1.
Transcribe them; do not invent values.

## Notes

A compile-time table rather than a data file. With six items, a `static` array
makes typos into compile errors and needs no parser or error handling. `ItemDef`
is the seam: when the count justifies RON or JSON, nothing outside this file
changes.

**Ids are stable and never reused.** They go on the wire in snapshots and
`item_spawn` events. Assign 0..5 now and treat them as permanent.

Weapon stack counts are ammo — picking up a second bazooka gives 8 rockets in one
slot, not two slots. `max_stack` for `bazooka` is therefore 4 per the table, and
merging is what T4.02 handles.

Three weight columns, not one, so crates can skew toward weapons and buried slots
toward the flashlight without a second table. Note in a comment that `flashlight`
is deliberately weighted highest in the buried column — the item you most need at
night is the one you have to dig for.

`WeaponId` is declared in T4.08. For now, forward-declare it as a `u16` newtype in
this file and let T4.08 give it meaning, or add a minimal stub enum. Say which you
chose in your report.

## Tests

- Every `id` in `ITEMS` is unique.
- Every `key` is unique.
- Ids are exactly `0..ITEMS.len()` (so `def` can index directly — assert this, since
  the fast path depends on it).
- Every `sprite` is non-empty.
- `def(id)` returns the right item for each id; `def(999)` returns `None`.
- `by_key("bazooka")` finds it; `by_key("nope")` returns `None`.
- `weights(Spawn)` has the same length as `ITEMS`.
- At least one item has a non-zero weight in each column (otherwise a spawn source
  can never produce anything).
- The medkit heals exactly `MEDKIT_HEAL`; the shield lasts exactly
  `SHIELD_DURATION` — assert against the constants, not against literals, so a
  constant change cannot silently desync from the registry.
- `flashlight`'s `buried_weight` is the highest buried weight in the table.
