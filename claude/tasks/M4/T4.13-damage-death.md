## Deliverable

```rust
pub enum DeathCause { Player(PlayerId), SelfInflicted, Weather(EffectKind) }

impl PlayerState {
    /// Returns true if the damage was actually applied.
    pub fn apply_damage(&mut self, amount: f32, src: DamageSource, now: f32) -> bool;

    /// Returns the dropped stacks for the caller to turn into world items.
    pub fn die(&mut self, cause: DeathCause, now: f32) -> Vec<Stack>;

    pub fn respawn(&mut self, pos: Vec2, now: f32);

    /// Validated item use. See the ordered checks below.
    pub fn use_item(&mut self, slot: u8, now: f32) -> Result<ItemId, UseError>;

    /// Validated fire. Checks cooldown and ammo; does not spawn anything.
    pub fn try_fire(&mut self, now: f32) -> Result<WeaponId, UseError>;
}

pub enum UseError { Dead, BadSlot, EmptySlot, WrongKind, OnCooldown, NoAmmo }

/// Choose a respawn point that is STILL valid on the damaged map.
pub fn choose_respawn(map: &Map, living: &[Vec2], rng: &mut ChaCha8Rng) -> Vec2;
```

## Notes

**`apply_damage` order** (`docs/21-player-stats.md` §4): dead or invulnerable →
ignore and return false; multiply by `SHIELD_DAMAGE_MULT` if shielded; subtract;
record `last_damaged_by` when there is an attacker; if `health <= 0`, die.

**Scoring** (§6). The victim always takes `DEATH_POINTS` (−1) — including self-kills
and weather deaths. The attacker gets `KILL_POINTS` (+1) only when it was another
player. Score is `i16` and **may go negative**; there is no floor at zero.

**The assist window.** If the killing blow was environmental but another player
damaged the victim within the last 5 seconds, that player still gets the kill.
Without it, shooting someone off a ledge into lava rewards nobody, which is the
wrong incentive.

**`choose_respawn` must re-validate.** `MapMeta.spawn_points` describes the pristine
map; by minute three a spawn point may be mid-air over a crater or buried under a
landslide of nothing. Re-run `surface::is_standable` (T1.09) on each candidate,
prefer the valid one furthest from the nearest living player (at least
`SPAWN_MIN_ENEMY_DIST` where possible), and if none of the six work, fall back to
the nearest still-valid point in `meta.surface_points`. **This check is not
optional** — skipping it is exactly how players end up spawning inside rock late in
a round.

**`use_item` validation order** matters, because the error tells the server what to
log: `Dead` → `BadSlot` → `EmptySlot` → `WrongKind` → `OnCooldown` → `NoAmmo`.

The **flashlight is the exception**: using it toggles `flashlight_on` and does
**not** consume the item.

On respawn: full health, shield cleared, jetpack refilled, inventory cleared,
`iframes_until = now + SPAWN_IFRAMES`, flashlight forced off (the item went with the
inventory). The player can act during i-frames — it is not a stun.

## Tests

- Damage on a dead player returns false and does not decrement the score twice.
- Damage during i-frames returns false and health is unchanged.
- A shielded player takes exactly half damage from every source.
- Health crossing 0 kills exactly once.
- **A self-kill is −1 to the victim and +0 to everyone else.**
- A player kill is −1 victim, +1 attacker.
- A weather death with no recent attacker credits nobody.
- The assist window credits a kill at 4.9 s and does not at 5.1 s.
- `die` returns one `Stack` per occupied inventory slot and empties the inventory.
- `respawn` restores full health, clears the shield, refills fuel, empties the
  inventory, sets i-frames, and forces the flashlight off.
- **`choose_respawn` never returns a point inside solid terrain** — carve away all
  six spawn points and assert the fallback still finds valid ground.
- `choose_respawn` prefers points far from living players.
- `use_item` returns each `UseError` variant under its condition, in the documented
  precedence order.
- `use_item` on a weapon slot returns `WrongKind`.
- `try_fire` on a medkit slot returns `WrongKind`.
- `try_fire` with 0 ammo returns `NoAmmo` and consumes nothing.
- `try_fire` inside the cooldown returns `OnCooldown`.
- Using the flashlight toggles it and does **not** consume the item.
- Using a medkit at 60 health gives 110 and consumes one.
