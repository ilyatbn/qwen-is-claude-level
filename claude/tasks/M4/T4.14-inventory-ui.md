```ts
export interface InventoryModel { slots: (Stack | null)[]; selected: number }

/** Pure reducers — the testable part. */
export function selectSlot(m: InventoryModel, slot: number): InventoryModel;
export function selectNext(m: InventoryModel, dir: 1 | -1): InventoryModel;

export class InventoryPanel {
  constructor(scene: Phaser.Scene);
  toggle(): void;
  setModel(m: InventoryModel): void;
  onSelect(cb: (slot: number) => void): void;
  onUse(cb: (slot: number) => void): void;
  readonly isOpen: boolean;
  destroy(): void;

  }): void;
  destroy(): void;
}
```

## Notes

**Right-click toggles the panel** — the brief's requirement. It is purely
client-side: opening sends nothing to the server and **does not pause anything**.
The round keeps running while it is open, so browsing your inventory in the open is
a real risk. Do not add a pause; that is not an oversight, it is the design.

Layout: a 4×2 grid of slots at the bottom centre, each showing sprite, count and
hotkey number, with the selected slot highlighted. A compact always-visible strip
shows the selected item and count, so the panel is only needed to change loadout.

Keep the **reducers pure and separate from the Phaser objects**. They are the only
unit-testable part of this file, and separating them is what makes T6.08's event
handling straightforward.

The panel is a *view*. It never mutates game state — clicking emits a callback, and
the authoritative `inventory` event from the server is what updates the model
(`docs/30-items-inventory.md` §6). Optimistically mutating the local model produces
counts that flicker back on every server message.

Selection is client-authoritative in the sense that it is sent as `select_slot` and
the server accepts it; but the *contents* are always the server's.

Depth 60, `scrollFactor` 0. Suppress the context menu (T0.06 should have done it;
verify).

Every sprite lookup falls back to a coloured rectangle with the item's initial
(`docs/50-sprites-skins.md` §8) — there is no art until M7 and this must not throw.

HUD: a health bar (with a distinct colour above 100 for overheal), a shield
countdown ring, a jetpack fuel bar, the selected item, score, round timer, a wind
arrow, and a subtle day/night indicator. The wind arrow matters — a wind you cannot
see is just noise (`docs/31-weapons-combat.md` §3).

## Tests

`client/src/ui/inventory.test.ts` — the reducers:

- `selectSlot` within range updates selection; out of range leaves it unchanged.
- `selectNext(+1)` skips empty slots and wraps around.
- `selectNext(-1)` wraps the other way.
- `selectNext` on an all-empty inventory does not loop forever.
- `applyServerInventory` replaces the slots wholesale and preserves the local
  selection when that slot is still valid.
- `applyServerInventory` moves selection when the selected slot became empty.
- Reducers never mutate their input (assert the original object is unchanged).

Plus, with Phaser stubbed:
- `toggle` flips `isOpen`.
- Clicking a slot fires `onSelect` with the right index.
- Clicking a consumable fires `onUse`.
- A missing sprite renders the placeholder and does not throw.
- `destroy` removes every created object.
