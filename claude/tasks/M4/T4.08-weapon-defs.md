## Deliverable

```rust
pub type WeaponId = u16;

pub struct WeaponDef {
    pub id: WeaponId,
    pub key: &'static str,
    pub delivery: Delivery,
    pub damage: f32,
    pub blast_radius: f32,
    pub range: f32,
    pub cooldown: f32,
    pub muzzle_speed: f32,
    pub gravity_scale: f32,
    pub wind_scale: f32,
}

pub enum Delivery {
    Projectile { fuse: Option<f32>, restitution: f32, friction: f32,
                 explode_on_contact: bool },
    Hitscan { shots: u8, spread: f32 },
}

pub static WEAPONS: &[WeaponDef] = &[ /* bazooka, grenade, smg */ ];

pub fn def(id: WeaponId) -> Option<&'static WeaponDef>;
pub fn by_key(key: &str) -> Option<&'static WeaponDef>;
```

The three weapons and every number are in `docs/31-weapons-combat.md` §1's table.
Transcribe them exactly.

## Notes

Three weapons, three roles: a direct arcing hit (bazooka), indirect area denial
(grenade), and sustained chip damage that also tunnels (smg). Do not add a fourth
"for completeness" — the arsenal expands in a later milestone, and each weapon added
now is a weapon that has to be balanced and tested twice.

`Delivery` is the extension seam. Clustering, homing, airstrikes and drills all
become new variants without touching the firing code's structure
(`docs/31-weapons-combat.md` §8).

Ids are stable and go on the wire in `projectile_spawn` events. Assign 0, 1, 2 and
treat them as permanent.

`range` is meaningful only for hitscan; projectiles are bounded by
`PROJECTILE_MAX_LIFETIME`. Set `range` to 0 for projectiles and say so in a comment,
rather than inventing a value that reads as meaningful.

Wire this to `ItemKind::Weapon(WeaponId)` from T4.01 — the registry's forward
declaration becomes real here.

## Tests

- Every `id` is unique and ids are exactly `0..WEAPONS.len()`.
- Every `key` is unique.
- `def` and `by_key` resolve correctly; unknown inputs return `None`.
- **Registry integration**: every `ItemKind::Weapon(id)` in `ITEMS` resolves to a
  real `WeaponDef`. This is the cross-table check that catches a mismatched id.
- Every projectile weapon has a positive `muzzle_speed`; every hitscan weapon has a
  positive `range`.
- Every weapon has a positive `cooldown`, `damage` and `blast_radius`.
- The grenade has a `fuse` and `explode_on_contact == false`.
- The bazooka has no fuse and `explode_on_contact == true`.
- The smg is `Hitscan` with a non-zero `spread`.
- Values match `docs/31-weapons-combat.md` §1 exactly — assert each number
  explicitly, so a silent balance edit in one place and not the other is caught.
