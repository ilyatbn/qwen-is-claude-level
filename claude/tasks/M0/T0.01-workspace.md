## Deliverable

A virtual workspace with three members. Dependencies declared in
`[workspace.dependencies]` and referenced with `.workspace = true` so versions are
pinned in one place.

```toml
# Cargo.toml
[workspace]
members = ["crates/game-core", "crates/game-server", "crates/game-wasm"]
resolver = "2"

[workspace.dependencies]
rand = { version = "0.8", default-features = false, features = ["std", "std_rng"] }
rand_chacha = "0.3"
tracing = "0.1"
tracing-subscriber = { version = "0.3", features = ["env-filter"] }
tokio = { version = "1", features = ["full"] }
axum = "0.7"
socketioxide = { version = "0.18", features = ["state", "extensions", "tracing"] }
serde = { version = "1", features = ["derive"] }
serde_json = "1"
blake3 = "1"
```

`rust-toolchain.toml` pins `channel = "1.97.1"` with the `wasm32-unknown-unknown`
target and the `rustfmt`, `clippy` components.

Crate contents for now:
- `game-core/src/lib.rs` — empty module declarations only, no logic.
- `game-server/src/main.rs` — `fn main() { println!("game-server"); }`.
- `game-wasm/src/lib.rs` — empty; `crate-type = ["cdylib", "rlib"]`,
  depends on `game-core` and `wasm-bindgen = "0.2"`.

## Notes

`game-core` must have **no** dependency on tokio, axum or socketioxide. If a later
task tries to add one, that is a design error — report it. Its only dependencies
are `rand`, `rand_chacha`, `serde` and (behind a feature) `png`.

Do not add `wasm-bindgen` to `game-core`. The WASM boundary lives entirely in
`game-wasm`.
