## Deliverable

```rust
#[derive(Copy, Clone, Debug, Default, PartialEq)]
pub struct Vec2 { pub x: f32, pub y: f32 }

impl Vec2 {
    pub fn new(x: f32, y: f32) -> Self;
    pub fn len(self) -> f32;
    pub fn len_sq(self) -> f32;
    pub fn normalized(self) -> Vec2;          // zero vector returns zero, never NaN
    pub fn dot(self, o: Vec2) -> f32;
    pub fn from_angle(a: f32) -> Vec2;        // (cos a, sin a)
    pub fn angle(self) -> f32;                // atan2(y, x)
    pub fn clamp_len(self, max: f32) -> Vec2;
}
// plus Add, Sub, Mul<f32>, Div<f32>, Neg, AddAssign, SubAssign

/// Axis-aligned box stored by centre and half-extents.
#[derive(Copy, Clone, Debug, PartialEq)]
pub struct Aabb { pub center: Vec2, pub half: Vec2 }

impl Aabb {
    pub fn from_center_size(center: Vec2, w: f32, h: f32) -> Self;
    pub fn min(self) -> Vec2;
    pub fn max(self) -> Vec2;
    pub fn contains_point(self, p: Vec2) -> bool;
    pub fn overlaps(self, o: Aabb) -> bool;
    /// Integer pixel bounds, inclusive, for mask iteration.
    pub fn pixel_bounds(self) -> (i32, i32, i32, i32);
}

pub fn approach(current: f32, target: f32, max_delta: f32) -> f32;
pub fn lerp(a: f32, b: f32, t: f32) -> f32;
pub fn clamp01(v: f32) -> f32;
pub fn smoothstep(t: f32) -> f32;             // 3t² − 2t³, t clamped to 0..1
pub fn wrap_to_pi(a: f32) -> f32;             // into (−π, π]
pub fn quantize_angle(a: f32) -> u16;
pub fn dequantize_angle(q: u16) -> f32;
pub fn isqrt(n: i32) -> i32;                  // integer sqrt, for circle spans
```

## Notes

`approach` is used by every movement rule (`docs/20-player-movement.md` §3) — it
must never overshoot the target, in either direction.

`pixel_bounds` decides how the float world maps onto the integer mask. Use
`floor(min)` and `ceil(max) − 1`, both inclusive. Getting this wrong shifts
collision by a pixel everywhere, so it gets its own tests.

`isqrt` must be exact integer arithmetic (Newton or binary search) — not
`(n as f32).sqrt() as i32`. It is used for circle rasterisation, where a
platform-dependent rounding difference would break the bit-identical carve
guarantee in `docs/11-map-destruction.md` §2.

`normalized()` on a zero-length vector returns `Vec2::default()`, not NaN. NaN
positions propagate silently and are miserable to debug.

## Tests

- `approach` never overshoots, going up or down, and reaches the target exactly.
- `lerp(a, b, 0) == a`, `lerp(a, b, 1) == b`.
- `smoothstep(0) == 0`, `smoothstep(1) == 1`, `smoothstep(0.5) == 0.5`, monotonic.
- `wrap_to_pi` maps 3π to π, −3π to π, 0 to 0.
- `quantize_angle(dequantize_angle(q)) == q` for **all** 65536 values.
- `dequantize_angle(quantize_angle(θ))` within 1e-4 of θ across a sweep.
- `Vec2::from_angle(θ).angle()` round-trips within 1e-5.
- `normalized()` of a zero vector is zero and not NaN.
- `clamp_len` leaves shorter vectors untouched.
- `isqrt` matches `(n as f64).sqrt().floor()` for `n` in 0..100_000.
- `pixel_bounds` for a 16×28 box centred at (100.0, 100.0) is (92, 86, 107, 113).
- `overlaps` is false for boxes touching exactly at an edge.
