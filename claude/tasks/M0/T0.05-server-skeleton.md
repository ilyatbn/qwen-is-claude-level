## Deliverable

A running axum server with socketioxide layered on, that echoes.

```rust
// config.rs
pub struct Config {
    pub bind_addr: SocketAddr,   // BIND_ADDR, default 0.0.0.0:3000
    pub game_log: String,        // GAME_LOG, default "info"
    pub map_scale: MapScale,     // MAP_SCALE, default medium
    pub max_players: usize,      // MAX_PLAYERS, default 6
    pub round_seconds: f32,      // ROUND_SECONDS, default 240
    pub min_players_to_start: usize,
    pub fixed_seed: Option<u64>, // FIXED_SEED
    pub record_replay: bool,     // RECORD_REPLAY
    pub debug_dump: bool,        // DEBUG_DUMP
}
impl Config { pub fn from_env() -> Result<Self, ConfigError>; }

// logging.rs
pub fn init(filter: &str) -> Result<(), LoggingError>;
```

`main.rs`:
- parse config, init logging, log the full config at `info` on startup;
- `GET /healthz` → JSON `{status, uptime_s, rooms, players}` (rooms/players are 0 for now);
- socket.io namespace `/` with an `on_connect` that logs, and an `echo` handler that
  emits `echo_back` with the same payload;
- serve with `axum::serve`, and a `tokio::signal` handler for graceful shutdown.

## Notes

Config parsing must **fail fast with a clear message** on a bad value, not silently
default. `MAP_SCALE=huge` should print what it got and what is allowed, then exit 1.
The same for an invalid `GAME_LOG` filter string — `EnvFilter::try_new` returns an
error; do not swallow it.

Log targets are the ones in `docs/61-logging-debug.md` §1. Use
`tracing::info!(target: "game::net", ...)`, not bare `info!`, so filtering works.

Do not build room logic, the tick loop, or game state here. That is T6.02. This
task's job is a process that starts, logs properly, answers `/healthz`, and proves
the socket.io transport works end to end.

## Tests

`crates/game-server/tests/skeleton.rs`:

- `Config::from_env` with a clean environment produces the documented defaults.
- An invalid `MAP_SCALE` returns an error naming the bad value.
- An invalid `GAME_LOG` returns an error rather than defaulting.
- The server binds an ephemeral port and `GET /healthz` returns 200 with the
  expected JSON keys.
- A `rust_socketio` client connects, emits `echo` with `{"n":42}`, and receives
  `echo_back` with the same payload within 2 s.
