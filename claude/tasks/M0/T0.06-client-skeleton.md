## Deliverable

A Vite + TypeScript + Phaser app that boots, shows a placeholder scene, connects to
the server, and round-trips the echo from T0.05.

`package.json` — pin exactly:
```json
{
  "dependencies": { "phaser": "3.90.0", "socket.io-client": "^4.7.0" },
  "devDependencies": { "typescript": "^5.5.0", "vite": "^5.4.0", "vitest": "^2.0.0" },
  "scripts": {
    "dev": "vite",
    "build": "tsc --noEmit && vite build",
    "typecheck": "tsc --noEmit",
    "test": "vitest"
  }
}
```

Phaser is pinned to an exact version, not a caret range — a minor Phaser bump
changing renderer behaviour mid-project is not a debugging problem anyone wants.

`vite.config.ts` must proxy socket.io **with WebSocket upgrade enabled**:
```ts
server: { proxy: { '/socket.io': { target: 'http://localhost:3000', ws: true } } }
```
Without `ws: true` socket.io silently falls back to long-polling, which looks like
unexplained lag rather than a configuration error.

`tsconfig.json`: `strict: true`, `noUncheckedIndexedAccess: true`, target ES2022.

`main.ts`: Phaser game config — `Scale.FIT`, design size `VIEWPORT_W × VIEWPORT_H`
(1280×720), `backgroundColor` a dark blue, `BootScene` registered.

`BootScene`: renders "connecting…", calls `connect()`, then renders the echo
result and the round-trip time.

`net/socket.ts`: a thin typed wrapper over `io()` exposing `connect()`,
`on(event, handler)`, `emit(event, payload)`, and a connection-state callback. No
game logic.

## Notes

Do not add a `constants.ts` in the client. Constants come from `game-core` through
WASM (T3.01/T3.02). Duplicating them in TypeScript is exactly the drift this
architecture exists to prevent. The one exception is the two viewport values, which
are pure presentation — inline them in `main.ts` with a comment pointing at
`docs/02-constants.md`.

Suppress the browser context menu on the canvas now, while it is a one-liner —
right-click is the inventory toggle later (`docs/30-items-inventory.md` §3).

## Tests

`client/src/net/socket.test.ts` (vitest, with the socket mocked):
- `connect()` registers the connect/disconnect handlers.
- `on()` before connection queues the handler and registers it after connecting.
- `emit()` before connection does not throw.

## Done when

```sh
npm --prefix client install && npm --prefix client run typecheck && npm --prefix client test -- --run
```
Then, with the server running: `npm --prefix client run dev` and confirm the page
shows the echo result and the browser console reports transport `websocket`.
