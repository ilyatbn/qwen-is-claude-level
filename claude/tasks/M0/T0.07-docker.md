## Deliverable

Exactly what `docs/62-docker-deploy.md` §2–§5 describes.

**`Dockerfile.server`** — multi-stage, dependency-cached:
1. `rust:1.97-slim` builder. Copy `Cargo.toml`, `Cargo.lock` and the three crate
   manifests with stub `src/main.rs` / `src/lib.rs`, run `cargo build --release`
   to cache dependencies, then copy real sources and build again.
2. `debian:bookworm-slim` runtime with `ca-certificates` and `curl` (needed by the
   healthcheck), a non-root user, the binary, `EXPOSE 3000`, a `HEALTHCHECK`
   hitting `/healthz`, and `ENTRYPOINT ["game-server"]`.

**`Dockerfile.client`** — three stages: `wasm` (installs `wasm-pack`, builds
`crates/game-wasm`), `build` (node:22-slim, `npm ci`, copies the wasm output into
`client/src/core/pkg`, `npm run build`), `runtime` (`nginx:alpine` + `nginx.conf`).

At M0 `game-wasm` is empty, so the wasm stage produces nothing useful — build it
anyway. Getting the stage working now, while there is nothing to go wrong, is much
easier than debugging it in M3 alongside real bindings.

**`nginx.conf`** — SPA fallback, and the socket.io proxy with the upgrade headers:
```
location /socket.io/ {
    proxy_pass http://server:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

**`docker-compose.yml`** — the `server` and `client` services from
`docs/62-docker-deploy.md` §4, with the `../replays` bind mount, the healthcheck
dependency, `stop_grace_period: 10s`, and the `redis`/`postgres` services present
but commented out.

**`.env.example`** — the block from §5.

## Notes

The `Upgrade`/`Connection` headers are the single most common cause of "multiplayer
feels laggy in Docker but fine in dev". Long-polling works well enough that the
misconfiguration hides. Verify the transport, do not assume it.

Build context is the project root (`context: ..`), so paths inside the Dockerfiles
are relative to it, not to `docker/`.

Add a `.dockerignore` at the project root covering `target/`, `node_modules/`,
`client/dist/` — without it the build context is hundreds of megabytes and every
build is slow.

## Tests

No unit tests. Manual verification, and it must all pass:

1. `docker compose -f docker/docker-compose.yml up --build` succeeds from a clean
   checkout.
2. `curl -f http://localhost:3000/healthz` returns 200.
3. `http://localhost:8080` loads and the echo round-trips through the nginx proxy.
4. In the browser console, `socket.io.engine.transport.name === "websocket"` —
   **not** `"polling"`.
5. `docker exec <server> whoami` is not `root`.
6. `docker compose down` exits cleanly.

## Done when

All six checks above pass. Paste the transport name from check 4 in your report.
