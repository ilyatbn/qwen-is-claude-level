## Deliverable

```
cargo run -p game-server --bin replay -- <file> [flags]

  --until <tick>        stop at this tick
  --dump-map <tick>     write a PNG of the terrain at this tick
  --trace <filter>      re-run with a different GAME_LOG filter
  --verify              compare the final state hash against the footer (default)
  --stats               print per-tick timing and event counts
```

Re-simulates the recorded round headlessly, at full speed, with **no networking and
no clock**.

## Notes

**This is the payoff for every determinism decision in the project.** The workflow
it enables — *"the map broke around two minutes in"* → replay to tick 7200, dump the
PNG, look at it — replaces guessing and reproduction attempts with a direct
observation.

On a hash mismatch, print the **divergence tick**: re-run comparing the state hash
every N ticks (start at 600, then bisect) and report the first tick where it
diverges. That single number is usually enough to identify the offending subsystem,
and it is what makes this tool worth more than a bare pass/fail.

`--dump-map` needs `game-core`'s `dump-png` feature (T1.16). Gate the flag behind it
and print a clear message if the binary was built without it, rather than failing
obscurely.

The runner constructs `World::new(seed, scale)` from the header and feeds recorded
commands at their recorded ticks, calling `world.step(SIM_DT)` for every tick
including empty ones. **Skipping empty ticks changes the result** — timers, weather
schedules and item cadences all advance per tick.

No `tokio`, no sockets, no sleeping. A 4-minute round should replay in a few seconds.

`--trace` re-runs with a different `EnvFilter`, so a bug can be investigated at
`trace` level without having captured it that way live. That is a large part of the
value: the original session did not need to be running verbose.

Exit non-zero on a verification failure, so this can go in CI as a determinism
regression test.

## Tests

`crates/game-server/tests/replay_run.rs`:

- Replaying a recorded round reproduces the footer's state hash exactly. **This is
  the single best regression test in the project** (`docs/60-testing.md` §4).
- Replaying twice produces identical results.
- `--until <tick>` stops at that tick and reports the state hash there.
- `--dump-map` writes a valid PNG.
- A deliberately corrupted command produces a clear error, not a panic.
- A truncated file produces a clear error.
- A version mismatch produces a clear error.
- **Divergence detection**: perturb one recorded command, and assert the runner
  reports a divergence tick close to where the perturbation was inserted.
- Empty ticks are simulated — a round with commands only at tick 0 and tick 6000
  still advances the weather schedule correctly.
- A 4-minute recorded round replays in under 10 s.
- Exit code is non-zero on verification failure.

## Done when

```sh
cargo test -p game-server --test replay_run
```
Then, end to end: run a real round with `RECORD_REPLAY=1`, replay the resulting
file, and confirm the hash matches. Paste the runner's output in your report.
