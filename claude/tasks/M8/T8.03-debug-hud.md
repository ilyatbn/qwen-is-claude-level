## Deliverable

```ts
export class DebugHud {
  constructor(scene: Phaser.Scene);
  toggle(): void;
  update(d: {
    rttMs: number; jitterMs: number; lossPct: number;
    snapshotsPerSec: number; inputsPerSec: number;
    pendingInputs: number;
    corrections: number; correctionRate: number;
    meanCorrectionPx: number; maxCorrectionPx: number;
    interpBufferDepth: Map<number, number>; extrapolatingMs: number;
    localPos: {x: number; y: number}; serverPos: {x: number; y: number};
    checksumStatus: 'matched' | 'mismatched' | 'resyncing';
    tick: number; serverTick: number; clockOffsetMs: number;
    seed: bigint; fps: number; frameMs: number;
  }): void;
  destroy(): void;
}
```

Plus **two ghost markers**: the local predicted position and the last server
position, drawn as translucent outlines.

## Notes

**Without these numbers, netcode bugs are guesswork.** That is the entire
justification for the task — every value here corresponds to a specific failure mode
that is otherwise invisible:

| Symptom | Number that explains it |
|---|---|
| rubber-banding | correction rate and max correction px |
| jittery remote players | interpolation buffer depth, extrapolating ms |
| shots not landing | RTT, and the two ghosts diverging |
| "I got shot through a wall" | checksum status |
| stutter | frame ms, fps |

**The two ghosts are the most useful single feature.** If the predicted and server
positions sit on top of each other, prediction is healthy. If they separate and snap
back rhythmically, something is wrong, and you can see it rather than infer it from
a log.

**Show the seed prominently.** It is the first thing to ask for in a bug report
(`docs/61-logging-debug.md` §8), and asking a user to find it in a console is a
worse experience than reading it off the screen.

Rolling averages over 60 frames for fps and frame ms; instantaneous values are too
noisy to read. Rates (snapshots/s, inputs/s, corrections/s) over a 1-second window.

Use a monospace bitmap font at depth 100, `scrollFactor` 0. Keep it compact —
top-left, one value per line, no decoration. This is an instrument panel, not UI.

When hidden, `update` must return immediately without computing anything. A debug
overlay that costs frame time when off defeats its own purpose.

## Tests

`client/src/ui/debugHud.test.ts`, with Phaser stubbed:

- `toggle` flips visibility.
- **`update` while hidden performs no work** — assert zero text updates and zero
  draw calls.
- Every field renders when visible.
- fps and frame ms are rolling means over 60 samples.
- Rates are computed over a 1-second window and are stable under a constant input
  rate.
- The two ghost markers are placed at the supplied positions.
- Ghosts overlapping (error 0) still render both.
- `checksumStatus` renders in a distinct colour when `mismatched`.
- The seed renders as a full 64-bit value, not truncated or in scientific notation.
- `destroy` removes every created object.
- An empty `interpBufferDepth` map does not throw.

## Done when

```sh
npm --prefix client test -- --run debugHud
```
Then in a real two-client round, press F3 and report the observed RTT, correction
rate, and whether the two ghosts stay coincident.
