## Notes

**Measure first.** The most likely hot spots, in order, are the silhouette pass and
the CA smoothing in map generation, the per-pixel stencil loop in chunk baking, and
`aabb_overlaps_solid` if the coarse grid fast path is not being hit. But the point
of this task is to find out, not to assume — every one of those may already be fine,
and time spent optimising a passing check is time wasted.

If something fails, the fixes the docs already anticipate are:
- map generation: parallelise the CA and labelling passes by row bands
  (`docs/10-map-generation.md` §4);
- chunk baking: cache edge stencils per chunk, or move fill+edge into a shader
  (`docs/12-map-render.md` §10);
- collision: verify the coarse grid is actually short-circuiting — a bug there turns
  every query into a 448-bit scan.

Do **not** start a broad optimisation pass. Fix what fails, leave what passes, and
say what you measured.

The README is the front door. Someone picking this up after a break should be able
to run it, see it, and debug it from that page alone. If a section would just repeat
a doc, link the doc instead.
