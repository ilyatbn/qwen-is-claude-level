# T9.08 — Announce the state that existed before the client did (v2)

Milestone: M9 · Depends on: T9.06 · Size: ~120 lines

## The pattern, now seen three times

1. **World items** (T9.03): `place_initial` runs inside `World::new`, before any
   event buffer exists, so no `item_spawn` was ever emitted for the initial 8–20
   items. The server had them; no client could know.
2. **Scores** (T9.06): the client's `score` handler discarded its payload and
   re-rendered a map that `welcome` had zeroed, so the scoreboard read 0 all round.
3. **Inventory** (T9.06): `inventory` is emitted on pickup, use and death — never
   on join. With `DEV_LOADOUT` the HUD says "(empty)" while you hold four rockets.

Each is the same bug: **state that exists before a client connects is never
announced to it.** Events describe *changes*; a joiner needs the *current value*.
`docs/41` §4 supports joining mid-round explicitly, which makes this a normal path,
not an edge case.

## Touch only
- `crates/game-server/src/session.rs` (the join path)
- `crates/game-server/src/events.rs` if the scope needs it
- `client/src/scenes/GameScene.ts`
- the integration test file that covers join

## Deliverable

On join, after `welcome` and `map_init` and before the first snapshot, the server
sends that player their **current** state: `inventory` (their own, per `docs/30` §6
— owner only), the `score` table, and the live world-item list. Nothing new goes on
the wire; these are existing events, sent once at the moment a client first needs
them.

## Notes

- `inventory` is owner-scoped. A join must not leak another player's inventory —
  §A31's class of mistake, and `scope_of` already knows the rule.
- The mid-round joiner is the case that matters: they arrive into a round with
  items on the ground, scores on the board and terrain already destroyed.
- Do not invent a new "join snapshot" message. The events exist; the defect is
  that nobody sends them.

## Tests

- A client joining a room where items were placed at round start receives an entry
  for **every** live world item — assert the count against the server's, the way
  T9.03's e2e asserts tracked-vs-drawn rather than just "the server has some".
- A client joining after kills have happened sees non-zero scores immediately.
- With `DEV_LOADOUT=1`, the HUD shows the loadout on the first frame, not after the
  first pickup.
- **Negative:** a joining client never receives another player's `inventory`.
- Falsify each at the live binding site.
