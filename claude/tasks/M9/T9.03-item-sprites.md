# T9.03 — Item, crate and pickup sprites (v2)

Milestone: M9 · Depends on: T7.02 · Size: ~150 lines

## Read first
- `docs/30-items-inventory.md` §1 (every `ItemDef` already carries a `sprite` key)
- `docs/50-sprites-skins.md` §8

## Why

Players have real sprites; items and crates are still coloured rectangles, and
`ItemDef.sprite` has been populated since T4.01 and never used. Kenney's
`pixel-platformer` pack is already vendored and has the art.

## Touch only
- `client/src/render/itemSprites.ts` + test
- `assets/atlas-map.json`, `assets/skins.json` (item frame entries)
- the world-item render path

## Deliverable

Items render their `ItemDef.sprite` frame with the existing bob and glow; crates
render a crate frame with a parachute while falling (`docs/32` §4 calls for the
parachute and the beacon); a buried reveal keeps its distinct sparkle so the
association with digging stays learnable (`docs/32` §5).

## Notes

- Fall back to the current coloured box per `docs/50` §8, logging once — the game
  must still start with no art.
- The inventory panel and the HUD strip use the **same** frames, so an item looks
  the same on the ground and in the slot.
- Do not change pickup radius or any gameplay number; this is presentation only.

## Tests

- Every `ItemDef.sprite` resolves in the atlas manifest, or the test names the ones
  that do not. This is the check that stops a registry entry and its art drifting.
- An unknown sprite key falls back to the placeholder and logs exactly once.
- A crate switches from parachute to grounded frame on landing.

## Done when

```sh
npm --prefix client test -- --run itemSprites && node scripts/e2e.mjs items
```
