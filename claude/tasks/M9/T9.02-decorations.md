# T9.02 — Draw the decorations (v2)

Milestone: M9 · Depends on: T7.02 · Size: 1–2 files, ~150 lines

## Read first
- `docs/50-sprites-skins.md` §6
- `docs/12-map-render.md` §5 (layer order: decorations at depth 10)

## Why

`MapMeta.decorations` has been generated since M1 — kind, position, surface-normal
flags — shipped in `map_init` since T6.04, and **never drawn**. The terrain reads
as bare because of it. The data and the wire format both already exist; this is
only the drawing.

## Touch only
- `client/src/render/decorations.ts` + `decorations.test.ts`
- `client/src/render/worldView.ts` (add the layer)
- `assets/atlas-map.json` (decor frames per theme)

## Deliverable

```ts
export class DecorationLayer {
  constructor(scene: Phaser.Scene, theme: ThemeId)
  build(decorations: Decoration[]): void
  /** Remove decorations whose anchor pixel is no longer solid. */
  onCarve(x: number, y: number, r: number): number
}
```

## Notes

- Depth 10 — above terrain, below world items.
- Each `kind` maps to a frame in the theme's `decorSet`; **a theme with no entry
  for a kind skips it** (`docs/50` §6), so kinds and themes evolve independently.
- Flags carry flip and scale tier; the surface normal is already estimated at
  generation, so props sit flat rather than all upright.
- **A decoration standing on ground that has been blown away must go.** It is
  cosmetic, so removal can be lazy — but a tuft floating over a crater is exactly
  the kind of detail that makes destruction feel fake.
- Purely visual: no collision, no gameplay effect, and a low-end client may skip
  the layer entirely.

## Tests (vitest, pure)

- An unknown kind is skipped without throwing and logs once.
- `onCarve` removes exactly the decorations inside the circle and returns the count.
- Flip and scale tier decode from flags correctly.
- A decoration whose anchor is already air at build time is not placed.
