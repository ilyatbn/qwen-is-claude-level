# T9.07 — The bake got slower and nobody knows why (v2)

Milestone: M9 · Depends on: T9.05 · Size: investigation, then a fix or a written finding

## The evidence

`docs/60` §6 sets a 400 ms ceiling on a full chunk bake at round start. Measured
now: **~427 ms**, red. Two sessions ago the same measurement was **280–296 ms**.

It was A/B'd rather than assumed. With the T9.05 conjunct fully disabled: 435 ms.
With it: 425 ms. On `953987b` in a clean worktree with only the harness fix
applied: **427 ms**. So it is **not** T9.05, and it predates that commit.

The samples are **bimodal in both commits with the same shape** —
`[445, 315, 279, 427, 437]` across five regenerate-and-bake cycles, with #2 and #3
consistently fast. That is a systematic effect, not variance, and it is the thread
to pull: something is warm on those two runs and cold on the others.

## What is wanted

Find the cause. Candidates worth eliminating in order, cheapest first:

- **Measurement**: is the harness timing the same work in both cases? A number that
  moved without a code change is a measurement suspect before it is a performance
  suspect, and this project has already had `actualFps` under-report for seconds
  after a stall.
- **Warm-up**: JIT, texture upload, or a lazily-built table that survives between
  the fast runs and not the slow ones.
- **Allocation**: the bake is supposed to reuse one scratch `ImageData` and one
  scratch canvas (`docs/12` §8). Confirm nothing reallocates per bake, and that
  the backdrop's coarse-grid work (§A17 hit counts, §A37 distance transform) is
  done once per bake rather than per chunk.
- **Real regression**: if it is genuine, bisect. The recorded 280–296 ms gives a
  known-good point.

## Rules

- **Do not move the ceiling.** If the honest conclusion is that 400 ms was always
  optimistic for this machine and this renderer, say so with the numbers and
  propose a ceiling with a stated basis — but that is a conclusion, not a shortcut.
- A/B every hypothesis. A metric with no control is a number, not evidence.
- The bimodality is the strongest clue in the data. An explanation that does not
  account for it is incomplete.

## Done when

Either the bake is back under the ceiling with the cause named and a regression
test that would catch it again, **or** a written finding in `tasks/JOURNAL.md` and
`docs/70-amendments-v2.md` that explains the bimodality, states what the ceiling
should be and why, and shows the measurements behind it.
