# T22.12E — What the tick review found

Milestone: M22 · From the accepted review of `4dfc5a5` (T22.12D; evidence `gate-review2212d-*.txt` in the repo
root) · Size: small–medium

## Findings (the review measured each)
- **F1 (guard went blind):** `Predictor.relocate`'s short-relocation branch measures `d` against the *current*
  prediction — a lead ahead of the server. When the snapshot at or past the relocation has already been
  reconciled (the prediction already holds the move), a moving body still shows `d > ε`, so the **next** correction
  is marked the relocation's and left out of the maxima — even a genuine misprediction (the review's temp vitest:
  a planted 20 px error read `maxAck 0`, `settled 2`; `gate-review2212d-relocate-plant.txt`). Teleport and
  `vortex_trip` take the same branch. **Fix:** `relocate` takes the event's tick; a snapshot at/past it already
  reconciled → no mark; otherwise compare the arrival with the prediction **at that tick** (the seq that ran on it),
  falling back to the current one only when there is none.
- **F2 (guard that cannot fail):** nothing checks the wire's `ends_tick` against the world's — a `+2` plant in
  `events.rs::round_state_payload` stayed green in Rust and in `black-hole` (`gate-review2212d-wireplant-*.txt`).
  **Fix:** a server test that the payload of `World::round_state_event` carries `phase_ends_tick()` and a
  `time_left` derived from it, in every phase; and an exact integer arm in `black-hole`: the tick the server rang
  the bell on (the `ended` `round_state`'s tick) equals the page's `bellEndsTick`. Plant `+2` red in both.
- **F4:** the HUD/results countdown (`results-math.ts::phaseDeadline`) is built from the float `time_left`; derive
  it from `ends_tick` — one rule.
- **F5:** the doc comment on `clock_ticks` names `tick_idle` as why `tick` and the round clock differ; the real
  reason is `room.rs` setting `world.tick = self.lobby_tick` at the first install (`tick_idle` has no production
  caller). Drive `the_bell_predicted_at_round_start_is_the_servers`' lobby case through that assignment.
- **F6:** `debug_assert_eq!(dt, SIM_DT)` in `World::step` — the derived clock assumes it.
- **Nits:** `golden_weather.txt`'s header says "recorded at 9535325^"; it was regenerated at `4dfc5a5` under R94.
  `dev_place_inward_of` (the vortex check's placer) gets the relocation event F3 gave `dev_place_near_black_hole`.

## As built (2026-09-24)
- **F1** `Predictor.relocate(x, y, tick)` (`GameScene.onRelocated` passes the event's `tick`): a snapshot at/past
  `tick` already reconciled → nothing; else the arrival is compared with `predictionAt(tick)` (seq `lastAck + tick −
  lastTick`), the current prediction only when none. Two vitests, **red at `a345d45`** (`gate-t2212e-red-vitest.txt`:
  both *"expected 1 to be +0"* — the genuine 20 px error was settled): snapshot-first, and a relocation the prediction
  itself made (a predicted vortex trip). Control: the event before its snapshot for an unpredicted move still settles.
  The fixture walks right from the spawn and a wall stops it at seq 21 (measured), so it reads ticks ≤ 20.
- **The event tick now means one thing:** the first tick whose state holds the move. Pads and trips are stepped, so
  their own tick; a dev placement runs between ticks, after that tick's snapshot, so `World::dev_relocate` stamps
  `tick + 1` — with the old `tick`, the new skip would have dropped a placement the snapshot never carried. Plant
  `tick` → `dev_relocations_are_announced_on_the_first_tick_that_holds_them` red (`gate-t2212e-plant-devtick.txt`).
- **F2** `events::tests::round_state_payload_carries_the_worlds_ends_tick_in_every_phase` (Lobby null; Warmup,
  Playing, Ended 37 ticks in). `black-hole` arm: `endedAtTick` (the `ended` `round_state`'s tick) `=== bellEndsTick`.
  Plant `ends_tick + 2` in `round_state_payload`: cargo red *"left: 602, right: 600"*; e2e red *"said ends_tick 4389,
  the server rang the bell on tick 4387 — off by 2"* while the bell px arm stayed green at 1.43 px
  (`gate-t2212e-plant-wire-{cargo,e2e}.txt`) — the review's finding reproduced. Green: 4388 = 4388.
  (The snapshot carries no phase, so "the first Ended snapshot" is read as the `ended` `round_state`; `World::step` sets
  `Ended` last, so its tick is the last `Playing` tick, exactly.)
- **F4** `phaseDeadline(serverRoundTime, serverTick, stateTick, endsTick | null, dt)`: `ends_tick − serverTick` whole
  ticks from the snapshot anchor; every rebroadcast of one phase gives the identical deadline (vitest, `Set` size 1).
- **F5** `clock_ticks`' doc names `room.rs`'s `world.tick = self.lobby_tick`; `tick_idle` documented as having no
  production caller; the bell test's lobby offsets are set by that same assignment. **F6** `debug_assert_eq!(dt,
  SIM_DT)` — the `--changed` run is a debug build, 1668 tests, none tripped it (`AttractCore::step(dt)` in wasm passes
  a JS dt; dormant, no caller).

  `dev_place_near_black_hole`). That made **`breach-vortex` red once** (`lastAckErrorPx` 385.84 px): the page now has
