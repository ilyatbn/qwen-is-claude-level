`R14`'s table has said since it was written that space has **"no animals at all"**, and that the
same ruling answers the `birds.rs` row. Nothing implements it. So a space round today spawns
beetles and spiders, and they stand on the rim and on asteroid tops **in a vacuum**.

This is the smallest task left in the milestone and the only one whose bug a player would see
immediately, so it is worth doing properly rather than quickly.

had given `T22.11A` only the four signature changes, and neither `T22.11B` nor `T22.11C` mentions

## **Gate on the generator, not on the gravity field** (`R58`)

The one hazard, and it is the whole reason this file says anything about how to do it. `R15`
derives `MapGenerator::Space` **from the mode**, and that derivation is the single source of truth
for "this round is in space". A suppression keyed on `self.gravity` is a second answer to the same
question, and `R15` exists precisely because two answers come apart. `Map::space_geometry`'s
`Some` is the established spelling for code holding a `&Map` — but read its doc first, because
`F6`/`R49` records that it is **sound server-side only** until `T22.11C` installs the client's
asteroid list, and note at the code which side your call runs on.

## Tests

- **A space round spawns no animals and no birds** — over several seeds, because a population
  claim needs more than one draw.
- **The control, and without it this task is untestable:** a **standard** round on the same seeds
  spawns animals and birds. "No animals in space" is satisfied by a build that spawns none
  anywhere, and that build would pass every assertion above.
- **Nothing already alive is stranded.** If a mode can change mid-session anywhere in this
  codebase, say at the code whether an animal alive at the switch is removed or left, and assert
  whichever you chose. If it cannot, say that instead and cite what makes it impossible.

**Falsify at the live binding site** — the suppression's own condition, not a constant and not a
default — and paste the red.
