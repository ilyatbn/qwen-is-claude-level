# T22.00 — The `title` check asserts a control that was deleted five days ago

Milestone: M22 · Depends on: nothing · Size: ~30 lines · Origin: found by T22.01's builder
while running `./scripts/check.sh --changed`, 2026-09-20

**This is not M22 work and it blocks M22's batch gate.** It is numbered `T22.00` because it
has to land before the first full gate of this milestone, not because it belongs to space.

## What is wrong

`scripts/checks/title.mjs` opens the Private Game screen and drives a map-size stepper:

    const shown = () => page.textContent('#scale-value')
    await page.click('#scale-next')
    await page.click('#scale-prev')

**That stepper no longer exists.** `4f28b2e` — *"owner play session: fall damage, boots,
wings, lava off, HUD, and two stale fixes"*, 2026-09-16 — took map size off the pre-host/join
screen at the owner's request and **did not touch `title.mjs`**. Verified against the
artifact, not the working tree:

```
git show 4f28b2e^:claude/client/src/scenes/MenuScene.ts | grep -c "scale-next"   → 2
git show 4f28b2e:claude/client/src/scenes/MenuScene.ts  | grep -c "scale-next"   → 0
git show --stat 4f28b2e -- claude/scripts/checks/title.mjs                        → (empty)
```

The check fails as `page.textContent: Timeout 30000ms exceeded. - waiting for
locator('#scale-value')`, taking ~98 s to do it.

## Why nothing reported it for five days

`title` is only selected by `scripts/affected.mjs` when a **client source file** changes. The
four commits since `4f28b2e` are a server-side seat fix, a check file, and two documentation
commits — none of them client source. **The first M22 task to touch the client found it
instantly**, which is the `--changed` design working, and also the reason a red check can sit
unseen: nothing runs the full gate between batches except the coordinator.

## The ruling on what it should assert now

**Do not delete the block.** Deleting assertions to make a check green is how coverage
vanishes quietly, and this repo has the rule for it: *a test count going up is not evidence
that no test was removed*, and its inverse applies here.

**The map-size coverage has a live home — and this paragraph originally overstated it.**
CORRECTED 2026-09-20 by the builder, who checked instead of taking my word for it:
`scripts/checks/lobby.mjs` has **two** lists, and `scale` is in only one of them.

```
184:const IDS   = ['scale', 'gravity', 'bots', 'kit', 'timer']
205:const MOVED = ['bots', 'kit', 'timer', 'gravity']
```

`grep -c scale scripts/checks/lobby.mjs` → **1**: that `IDS` line is the only mention in the
file. `IDS` drives three assertions — the row is on the host's panel, on the guest's panel, and
seat-gated. But **the stepping assertions iterate `MOVED`**, so *"the host changed it"* and
*"the guest sees the same"* never ran for map size, and no other check steps it either.

So of the four things I claimed, two were false. **The ruling stands** — the row and the seat
gate genuinely moved to a better place, the stepping logic is pinned by
`client/src/net/lobby.test.ts` (`stepSetting(s, HOST, 'scale', 1, …)` and `-1`, wrapping both
ways, which is exactly what the old `title.mjs` block claimed), and the control this check drove
no longer exists. **But the wire half for `scale` was covered by nothing** — the same gap
T22.01 had just closed for `gravity`, one setting over.

**Closed in the same commit** by adding `'scale'` to `MOVED`. `session.rs`'s `set_scale` takes
the identical `room.set_scale(id, …)` shape as the other four and refuses with `lobby_error`
for the same reason, and `MenuScene` calls it *"the same `scale` row as `bots`, `kit` and
`timer`"* — so its absence from `MOVED` was an oversight, not a rule.

Replace the stepper block with an assertion of what the Private Game screen **is** now —
Host, Join and Back, and that it navigates — plus a comment naming `lobby.mjs`'s `IDS` as
where map size is now asserted and `4f28b2e` as the commit that moved it. A reader who finds
this file in a year should not have to run `git log -S`.
