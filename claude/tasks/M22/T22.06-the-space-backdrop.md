# T22.06 — The space backdrop: sun, moon, earth, stars, and they move

Milestone: M22 · Depends on: **T22.01** · Size: ~200 lines · Origin: new, 2026-09-18

Asked for: *"there's no day/light in space but the sun and moon and the earth and stars can be
the background and should move. there are no clouds or fog or anything like that."*

## What this switches off, and it is a lot

The sky stack is five milestones deep and almost none of it applies. **Switching it off is most
of this task**, and each of these is a separate decision with a live check behind it:

| today | in space |
|---|---|
| the day/night cycle (`docs/14`, `sky-math.ts`, the lightmap) | off — there is no day in orbit |
| clouds (T21.31A: seeded, world-space, drifting) | off — the owner said so |
| the fog effect and `fogVeilAlpha` | off — and it is a *vision* rule, not only a picture |
| ambient rain (T21.26/T21.31B) | off |
| the parallax mountain ridge (`parallax.ts`, T21.20, T21.33) | replaced |
| `SkyBand` and birds | see `T22.05B` |

**`night_darkens_the_world`, `living-sky`, `clouds`, `clouds-canvas`, `cloud-rain`,
`ambient-rain`, `fog-visible` and `fog-shader` are live checks over this area.** Each needs to
either skip in this mode or assert the mode's own answer. The T21.39 precedent is the shape:
a check that reads the switch and skips its section, not a deleted check.

## Deliverable

- Sun, moon, earth and stars, **moving**. The owner said "should move" — so movement is the
  feature, not the decoration, and a still frame cannot show it.
- Seeded off the map seed, so a seed looks like itself. **Read the seed from the wire**, not
  from `core.meta.seed`: the 2026-09-16 finding is that `loadMask` leaves a networked client's
  `meta.seed` at its startup value — measured as 1 across four rounds — and `meta.theme` at 0.
  `GameScene` passes `this.mapSeed` and `init.theme` for exactly this reason now.
- Both render paths. Canvas is not optional (T21.33).

## Hazards

- **A backdrop that moves with the camera instead of the world.** This is the `living-sky` bug
  (`032440f`): `ParallaxLayers.layout` read `camera.worldView.y`, which Phaser refreshes only in
  `preRender`, so the ridge trailed a moving camera by one frame's travel — probed at 9, 8, 6,
  5, 5, 3 px. The fix is `parallax-math.ts::liveViewY` and rig-before-sky ordering. **Anything
  new in this layer inherits that trap.**
- **`drawClouds` still culls on last frame's `worldView`** — recorded as harmless and open. If
  clouds go away here, check whether the new bodies copied the same cull.
- **The lightmap.** Night darkening is a gameplay-visible vision rule, not just a tint. Turning
  the cycle off must not silently leave the lightmap in a permanent state nobody chose.

## Tests

- **The bodies move**: two frames, a real gap, the same body at different pixels, with a
  control region that does not move (§C2's control frame and control region).
- No cloud, no rain, no fog veil, in this mode — each asserted as an **absence beside a
  presence** in the standard mode, or the test passes for a renderer that draws nothing.
- Canvas and WebGL both.
- The backdrop is seeded: two seeds differ, one seed repeats. **Compare against the wire seed**,
  and note that `terrain-seed.mjs` runs in the *sandbox*, where `meta.seed` is real — so it
  could not catch the networked bug. A networked-round assertion is what this needs.
