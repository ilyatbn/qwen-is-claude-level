## Do these, in this order — the first two are the ones that matter

### 1. F1 — prove the three unproven guards are live, or find out they are not

`meta.rs::a_space_map_ships_none_of_the_furniture_that_needs_a_ground` asserts five
collections are empty in space. Only **two** of the five guards are shown to change anything
(`buried_slots` has a measured pre-guard count; `wind` is a float draw that is ~never exactly
zero). For `teleport_pads`, `gun_platforms` and `decorations` the same commit **removed the
floor crust those samplers were finding**, so they may return empty with the guard deleted and
the test would stay green.

**Run deferred falsification 1 before writing anything** — flip each of the three guards to
`if false` *separately* at `meta.rs::generate_full_with` and run that test. Do not flip the
`space` binding itself; that moves all five at once and tells you nothing about which.

- **Any that stays green:** its guard is decoration and the test cannot report its deletion.
  Add the assertion F1 names — call the suppressed sampler directly on a real space map and
  assert it returns something. Then **falsify your own remedy**: with the guard flipped back
  off, the new assertion must go red.
- **All three red:** F1 downgrades to "the reasoning was unstated". Write the numbers into the
  rulings' comments and say at the code that you measured them. `decorations`' comment makes
  the strongest claim — *"the filtered surface still has seated points on asteroid tops, so
  without this guard a space map would ship props standing on rocks"* — and that sentence is a
  number nobody wrote down. Write it down.

### 2. F2 — items in space do not float, and two comments say they do

`items/world.rs::WorldItems::step` passes a literal `1.0` to `integrate`, and its own comment
says so honestly. **You may read that file; you may not edit it** — see Touch only. But `items/spawning.rs::place_initial` and `::tick_crates` describe a crate
arriving in open air **"and floats there"**, present tense. It does not: it falls at standard
gravity to the bottom of the ellipse. **That is the first thing a player would see in this
mode.** All three new tests assert only where a thing is *placed* and never call `step`.

The fix is **not** to make it float — R10 assigns that signature change to `T22.11A`. It is:
- (a) reword both comments to the tense `items/world.rs::step` already uses: *will* float once
  `T22.11A` lands (R14); **today it falls to the rim's inner floor**;
- (b) step the items **from your own test in `items/spawning.rs`** (call `WorldItems::step`,
  do not edit it) in `crates_spawn_inside_the_arena_in_space` and assert what is true
  **today** — still inside the rim, `vel.y` non-zero at least once — so the test has to be
  revisited when `T22.11A` zeroes the scale rather than silently continuing to pass.

Run deferred falsification 3 first and paste its numbers; if the items do not move, F2 is
withdrawn and you should say so.

### 3. F5 — measure what a space respawn actually does, **before** deciding it is a follow-up

`player/respawn.rs`' module doc says *"an assertion that the fallback is dead code is worth
more than the fallback"*. In space there are no pads, so the fallback may be the **only** path.
Run deferred falsification 4. If the respawn position is not one of `map.meta.spawn_points`
mapped through `surface_to_centre`, **stop and report** — that is the headline fix not covering
the death path, which is a blocker and not a follow-up. Otherwise: the sentence in
`player/respawn.rs`'s module doc naming space as the mode where the fallback is the path, plus
the test F5 suggests. **The matching sentence at `resolve_deaths` is `T22.11A`'s file** — put
the exact wording you want in your journal entry and say it is owed.
