# T22.00D — `body.airborne_ticks` is unhashed, and it is not a derived value

Milestone: M22 (filed here, **not M22 work**) · Depends on: nothing · Size: ~40 lines ·
Origin: found by `T22.03`, 2026-09-21

**Pre-existing, in every mode, and not urgent** — but it is a determinism hole and this
milestone is the reason anyone looked. **Do it after M22 closes** unless a desync makes it
urgent sooner.

## The hole

`World::state_hash`'s per-player fold hashes `id`, `body.pos`, `body.vel`, `body.grounded`,
`aim`, `health`, `score`, `deaths`, `alive`, the five `jetpack` fields, `jump.buffered_ticks`,
`respawn_at`, `iframes_until` and the inventory. It does **not** hash `body.airborne_ticks`:
`grep -c airborne_ticks crates/game-core/src/world/mod.rs` → **0**.

`T22.03`'s task file — mine — said `airborne_ticks` was unhashed *"as a per-tick derived
value"*, alongside `landing_impact`. **`landing_impact` genuinely is derived and reset every
tick. `airborne_ticks` is a running counter**, and it gates:

- `Body::in_coyote_time()` → `try_jump`'s `can_launch`, and
- `jetpack::update`'s hold-delay branch.

**So two worlds can agree on every hashed field at a checkpoint and disagree on
`airborne_ticks`** — one can coyote-jump off a ledge and the other cannot, and nothing reports
it. The hash is sampled at checkpoints, not every tick, which is exactly the gap: the
`grounded` histories can differ between samples and agree at them.

## Before you fix it, prove it

**Construct the two worlds.** Same seed, same hashed fields at a checkpoint, different
`airborne_ticks`; show one launches and the other does not. **If you cannot construct it, say
so and stop** — the hole may be unreachable in practice, and that is a finding worth more than
a speculative fix.

## The cost, which is the reason this is its own task

Adding a field to the per-player fold **moves every state hash in the game**. That invalidates
historical checkpoints and very likely moves `REPLAY_VERSION` (currently 14). `replay.rs`'s own
rule is that anything an old file would *"load, run, and diverge silently"* on is a bump — and
this is the definition of that.

So: measure first, then decide between hashing it and **deriving it**, which is the other
honest answer. `airborne_ticks` could be recomputed from `grounded` if the reset rule is
exactly *"zero when grounded, increment otherwise"* — check whether it is, because if it is,
the field is redundant with something already hashed and the fix is smaller.
