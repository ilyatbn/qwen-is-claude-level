# T22.01 — The gravity match setting

Milestone: M22 · Depends on: nothing · Size: ~150 lines · Origin: the first half of the parked
`T21.05-low-gravity.md`

**The foundation, and deliberately behaviourless.** This task ships the setting and changes
how nothing plays. Every other task in M22 reads it.

## Why this no longer depends on T21.04

`T21.05` declared *"Depends on: T21.04 (the settings pattern)"* — the day/night setting, which
is parked. Two things retire that: the owner has ruled day/night **out** of space entirely, and
the pattern T21.04 was going to establish is **T20.07's**, which landed. Copy T20.07's path
directly. Nothing in M22 waits on the parking lot.

## Read first
- `tasks/M20/T20.07-*` and the settings it added — the path this copies
- `client/src/ui/menu.ts` and `MenuScene`'s lobby `step('scale', …)` row — the four existing
  rows are the shape a fifth takes
- `crates/game-server/src/room.rs` — where a lobby setting becomes world state
- `crates/game-server/src/replay.rs` — the header, and why simulation state belongs in it

## Deliverable

- One setting, `standard | low | space`, on T20.07's established path: lobby panel row, wire
  message, host-only, `lobby_state` broadcast, and **in the replay header** because it is
  simulation state that must survive a restart.
- It reaches `World` as one field and nothing reads it yet beyond a test.
- The name is `space`, not `none`. The brief said *"gravity: standard, low, none"*, but the
  mode the owner described is not "no gravity" — it is a different map, a different backdrop,
  two hazards and a suit. Naming the enum after the one physical property it changes is how it
  ends up with map generation hanging off a word that means gravity. **If the owner wants low
  gravity dropped (see the milestone's open question 3), this becomes `standard | space` and
  `T22.02` is deleted.**

## Hazards

- **Determinism.** The setting is read inside the pure simulation, so it must reach
  `apply_input`'s path identically on both sides or prediction desyncs. This is the shape
  T21.02 and T21.03 solved: derive at the encode site, do not store a second copy.
- **`docs/` does not describe this setting.** An amendment is owed; a builder does not write
  it. Report the gap.

## Tests

- The setting round-trips: set in the lobby, arrives in `World`, survives a restart.
- A guest cannot change it and the refusal is visible (T20.07's rule, and `lobby_error` not
  `join_error` — `config.rs` records why).
- **The control: with the setting at `standard`, every existing test still passes unchanged.**
  That is the assertion that says this task shipped no behaviour.
