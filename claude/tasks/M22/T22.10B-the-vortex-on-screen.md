# T22.10B — The vortex on screen

Milestone: M22 · Depends on: **T22.10A** (the Rust half: detection, vortex, pull, capture, events,
`GameCore::set_vortices`) · Origin: the split of `T22.10-the-breach-vortex.md` (2026-09-24).
Read that file's **As built — T22.10A** first; the rulings are R9, R11, R16, R19. M23 restyles
visuals later — build in the current renderer.

**Until this lands a client predicts no pull near a vortex while the server pulls: a rubber-band.**
T22.10A must not reach players without it.

## Touch only
`client/src/net/*` (the event handlers), `client/src/world/worldMirror.ts` (+ test),
`client/src/core/index.ts` (the `setVortices` wrapper), a new `client/src/render/vortexFx.ts` +

## Do these
1. **Mirror the list, in opening order.** `vortex_open` appends `{id, x, y}`, `vortex_close` removes
   by id, both call `core.setVortices(xs, ys)` with the list **unsorted** (R11: the sum's order is
   the contract — `set_vortices`' doc). `vortex_trip` for you: snap the predictor to `(x, y)` the way
   `teleport` does (find that handler and share it — do not write a second one). A new round clears
   the list (`resetForNewRound`'s field rule — `gameScene-reset.test.ts` enforces it).
2. **Draw it** — a swirling vortex at each live one, unmistakable in the world (R9, point 5), **not
   on the minimap**. Radius the drawing from `VORTEX_CAPTURE_R` (what takes you) with the swirl out
   toward `VORTEX_REACH / 2` (where thrust stops winning), so what you see is what pulls. Both render
   paths (shader and flat, T21.33/T21.36), as `flareFx` does.
3. **Sandbox hook**: a way to open a vortex in the sandbox for the pixel check (the sandbox has no
   `World`; a `?vortex=` or a `window.__game` dev call that sets the core's list and the layer).
4. **`scripts/checks/breach-vortex.mjs`** — in a real match (`GameScene`, not only the sandbox):
   breach the rim (a `DEV_LOADOUT` bazooka at the rim, or a dev hook), then assert **on rendered
   pixels** that the vortex is drawn where `vortex_open` put it, with a **control region** clear of it
   and a **control frame** with the layer hidden (§C2); that it is absent from the minimap (a
   `page.screenshot()` of the DOM overlay — R13's note); that a player driven into it reappears
   inside the rim; and that the client's predicted position does not jump near the vortex beyond one
   snapshot's travel (the rubber-band this task exists to prevent — plant: skip `setVortices` → red).
