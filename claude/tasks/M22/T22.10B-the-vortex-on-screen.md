## Do these
1. **Mirror the list, in opening order.** `vortex_open` appends `{id, x, y}`, `vortex_close` removes
   by id, both call `core.setVortices(xs, ys)` with the list **unsorted** (R11: the sum's order is
   the contract — `set_vortices`' doc). `vortex_trip` for you: snap the predictor to `(x, y)` the way
   `teleport` does (find that handler and share it — do not write a second one). A new round clears
   the list (`resetForNewRound`'s field rule — `gameScene-reset.test.ts` enforces it).
2. **Draw it** — a swirling vortex at each live one, unmistakable in the world (R9, point 5), **not
   on the minimap**. Radius the drawing from `VORTEX_CAPTURE_R` (what takes you) with the swirl out
   toward `VORTEX_REACH / 2` (where thrust stops winning), so what you see is what pulls. Both render
   paths (shader and flat, T21.33/T21.36), as `flareFx` does.
3. **Sandbox hook**: a way to open a vortex in the sandbox for the pixel check (the sandbox has no
   `World`; a `?vortex=` or a `window.__game` dev call that sets the core's list and the layer).
4. **`scripts/checks/breach-vortex.mjs`** — in a real match (`GameScene`, not only the sandbox):
   breach the rim (a `DEV_LOADOUT` bazooka at the rim, or a dev hook), then assert **on rendered
   pixels** that the vortex is drawn where `vortex_open` put it, with a **control region** clear of it
   and a **control frame** with the layer hidden (§C2); that it is absent from the minimap (a
   `page.screenshot()` of the DOM overlay — R13's note); that a player driven into it reappears
   inside the rim; and that the client's predicted position does not jump near the vortex beyond one
   snapshot's travel (the rubber-band this task exists to prevent — plant: skip `setVortices` → red).

## As built (2026-09-24)
- **The list** is `WorldMirror.vortices` (`vortex_open` appends `{id, x, y}` by id — the join catch-up's
  re-announcement is not a second; `vortex_close` marks `closedAt`, R88), in opening order, unsorted;
  every change calls `Core.setVortices(pulling)` (the new `core/index.ts` wrapper — its production caller).
  Held by the mirror, not the scene: a `map_init` resync does not drop it, and `onMapInit` re-pushes it
  after the map (events before the map are applied after). A new `WorldMirror` clears the **shared**
  core (the registry's core outlives a scene — measured: the last test's vortices were still pulling
  in the next one); `resetForNewRound` and the in-scene restart branch call `clearVortices`.
- **Relocations**: `GameScene.onRelocated` is the one handler for `teleport` **and** `vortex_trip` —
  there was no teleport handler to share; a pad trip reached the local body only as a reconcile error
  and a remote glided. You: `Predictor.relocate` (sim + render snap, skipped when a snapshot already
  put you there). Others: `RemoteInterpolator.cut` steps across the trip at the midpoint.
- **Drawing**: `render/vortexFx.ts` (+ `-math`): dark core, spiral arms to `VORTEX_REACH/2`, the capture
  ring opaque at `VORTEX_CAPTURE_R` in `VORTEX_RING_COLOR`; shader quad per vortex under High Quality,
  `Graphics` otherwise; closed ones fade over `VORTEX_FADE_MS`. Not on the minimap. `VORTEX_CAPTURE_R` /
  `VORTEX_REACH` added to `constants_json`. Sandbox: `__game.openVortex(x, y)` / `showVortices`.
- **The check** (`breach-vortex`, standalone): sandbox arm + a real match on a `DEV_PROBE` server
  (`debug_breach` → `World::dev_breach_toward` / `dev_place_inward_of`, both `#[doc(hidden)]` seams,
  the verb guarded by the extended `the_flare_probe_answers_only_on_a_dev_probe_server`).
  Asserts: the vortex where the server breached; **no correction moves the predicted body more than
  `RECONCILE_EPSILON_PX` while it pulls** (`PredictorStats.lastJumpPx`, new); the trip inside the rim,
  clear of the pull, the prediction there; the ring **in its own colour** at ≥ 80 % of in-view probes,
  both paths, against a hidden frame, plus a clear control; the minimap unchanged.
- **Three netcode defects the rubber-band arm found, all pre-existing, all player-visible on anything
  moving fast** — outside the Touch-only list, each measured red first, reported for the reviewer:
  1. `session.rs` `input` handler did its work inside the spawned future, so two packets could reach the
     room out of order and the room drops any seq not above the last accepted: **137 seq gaps in one
     match** (instrumented, then removed) → 0 once the work runs in the handler call.
  2. `GameScene` sent only `batch.slice(-INPUT_REDUNDANCY)` per frame: a frame of 4+ ticks (a 15–20 fps
     page) lost its oldest inputs. Now every input, in packets of at most `INPUT_REDUNDANCY` (the spec's
     value unchanged).
  3. `Room::last_seqs` acked the last *received* input; the world consumes one per tick. Now the last
     *consumed* (`World::oldest_queued_seq` − 1, derived). Room test red first (*"left: Some(3), right:
     Some(0)"*); a room + client model at 15 fps measured errors 1.3–5.1 px before, 0.00 after.
  Before the three: worst jump 11–14 px under the pull (every other snapshot). After: 0.72 px.
- `lastCorrectionPx` / the correction **count** are not a rubber-band measure — they compare the
  current prediction with the acked state, so any fast body "corrects" every snapshot (11 of 12 here
  with the list told). Reported: `RECONCILE_EPSILON_PX`'s early return is gated on that same number, so
  it almost never fires while moving; every snapshot resets and replays. Harmless now, not fixed.

  handler back (bv10) → *"worst correction jump 11.67 px"*; unguarded `debug_breach` → *"a server
  without DEV_PROBE answered debug_breach"*.
