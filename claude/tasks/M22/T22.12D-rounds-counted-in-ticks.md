## Findings (the review measured each)
- **R94 — a round's length was an `f32` sum reaching a float deadline.** Playing lasted **14401 / 18002 / 36006**
  ticks for 240 / 300 / 600 s rounds (a 600 s round ran 600.1 s), and the bell `black_hole::bell_seq` derived from
  the round-start `round_state` was off by **−1 / −2 / −6** ticks (`gate-review2212c-drift.txt`); at 600 s the
  wasm bell test read 222 px (`gate-review2212c-bell600.txt`). T22.12C's `<= SIM_DT/2` fixed ties only, and its
  comment ("a round is a whole number of ticks, so the deadline always falls on a tie") is false for real rounds.
  **Ruled:** every phase records the tick it began on; its end tick = start + round(seconds × `SIM_HZ`); Warmup,
  Playing and the Ended vote window (`round.rs`) all end by that one rule (one function); `round_time` and
  `phase_time_left()` are derived from ticks; `round_state` carries an integer `ends_tick`; `bell_seq = ack +
  ends_tick − snap_tick + 1`, no float.
- **F1 (MEDIUM) — a guard that cannot fail:** deleting `GameScene.onSnapshot`'s `setBell` call leaves `black-hole`
  green. Add an arm for a body in the pull at the bell, with the deleted-`setBell` plant red.
- **F3** — `dev_place_near_black_hole` moved the body with no relocation event, so the predictor counted the
  44 px placement as a misprediction (T22.12C's "not this task's" line).
- **F4** — the escape test measures to `REACH + 8` while the wells switch back on abruptly at `REACH`: assert past
  it that escape still holds with the wells on (or say why it cannot fail there).
- **F6** — `breach-vortex.mjs`'s comment about `i16` positions (~1.4 px) is false since T22.10H.
- **F7** — one `World` method builds `black_hole_warn` for the live telegraph and `session.rs`'s catch-up.
- DOCS-77: the round length is exact in ticks; `ends_tick` on the wire.
