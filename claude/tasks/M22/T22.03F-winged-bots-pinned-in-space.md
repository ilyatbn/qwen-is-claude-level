# T22.03F — Winged bots pinned in space

Milestone: M22 · Depends on: T22.03D · Size: small · Origin: T22.03D (filed), T22.03E F7. **Built** (below) — the ruling it asked for is recorded as the builder's call.

`space::flies` excludes wings (R5 kept wings "as anywhere"), so a winged bot in space steers by the walking model's
buttons. `space_bots_report` counts it apart: against rock **0.0–1.4 %** of alive time, runs up to **51 s**
(T22.03D's As built; 0.0–0.8 % over T22.03E's four 32-seed draws, `gate-t2203e-pin.txt`). Rule first whether a winged
bot in space should use `space::steer`'s detour (wings are not fuel-limited, so only the rock half applies), then
assert a winged-bot pinned bound in `space_bots_report` with a plant.

## Done when

## Decided (builder, 2026-09-24 — for the coordinator to confirm or reverse)
**Not `space::steer`'s detour.** Measured first (`space_bots_report`, new `runs_wings`/`longest_wings`, four 32-seed
draws): winged pinned runs ≥ 10 s were **standard 6/6/3/10, space 4/0/6/4 (to 152 s)** — as common under ordinary
gravity, so not a space problem. Traced: a winged bot hovering against rock holding RIGHT (or LEFT), still. The
walking model's stuck response is a jump and **wings refuse the jump**; the note at the code expected it to "walk out
sideways" and it never did. So the fix is the walking model's, in every mode, and R5 ("wings as anywhere") stands.
Reverse by: the `winged && stuck` block in `Bot::think`.
