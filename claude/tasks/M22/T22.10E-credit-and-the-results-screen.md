## Do these
- **F-1 (HIGH, exploit)** — catch-up credit is bankable: it accrued on every input-less tick in any state (dead,
  Warmup, silent), survived respawn and Warmup→Playing, and a 1/tick client never spent it. Bank 15 while dead,
  send 1+16 future seqs later: a 2× dash (5.00 px/tick for 10 ticks vs a walk's 2.50). **Ruling:** credit accrues
  only while alive and the phase accepts input; cleared at the end of any tick where the player consumed an input
  and has ≤ `INPUT_BACKLOG_TARGET` left; reset on respawn and when Playing starts. Guard in `world_step`: bank
  (dead / warmup / silent) → 60 honest ticks → burst: no tick consumes 2; the honest long frame still drains.
- **F-3 (MED, player-visible)** — in `Ended` the server takes no input and steps neutral ticks (T21.30); the client

  every snapshot (104 corrections, jumps to 41 px), replaying everything each time. Stop keeping inputs when the
  phase takes none; neutral local ticks as the server; share the rule. vitest + `thrusters-match`'s bell arm.

- **F-5 (MED)** — `thrusters-match`'s bell arm fails ~1 in 6: bo can be grounded at the bell, where DOWN cannot
  engage, and the arm never asserted its airborne precondition. Establish and verify it (fail as `control:`).
- **F-6** — a vitest where only health changes while moving (and only `alive`); say at the gate that other hidden
  state is not re-installed while the position agrees.

## As built (2026-09-24)
- **F-1** `World::apply_inputs`: credit is zero while dead or in a phase that takes no input (so a respawn starts at
  0 — derived from `alive`, not a second reset at `respawn`); cleared after any tick where the player consumed and
  has ≤ target queued; `set_phase` zeroes every credit on **any** transition (a superset of "when Playing starts",
  said at the code). Guard `catch_up_credit_cannot_be_banked_for_a_later_burst`: control — the honest long frame
  (silence straight into its burst) still consumes 2 a tick. Red before: *"credit banked silent, then 60 honest
  ticks: a later burst consumed 2 inputs in one tick"*. Each half planted alone, each red at its own case: clear
  off → the silent/60 case; alive rule off → *"banked dead, then 0 honest ticks"*; `set_phase` reset off →
  *"banked warmup, then 0 honest ticks"*. **T22.10D's world test changed shape:** its control was a *stream* of 2/tick
  after silence, which by the ruling no longer catches up (the stream never stands above the target, so its first
  tick clears the credit); its first tick now carries the long frame's burst. The room's `a_long_frame…` is unchanged
  and green.
- **F-3** `Predictor`: while `core.acceptsInput()` (new wasm export = `RoundPhase::accepts_input`) is false it keeps
  nothing — `pending`/`predicted` cleared on entry — and steps a neutral tick per local step, each labelled with the
  server tick it stands for. A snapshot (now carrying `tick`) is compared with the local state labelled with its tick,
  by the same gate; a local body behind the snapshot first runs the ticks it owes (≤ one `MAX_FRAME_DT`); a
  correction re-anchors and replays as many neutral ticks as it was ahead. vitest `the results screen` (a falling
  body, two inputs in flight at the bell, told two ticks late, on-time and jittered delivery): HEAD's predictor →
  *"expected 76 to be +0"* (pending), and with the pending line removed *"expected 44.78 to be ≤ 2"*; catch-up
  planted off → *"expected 4.69 to be ≤ 2"* (jittered). `thrusters-match` before the fix: *"11 corrections in 3 s
  after the bell (the first 11.64 px), worst later jump 13.75 px, pending up to 181"* (`gate-t2210e-thr-before2.txt`);
  after, 5 runs: pending 0, one correction ≤ 0.14 px (the first of those runs failed on a "bo must drift" control this
  task then dropped — `gate-t2210e-thr-after1.txt`). **But bo drifted ≤ 0.1 px after the bell in all five runs** (parked under/against a rock), so
  in the browser the pending half is the discriminating one; the moving case is the vitest's. The check asserts a
  pending control (inputs kept before the bell) and reports the drift rather than requiring it.
