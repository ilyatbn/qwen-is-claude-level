# T21.06 — Zero gravity: the movement model (v9)

Milestone: M21 · Depends on: **T21.05** (the setting), **T21.07** is its map · Size: **large**

Asked for: *"no gravity mode makes everything basically float in space… In no gravity mode the
players movement just doesn't stop. If they move in a certain direction, it's constant until
they hit something. Jumping and even moving now takes jetpack energy."*

**This is a different movement model, not a gravity value of zero.** Setting `GRAVITY = 0`
gives you a game where nobody can move: `move_x` relies on ground friction and `grounded` to
do anything, and a player with no contact has no input authority at all. Read the brief again
— *momentum that never stops*, and *movement costs fuel* — and note that neither follows from
zeroing a constant.

## Read first
- `crates/game-core/src/physics/resolve.rs` — the whole file, especially `move_x`, `move_y`,
  `ground_snap`, and how `grounded` gates everything
- `crates/game-core/src/player/jetpack.rs` — the fuel model this mode makes universal
- `crates/game-core/src/player/mod.rs:19-23` — the purity contract, which this must not break

## Deliverable

- A movement regime where **velocity persists**: input applies an impulse, and nothing damps
  it but a collision. `GROUND_FRICTION` and `AIR_DRAG` must not apply, and saying "set them to
  zero" is not the same as saying which code path runs.
- **Every input costs jetpack fuel** — moving and "jumping" alike. That makes
  `JETPACK_MAX_FUEL` the whole resource economy of the mode, so state what refuels and how
  fast, or the mode ends with everyone motionless.
- Collisions **stop or bounce** — decide which, and say so. "Constant until they hit
  something" does not say what happens on contact, and the two feel completely different.

## The questions that must be answered before any code

1. **What is `grounded` in zero-g?** It gates jumping, friction, fall damage, `ground_snap`,
   step-up, and the bot's entire movement model. If it is always false, every one of those
   paths changes behaviour at once. If it is true on contact, "landing" happens constantly.
2. **What happens to fall damage (T20.11)?** There is no fall. Either the mode disables it, or
   impact damage becomes the *collision* rule and this task owns it.
3. **What do bots do?** `bots/mod.rs` assumes walking, jumping and a ground. A bot in zero-g
   with a walking model is a bot that never moves — and `balance.rs` will measure that as a
   game with no fights. **This is not optional scope**; a mode where bots are inert is a mode
   nobody can playtest alone.
4. **Prediction.** Momentum that never damps makes divergence permanent rather than
   self-correcting: under friction a mispredicted velocity decays, here it persists forever.
   Say how reconciliation behaves before building.

## Notes

- **Do not fork `apply_input`.** Two movement functions is the "share the guard, or share the
  function" rule broken at the largest possible scale, and every future movement change would
  need doing twice. One path, branching on the regime.
- Anything stored for this is hashed and must join the exhaustive destructure at
  `world/mod.rs:3331`.
- The map this mode needs is **T21.07** and does not exist. **This task is unplayable without
  it** — sequence them together or build behind a flag.

## Tests

- Velocity persists across ticks with no input, and a collision is the only thing that changes
  it — with a standard-gravity control in the same test.
- Fuel is consumed by movement, and at zero fuel the player keeps drifting but cannot steer.
- Prediction and server agree after a mispredicted impulse.
- Determinism: fixed seed, same state hash across runs.
