# T21.34 — Wings that hover

Milestone: M21 · Depends on: **T21.03** (unicorn wings), **T21.02** (the boots' visible-on-body
pattern) · Size: ~250 lines across three small changes

## The report

The owner played on 2026-09-15: *"i just pickd up unicorn wingws and the player keeps flying
up"*.

Three defects, all visible in one screenshot of a flying player:

1. **Flight rises forever.** `player/movement.rs::apply_flight` set `vel.y = -WINGS_FLY_SPEED`
   with no input and `+WINGS_FLY_SPEED` with DOWN. There was no hover. That was T21.03's
   literal reading of *"you just fly constantly"*, and T21.03's own test asserted "rises
   without input and keeps rising" — so the suite was pinned to the bug.
2. **The wings are not drawn on the player.** The item sits in the last inventory slot and
   nothing on the body says the player has wings. (The sandbox's `boots:` flag was
   `moveMods !== 0`, so in the sandbox a winged player was drawn wearing **boots**.)
3. **The HUD shows `JET 5.0` and a full jet bar** while the jetpack is refused.

## Rulings

- **Coordinator (reversible): hover with no vertical input; UP rises and DOWN descends, both at
  `WINGS_FLY_SPEED`.** UP and DOWN held together cancel, so the player hovers. Flight is still
  constant: gravity stays off, jump and jetpack are still refused, and dropping the wings is
  still the only off switch.
- **UP is `W`, and jump is `SPACE`** (`client/src/input/localInput.ts`). They are separate
  bits (`button::UP` = 1<<2, `button::JUMP` = 1<<4). UP's only other reader is
  `jetpack::apply_thrust`, which does not run while flying, so the two do not collide.
- **The bots need no change.** A winged bot presses `JUMP|UP` when its target is above, and UP
  now means climb. With no target above it hovers instead of drifting up. The comment in
  `bots/mod.rs` is updated to say so.
- **Wing art: there is none** under `assets/` or `../sprite_packs`, so the wings are drawn in
  code, like the boots. They are a pale, feathered pair behind the body, wider than the body,
  so the player's outline changes (the boots' readability rule).
- **HUD: the jet readout says `JET —`, and the jet bar is empty and grey with `—` for its
  label, while wings are held.** Hiding it would make the bottom-left layout jump when wings
  are picked up. Showing it as unavailable follows the bar's existing refill-delay pattern: a
  dimmed colour for "not usable right now". Both are driven off the snapshot's wings bit,
  which is the same byte the mirror predicts with.

## Tests

- **Hover:** a winged player with no input holds its height, and the control is the same
  player without wings, which falls.
- **UP rises, DOWN descends,** at `WINGS_FLY_SPEED`; UP+DOWN hovers.
- **Unit:** `apply_flight` is pure and idempotent. Applying it twice matches applying it once,
  and the result depends only on the input, not on the incoming velocity.
- **Prediction:** the client mirror puts a winged player climbing on UP where the server does,
  and the control is that the unwinged run with the same UP does not rise.
- **Pixels (`wings-visible`):** the same body, photographed before and after `giveWings()`.
  The subject is a band beside the torso and the control is a band at the feet.
- **HUD:** `jetpackBar`/jet-readout text are unavailable while flying, and the control is
  the normal reading without wings.
