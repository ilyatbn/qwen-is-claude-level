# T21.32 — The round after the round (v1)

Milestone: M21 · Depends on: nothing · Size: medium (four separable fixes, one commit each)

Reported from play on the Docker build, 2026-09-15 (one human, three bots). A coordinator read the
code and the server log; every claim below was re-verified at the code before it was relied on.

## The owner's reports

1. **"Play again" does nothing.** Clicked on the Round over screen: the button turned to "Voted",
   disabled, and no round ever came. The owner had to exit to the title and rejoin.
2. **The same map every round.** Round 1 (07:53:04) and round 2 (08:00:19), same `room=1`, both
   logged `map generated seed=222892591914436108` — same traversable fraction, spawns, theme and
   ground texture.
3. **An empty room was not reaped.** "last human left; room is on the clock ttl_s=15.0" at
   07:59:51.10, no "reaped" line ever, and the rejoin at 08:00:09.47 (18.4 s later) landed back
   in room 1.
4. **The round timer reads 0:00 while "Waiting for players"**, on the first frame after joining.

## Verified causes

Measured with `owner-probe` (a scratch script driving the real client through the owner's
flow: title → quick match with three bots → round ends → wait past the window → late "Play
again" → "Exit to title"), on the unmodified tree at `1173c70`:

```
[27.58] results up; rooms=1
[53.96] past the window: {"phase":"ended","results":true,"count":""} rooms=1
[55.53] late vote: button=Voted
```

1. **Reproduced.** `return_to_lobby` sends nothing, so the client holds `ended` forever; the
   countdown renders `""` once the deadline passes; the late click still reads "Voted".
2. **Verified at the code.** `Room::seed` has two writers — `new_in_room` and `restart` — and
   `return_to_lobby` is not one; `generate_world_task` reads it.
3. **Not reproduced, three ways.** (a) `tests/reap.rs::a_room_whose_round_went_back_to_the_lobby_is_reaped_when_its_last_human_leaves`
   drives quick match → round → window → `ToLobby` → disconnect through the live reaper: green.
   (b) The browser probe's exit, `ROOM_EMPTY_TTL=3`: `last human left` 08:28:31.29, `reaped`
   08:28:35.57. (c) Neither bots nor seats count: `RoomEntry.humans` is keyed on socket ids.
   The one writer that clears `empty_since` is `registry.rs::attach`, and the owner's log has no
   line that would show it firing, because there was none. The report's numbers leave 1.4 s
   between the worst-case reap (15 s TTL + 2 s sweep = 17.0 s) and the rejoin (18.4 s), so an
   `attach` to room 1 inside that window is the only explanation the code allows — and no client
   path found makes one without a click. **Fix: the missing log line** (`a human arrived; room is
   off the clock`) so the next occurrence names its socket; the test stays as the regression.
   **Put to the coordinator:** the raw `room=1` / `socket connected` lines between 07:59:51 and
   08:00:19 would settle it.
4. **Reproduced, and wider than the first frame.** For the whole warmup:
   `{"phase":"lobby","timer":"0:00"}` ×5 samples, then `{"phase":"playing","timer":"0:19"}`. The
   Warmup `round_state` arrives while `MenuScene` still owns the socket and `GameScene.create()` is
   awaiting its asset loader, so no handler is attached and it is dropped; `round_state` is not in
   `connection.ts::LATCHED_EVENTS`. `welcome` said `lobby`, and nothing corrects it until the
   first `Playing` rebroadcast. The `0:00` is `JoinInfo.time_left = INFINITY`, which serde writes
   as `null`, read as `Number(null ?? 0)`.

## Rulings (builder, reversible — put to the coordinator)

- **R1. Where a client goes when its room returns to the lobby: the title, with its socket
  closed.** Spec-following, not a choice: `docs/72` §C3 (an amendment, so it overrides `docs/41`
  §3's "quit/menu screen") says "If it does not [carry], the client returns to the title." One
  `GameScene::exitToTitle`, shared with "Exit to title". Not "stay seated in the lobby":
  `GameScene` cannot hand a live socket back to `MenuScene`, and building that is its own task.
  **Put to the coordinator** as a possible follow-up: returning to the menu would save a click.
- **R2. The vote is acknowledged.** A vote the server will not count must not show "Voted", and
  the client cannot know that from its own clock — the server closes the window on the server's.
  So `vote_restart` gets a reply, `vote_counted { counted }`, and the button reads "Voted" only on
  `counted: true`. Until the reply it reads "Voting…"; on `counted: false` it reads "Vote closed".
- **R3. The countdown wording.** Before this client has a counted vote: "Vote closes in N s".
  After: "New round in N s". A bare "New round in N s" for a player who has not voted would
  promise a round that silence does not produce (`restart_wins` needs at least one vote).
- **R4. When the seed advances: on the return to the lobby**, with `RoundController`'s
  `next_seed` derivation shared with `restart`. So the first match from a fresh room is still
  built on the room's own seed, every later lobby start is on a fresh one, and the seed the lobby
  reports in `welcome`/`round_state` is the one its next map is built on (`procTextures.ts` seeds
  the ground from that value, so a seed advanced *at* start would paint the old ground). With
  `FIXED_SEED` the whole sequence is a function of it: round one on it exactly, and later rounds
  derived — the same rule `restart` already follows.
- **R5. The lobby timer is blank.** `docs/74` §E1: "The map, **the round timer**, the weather
  schedule and the item spawns come into existence at the moment the match starts." A room in
  `Lobby` has no round timer, so the top-right timer draws nothing rather than `0:00`.
