# T21.17 — Shader plumbing, and fog as the first effect (v9)

Milestone: M21 · Depends on: **T21.16** · Size: **large — the first shader in the
project pays for the setup**

Asked for by the coordinator: make the game *"prettier … more dynamic and animated"*.
Fog is first because it is the worst-looking thing on screen: **one flat grey
rectangle at 80 % opacity**, no movement, no depth, identical everywhere.

## The setup this task pays for

There are **no shaders in this project today** — no pipelines, no GLSL, nothing.
So this task builds the road as well as the first mile:

- a place to register pipelines on the game config;
- a decision on where shader source lives. **Try inline template literals first**:
  the build tool has no `glsl` handling (checked), and inlining sidesteps the
  question entirely. If that proves unreadable, add the loader deliberately and
  say why.
- the High Quality switch from T21.16 actually selecting between the shader path
  and today's path.

## Deliverable

Fog that drifts, varies in thickness across the screen, and thins near a light —
under High Quality. With it off, **exactly today's flat veil**, unchanged.

## Watch for

- **Fog is not only a picture.** `fogVeilAlpha` feeds how far a player can see,
  and the flashlight multiplies it. The shader replaces the *veil*, not the
  seeing rule. If the shader version changes what a player can see, it is wrong.
- **It interacts with the light/darkness layer**, which is the one subsystem in
  this codebase with a written history of GPU compositing going wrong — read
  `lightmap.ts`'s header before touching it. It uses a 2D canvas *on purpose*
  after a `RenderTexture` version was measured producing the wrong radius.
- **Three browser checks sample fog brightness** — `fog-visible`, `night-combat`,
  `weather-visible`. They assert today's flat veil. Each needs re-measuring, and
  a threshold that moves must be re-derived, not nudged until green.
- **Both paths must keep working.** Half this game's players may have the toggle
  off; a shader path that quietly becomes the only path is a regression for them.

## Tests

- With High Quality **off**, the fog frame is unchanged from today. Pixel-compared
  against the current behaviour — this is the assertion that protects everyone
  who cannot run shaders.
- With it **on**, the fog region differs from the off version. Control region
  outside the fog, control frame with fog inactive.
- The fog **animates**: two frames a moment apart differ under High Quality and do
  not with it off. A still shader is a wasted one.
- What a player can *see* is identical in both modes — the simulation half is
  untouched. Assert the seeing rule, not the picture.
- The existing fog checks still pass, with any re-derived threshold explained.
