# T21.23 — Audit the browser checks for waits in the wrong clock (v9)

Milestone: M21 · Depends on: nothing · Size: small-to-medium (an audit, then
however many fixes it finds)

## Where this came from

T21.22b, hunting a different bug, measured this while pacing shots against
`BAZOOKA_COOLDOWN`:

> **one gap advanced the wall clock 1113 ms while `serverRoundTime` advanced
> 400 ms.**

The check slept `BAZOOKA_COOLDOWN * 1000 + 120` — 120 ms of headroom on 900 — and
the next shot was refused, because **the cooldown is spent in `world.round_time`,
not in wall-clock time.** Under load the two diverge by more than the headroom.
It cost 3 reds in 30 runs and reported `fired 4 but only 3 rockets left the
muzzle`: a true sentence about a *refusal*, which says nothing about the muzzle.

This is a near neighbour of a rule we already have — *a wait hardcoded against a
tunable is a test that expires* — but it is a distinct failure. That rule is
about the **number** drifting. This is about the **clock**: the number is right,
the units are right, and it is still wrong, because the simulation is not
obliged to advance in step with the wall.

**It gets worse as the machine gets busier**, which means it fails in the full
gate and passes when the check is run alone — the exact signature that gets
blamed on flakiness and then ignored.

## The work

1. **Find every wait paced against a simulation tunable.** Start from
   `grep -rn "COOLDOWN\|INTERVAL\|_TIME\|DELAY" scripts/checks/ scripts/e2e-*.mjs`
   and read each hit: the question is whether what it waits *for* is counted by
   the server's clock or by the browser's.
2. For each one that is in the wrong clock, wait on the **server's** clock.
   T21.22b's `e2e-two-clients.mjs` has the shape that worked: wait for the action
   to be **accepted**, anchor there, then wait out the cooldown in
   `serverRoundTime`. Anchoring *before* the action is optimistic and reds on its
   own.
3. A wait that can never be satisfied must fail loudly rather than hang — the
   loop that hung this box for eighteen hours counted successes, so it could
   never trip its own guard. Bound by attempts.

## Watch for

- **Not every wall-clock wait is wrong.** Waiting for a render, an animation, or
  a DOM transition is correctly wall-clock. Only waits against something the
  simulation counts are in scope, and changing the others is churn.
- **A check that is already green proves nothing here**, because this only bites
  under load. The evidence that a fix works is the measurement — the two clocks'
  advance across the wait — not another green run on an idle box.
- Report the tally: how many waits were audited, how many were in the wrong
  clock. *"Some were fixed"* is not a finding.

## Done when

```sh
./scripts/check.sh
```

and the journal entry states both numbers.
