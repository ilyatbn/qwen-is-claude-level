# T21.15 — The terrain texture never varies (v9)

Milestone: M21 · Depends on: nothing · Size: **small change, wide blast radius** —
every generated mask's *appearance* moves, and the golden tests are about the mask

**Reported from play by the coordinator**: *"check if theres an issue in randomizing
the map texture. It seems like its always the same."*

It is always the same, and this is not a perception problem.

## What was found

`render/procTextures.ts` hands `makeNoiseTile` a **hardcoded seed** at all three
call sites:

```ts
makeFillTexture(size, theme) → makeNoiseTile(size, theme.fill, theme.spread.fill, 7)
makeEdgeTexture(size, theme) → makeNoiseTile(size, theme.edge, theme.spread.edge, 23)
makeBackTexture(size, theme) → makeNoiseTile(size, theme.back, theme.spread.back, 41)
```

`makeNoiseTile(size, base, spread, seed)` takes a seed and uses it properly —
`wrappedNoise(x, y, freq, size, seed)` and `(…, seed + 17)`. **Nothing ever passes
the map's.** So the rock body, the upward rim and the cave-back are byte-identical
on every seed, in every round, forever.

The only thing that varies between maps is which of **three** palettes is drawn:
`map/meta.rs::theme_for` is `substream(requested_seed, "theme") % THEME_COUNT`, and
`THEME_COUNT` is 3 (`client/src/render/themes-math.ts::THEMES` has three entries to
match). So a player sees three terrain looks, ever, and within each the noise is one
image repeated.

**The seed is already in scope at the call site.** `render/worldView.ts` builds the
three textures a line below `core`, whose `core.meta.seed` is the map's. Nothing is
missing but the argument.

## Watch for

- **`PreviewScene` calls all three with no arguments at all**
  (`makeFillTexture()`), so it gets theme 0 and the same literals. Decide whether a
  preview should match the round it previews and say which at the code — a preview
  that looks nothing like the map is its own small lie.
- **The golden tests are about the mask, not the picture.**
  `golden.rs::generated_masks_match_the_golden_table` pins terrain *geometry*; this
  changes only client-side pixels, so it must **not** move. If it does, something
  other than the texture changed and that is the finding.
- **`docs/51` §5 and `themes-math.ts` both call these the procedural fallback** and
  the shipping path. The `theme.json` route in `assets/manifest.json` (`themes: []`)
  is declared and unused. Seeding the fallback does not close that door; say at the
  code which one is intended to win when both exist.
- **A seeded texture is still a cache key.** `terrain.ts` keys chunk textures by a
  map generation counter precisely because Phaser's texture manager is global and a
  reused key keeps old pixels. Three tiles that now differ per seed must not collide
  across a regenerate — that renderer's header records what the symptom looks like.
- **Do not reach for the round seed inside `procTextures.ts`.** It is Phaser-free
  and pure (`docs/70` §A8); the seed is the caller's to pass.

## Tests

- Two different seeds produce **different** fill/edge/back tiles — compared per
  pixel, not by a histogram. **Control**: the *same* seed twice produces identical
  tiles, or "different" is satisfied by a generator that is merely nondeterministic.
- A seed change moves the tile but **not** the palette: the mean colour stays within
  the theme's `spread`, so seeding cannot silently become re-tinting.
- The tile is still **seamless** at the new seed — the property `makeNoiseTile`'s
  torus sampling exists for. Assert wrap continuity on a seeded tile, across several
  seeds; a seam is invisible in a unit test and glaring at every 256 px boundary.
- The golden mask table is **unchanged**, asserted, because this task must not move
  terrain geometry.
- **Rendered pixels** (`docs/72` §C2): two maps on different seeds, same theme, differ
  in a terrain region — with a control region of UI that must not move between them.
  Two seeds that happen to roll different *themes* would pass that without the tiles
  changing at all, so pin the theme and vary only the seed.
