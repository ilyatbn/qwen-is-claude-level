# T21.14 — The gun platform: what the review found (v9)

Milestone: M21 · Depends on: **T21.11A/B/C** (all landed) · Size: ~250 lines

A harsh review of `2d5c16a`, `507bfe6` and `a3eb2cc` found defects in work that was
already committed and gate-green. **Every finding below was re-verified against the
committed artifact before being written down.** Two are player-visible bugs; the rest
are guards that cannot fail.

## The two that are bugs

### 1. The occupied lamp never lights in a real match

`render/platforms.ts::PlatformLayer::setOccupied` has exactly **one** non-test caller:
`SandboxScene::mountNearestPlatform`, a debug hook added for the pixel check.
`GameScene` calls `world.platforms.build` and `world.platforms.count` and **never calls
`setOccupied`**.

So in any networked match a player mounts, loses movement, the bag and healing — and the
cyan lamp, which T21.11B's own journal entry called *"the only signal separating 'you're
mounted' from 'the game has frozen'"*, never lights for anyone.

**And `scripts/checks/platforms.mjs` cannot see it**: it drives the lamp through
`mountNearestPlatform`, which calls `setOccupied` directly. The check proves the sandbox
hook and the layer method, never the production path. Ask what that assertion reports if
the wiring had never happened — exactly what it reports now.

The data is already on the wire: `MOVE_MOD_MOUNTED` rides `move_mod_bits` and the codec
carries it. Nothing client-side turns it into a lit lamp.

### 2. Knocked off a platform, you stay mounted — and keep firing it

`world/mount.rs::step` opens with `if let Some(id) = st.mounted { … return }` and **never
consults `under` or `grounded` while mounted**. Nothing else clears `mount.mounted` on
displacement.

`weapons/explode.rs` applies an impulse to players, and a mounted player has no exemption
— T21.11B's `a_mounted_player_takes_damage_normally` establishes that, but it uses
*poison*, which applies no impulse, so knockback on a mounted player is exercised nowhere.

Failure: a rocket throws a mounted player clear of the platform. They are immobile
(`MoveMods::mounted` zeroes the direction), inventory-locked — and `World::fire` still
routes to `fire_platform`, which spawns rounds at the platform's own origin. **They fire
the turret from behind cover, from somewhere else.** Deliberate self-knockback makes it
repeatable.

## The guards that cannot fail

3. **`gun_platforms_draw_from_their_own_sub_stream` is unfalsifiable.** `build_meta` now
   passes `choose_gun_platforms` a candidate list already cleared of pads by
   `GUN_PLATFORM_PAD_CLEARANCE`, so platforms can never equal pads whatever stream is
   named. **Proved by mutation**: renaming the stream to `"pads"` leaves it green. The
   clearance filter — added to fix the seed-4242 collision — silently hollowed out the
   test written to detect that collision's cause.
4. **A citation with no referent.** `build_meta` cites
   `platforms_do_not_move_the_pads_or_the_spawns`; `git grep` finds exactly one
   occurrence, the comment itself. The property it names is asserted nowhere.
5. **`MountState::progress` has no caller** outside its own unit test, and its doc comment
   claims it is "for the client's indicator, the way `TeleportState`'s charge byte is" —
   but it is not on the wire and nothing reads it. A player stands still for a second with
   no feedback at all; the pad it was modelled on has a charge arc for exactly this reason.
6. **Hash sentinel collision.** `state_hash` folds `mount.mounted.unwrap_or(255)` while
   `mount::WIRE_MOUNTED == 255`. No live divergence — server-side `mounted` is never 255 —
   but "unmounted" and "mounted per the wire" are indistinguishable in the one place built
   to detect divergence.
7. **`the_carried_table_exemptions_all_exist` asserts the wrong property.** It checks each
   `NOT_CARRIED` member `is_ballistic` — the property that made it need exempting, not the
   one that justifies it. Give the platform gun an `ItemDef` and it becomes carried,
   untabled, and still green.

## Do not

- **Do not weaken any threshold.** Every fix here is a control restored or a caller wired,
  not a bar lowered.
- **Do not delete `setOccupied` to make finding 1 go away.** The lamp is the feature.

## Tests

- The lamp lights **through the production path**: a networked player mounts, and
  `GameScene` lights the platform they are on. Rendered pixels (`docs/72` §C2) with a
  control frame, and **not** driven by the sandbox hook — the mutation to beat is deleting
  the `setOccupied` call from `GameScene`.
- A mounted player displaced by a blast dismounts. **Control**: one that is not displaced
  stays mounted. And a second: after displacement, firing no longer spawns platform rounds.
- A real guard for the sub-stream property: assert pads and spawns are **unchanged** by
  platforms existing, or delete the claim. Whatever is written must go red when the stream
  name is shared — verify by mutation, not by reasoning.
- The dangling citation either names a real test or goes.
- `progress` reaches a player or is deleted. If it reaches them, assert it on pixels.
- A hashed sentinel that cannot collide with a real id, asserted.
- `NOT_CARRIED`'s guard asserts *not carried*.
