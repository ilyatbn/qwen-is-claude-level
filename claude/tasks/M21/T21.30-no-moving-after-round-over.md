# T21.30 — Nobody moves once the round is over (v9)

Milestone: M21 · Depends on: nothing · Size: small

Reported from play, 2026-09-15: *"i can still move my character after the 'round over' is displayed."*

## What is true today

- `game-core/src/world/mod.rs::World::step` runs **step 2, `apply_inputs(now, dt)`, in every phase**.
  Only pads (3b), hazards (5) and items (6) are gated on `playing`. So in `Ended` a player walks,
  jumps and jetpacks for the 20 s `ENDED_SECONDS` window while the results screen is up.
- The client has no phase gate on input or prediction: the only `'ended'`-aware line in
  `GameScene.ts` hides the join-code banner.
- **Established (builder, 2026-09-15): yes, all of them.** `World::fire`, `use_item`, `use_heal`,
  `drop_item` and `select_slot` checked only alive and mounted (`World::inventory_actor`), never the
  phase, and the server's `Command::Fire`/`UseItem`/`DropItem` handlers call them in every phase.
  Measured at HEAD by `world::round_over_input::nothing_fires_digs_or_is_used_once_the_round_is_over`:
  *"fire (and the dig it makes) still worked after the round ended"*. Digging is a shot — every
  weapon carves.
- **And the mid-air half was already broken the other way:** `GameScene` stops *sending* input once
  the results screen is up, and `apply_inputs` integrates only players who sent one, so a player
  airborne at the end hung in the sky (*"still at y 398.8 (started 398.8), grounded false"*).
- **The browser bug, at HEAD:** `round-over-frozen` — control 79.1 px in `playing`; after "Round
  over" D moved the rendered player 130.9 px and A −156.7 px. The client stopped sending but kept
  predicting.

## Ruling (coordinator, reversible)

**In `Ended`, input does nothing: no movement, no firing, no digging, no item use.** Bodies still
settle under gravity (a player mid-air when the round ends lands; nobody hangs frozen in the sky).
`Warmup` is unchanged.

## Deliverable

- **One derived rule, read by both sides** — e.g. a `RoundPhase::accepts_input()` in `game-core`
  that `apply_inputs` consults and the wasm prediction path shares. Not a flag the server sets and
  the client keeps its own copy of (CLAUDE.md: derive, do not add a fourth flag; share the guard).
- The client stops predicting input in `Ended`, or the local body will walk on screen and snap back.

## Tests

- In `Ended`, held input moves nobody, fires nothing, digs nothing — with the **control** that the
  same inputs in `Playing` do all three.
- A player airborne at the moment the round ends still lands.
- Client prediction agrees with the server for a player holding a direction across the
  `Playing → Ended` transition.
- A browser check: after "Round over", holding a direction for a second leaves the local player's
  rendered position unchanged, with a control that the same hold moved them during `Playing`.

## Done when

`cargo test -p game-core`, the client tests for the prediction change, and the browser check green
and falsified; `./scripts/check.sh --changed` run with its wall time recorded.

## Outcome (builder, 2026-09-15)

- **One rule:** `world/mod.rs::RoundPhase::accepts_input` (false only in `Ended`). Read by
  `World::apply_inputs` (queued input dropped; every alive player integrated on a neutral input, so
  bodies settle and nobody hangs in the air), `World::inventory_actor` (use, heal, battery, drop,
  select, drag, grenade throw) and the top of `World::fire` (its platform branch bypasses the actor),
  refusing with a new `UseError::RoundOver`. The wasm mirror stores the announced phase
  (`GameCore::set_phase`, from `round_state` and `welcome` in `GameScene`) and zeroes the buttons in
  `apply_input` through the same function.
- **Tests:** `world::round_over_input` (held input, fire+dig/use/heal/drop/select, airborne lands —
  each with a `Playing` control) and `game-wasm::prediction_agrees_with_the_server_across_the_round_ending`
  (the mirror not told the phase is the control and must disagree). Browser: `round-over-frozen`.
- **Falsified at each live site:** neutral block off → held-input and airborne red; actor+fire gates off
  → "fire (and the dig it makes) still worked"; wasm zeroing off → mirror 1106.8 vs server 1075.2;
  `GameScene`'s two `setPhase` calls removed → browser check red (±11.5 px after "Round over").
- **Decision (reversible, not in the ruling):** a landing in `Ended` still costs fall damage — damage
  in `Ended` was never gated (projectiles in flight already hurt), and adding a gate is a separate call.
- `REPLAY_VERSION` 8 is shared with T21.29, named at the constant.
