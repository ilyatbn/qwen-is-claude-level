# T21.33 — The Canvas renderer: what the owner actually sees

Milestone: M21 · Depends on: T21.20 · Size: ~250 lines over `parallax.ts`, one check, a flag

## Reported

**The owner's browser renders with Phaser's Canvas renderer, not WebGL.** Headed Chrome under
WSLg, launched by `scripts/play.mjs` without GL flags: the game canvas returns a `2d` context and
`getContext('webgl')` / `('webgl2')` are false. Every browser check runs WebGL (swiftshader), so
nothing in this repo had ever looked at the Canvas picture. A player whose browser lacks WebGL
gets it too.

1. **A solid dark navy bar across the middle of the background**, full width, ~220 screen px tall,
   its top edge exactly where the far mountains stop.
2. **A thin dark vertical line in the sky**, top-left (x≈58 of 1548 px), top edge down to y≈380,
   also at another camera position (x≈86).
3. Audit every other WebGL-only drawing call a Canvas player hits.
4. A way to test the Canvas renderer, and a pixel check on the bar region.

## Rulings (builder, 2026-09-15)

- **R1, the foot.** `fillGradientStyle` is WebGL-only. Phaser's Canvas Graphics renderer *skips* the
  gradient command, so the `fillRect` after it paints with whatever `fillStyle` the context last
  held: solid at alpha 1, in the clear colour `#0b1020`. That is the navy (90 world px × zoom 2 ×
  1548/1280 = 218). The foot is now a **1×N canvas texture** holding the tint and an alpha ramp,
  re-painted only when the tint moves, drawn as an `Image`. **One path for both renderers**, so
  there is no second picture to drift.
- **R2, found by looking: the ridges are white on Canvas.** They are baked white and coloured with
  `setTint`, and Canvas's `batchSprite` has no tint at all. On Canvas the ridge texture is
  re-coloured in place (`source-in`, which keeps the silhouette's alpha exactly) when the tint
  moves, and the TileSprite is marked dirty so it rebuilds its pattern. WebGL keeps `setTint`: a
  megapixel re-upload several times a second is what the file header protects against.
- **R3, the line.** `ridgeTexture` closed its silhouette at `x = w - 1`, so the texture's last
  column was empty: a 1-texel transparent seam at every wrap of every ridge, running from the
  crest to the base. On WebGL it is sky through a sky-hazed ridge and hard to see; on Canvas it is
  sky through a *white* ridge. Now closed at `x = w` with `profile[0]`, which the wrapped noise
  makes the same height.
- **R4, High Quality with no WebGL.** Shaders cannot run on Canvas and every shader site already
  falls back through `hasWebGL`. The options panel therefore shows the toggle **disabled, reading
  Off**, with the hint "Needs WebGL, which this browser is not using." The stored preference is not
  overwritten: the same player on a WebGL browser keeps their choice.
- **R5, the harness.** `?renderer=canvas` forces `Phaser.CANVAS`, dev surface only (`main.ts`).

## Resolution (builder, 2026-09-15)

**Seen before fixing.** `?sandbox=1&seed=4242&renderer=canvas`, carved open around the ridge base:
a solid navy bar exactly the foot's rows (180 px at 1280 wide = 218 at 1548) and **white**
mountains. The same frame on WebGL: tinted ridges, a fading foot. `canvas-renderer` was written
first and went red on the bar: foot bottom 193.0 vs top 194.5 against the hidden frame.

**Fixed** in `render/parallax.ts`: R1 (`paintFoot`, an Image), R2 (`recolourRidge`, then
`setTexture` again — `dirty = true` alone was measured to redraw the old white pattern, 2955 of
2955 px), R3 (`ridgeTexture` closes at `w`). **A fourth defect, found by looking at the first
fixed frame:** one full screen row of sky between ridge and foot on Canvas, because the
TileSprite's internal canvas truncates 172.8 → 172. The strip now carries one opaque overlap texel
drawn one texel above the base; `skirt.y` still reports the fade's start, so `living-sky`'s base
assertion is unchanged. R4 in `ui/optionsPanel.ts::qualityRow`, called by `GameScene`.

**Green:** `canvas-renderer` — foot top 88.6 → bottom 8.2, sky below 0.0, drift 1.0; rows across
the base all 92.9–97.4; 3546 ridge px all the near tint, 0 white; wrap column vs neighbours 0.
`living-sky` green on WebGL. Vitest 919/919.

**Falsified at the live site, each red for its own reason:** F1 old Graphics
`fillGradientStyle` foot (hidden with the band, as the original was) → "solid bar", bottom 179.3
vs top 194.5. F2 recolour skipped → 2364 of 3546 ridge px white. F3 `x < w` / `lineTo(w - 1)` →
wrap column x 1017 differs by 32.3. F4 overlap texel 0 → row 189 reads 0.

**Not covered.** The owner's own frame was not reproduced: the vertical line is attributed to the
wrap seam by mechanism and by F3, not by re-photographing their camera position. The disabled
High Quality row is unit-tested (`qualityRow`) but no browser check opens the panel on Canvas.

### Audit — WebGL-only drawing a Canvas player hits

| Site | Call | Canvas result | Ruling |
|---|---|---|---|
| `parallax.ts` foot | `fillGradientStyle` | solid bar in the context's last colour | **fixed** (R1) |
| `parallax.ts` ridges | `TileSprite.setTint` | untinted white | **fixed** (R2) |
| `parallax.ts` clouds; `weather.ts` fog; `ordnance.ts` beams/flames/blasts; `ordnanceFx.ts` smoke | `add.shader` | never built: each is gated by `hasWebGL`, flat fallbacks draw (clouds: none, by T21.18's design) | harmless; menu says so (R4) |
| `playerView.ts` skin body | `Sprite.setTint` | **the one tinted skin (`0xff8a7a` in `assets/skins.json`) draws untinted** | **open** — not harmless; needs a baked tinted atlas copy on Canvas. Proposed as its own task |
| `sky.ts` sun glow | `Image.setTint` | glow stays white instead of warming toward the horizon; the disc itself warms (`setFillStyle` works on Canvas) | harmless, cosmetic |
| `sky.ts` glows, `ordnance.ts` gfx, `itemSprites.ts` chutes, `weather.ts` rain/fire | `BlendModes.ADD` | `lighter` — supported | harmless |
| `lightmap.ts` | `BlendModes.MULTIPLY` | `multiply` — supported in Chrome (`CanvasFeatures.supportNewBlendModes`) | harmless |
| `lightmap.ts`, `sky.ts` glow | `setFilter(LINEAR)` | honoured: Canvas `batchSprite` sets smoothing from `frame.source.scaleMode` | harmless |
