## Coordinator rulings
- Scene 1's caption: **`TRUST NO ONE`** (ties back to the intro's virus).
- Captions for scenes 1–4: typed letter by letter, **top-left**, in the intro's terminal style (`> ` prompt, blinking
  cursor; match `PLANET DROXILON 7` in `promo/intro/`), the owner's words verbatim. The final scene: **large, centred**,
  typed, held ~1 s, then erased with a glitch/scramble wipe, then the next line.
- Bot scenes use **hill** (small scale) or the scene's named shape — never Random (owner rule). The final scene has no
  fighting bots; "random map" there means any classic-look map at moonlit night — pick the best-looking.
- Every clip: 1920×1080, 60 fps, no film grain, no HUD/minimap/names/crosshair (as `promo/capture-match.mjs` hides
  them), full quality (CRF ~18; size doesn't matter). Real game, GPU (headed Chrome, `GALLIUM_DRIVER=d3d12`).

## Build first (dev/promo-only, default off, never in a real round)
Audit what exists (`crates/game-server/src/config.rs` DEV_* vars: `DEV_LOADOUT`, `DEV_START_HEALTH`,
`DEV_BOT_FRENZY`, `DEV_MAP_SHAPE`, `DEV_ROUND_CLOCK`, `WEATHER`, …; the lobby's gravity; `__game` debug hooks) and add
only what's missing, each with a config test:
1. **Every weapon** for every player at spawn and respawn (all weapon kinds, ammo, full battery) — `DEV_LOADOUT` may not
   hold all; add `DEV_ALL_WEAPONS`.
2. **Health pool 1000** (max and start, every respawn) — `DEV_MAX_HEALTH=1000`; the HUD isn't shown so bars needn't fit.
3. **Small map** — the scale (env if missing), **look forced** (`DEV_WORLD_LOOK=volcanic`), **gravity forced**
   (`DEV_GRAVITY=space`) for a watched room.
4. **Disasters on cue**: start a meteor shower at a chosen round time (WEATHER/effect scheduler forcing), and a
   **camera shake while it falls** (client: the rig's trauma on meteor impacts — if there is none, add a promo-visible
   shake on impacts near the camera; a real-game feel improvement is fine if it stays subtle by default).
5. **Space**: the black hole open (DEV_ROUND_CLOCK to its window), a bot near it, and **one bot pulled in** — steer one
   bot there (a debug command like `debug_place` for a bot id, server-side, dev only) so the capture is reliable.
   "Shooting upside down from a meteor": a bot standing on the underside of an asteroid firing.
6. **All fauna on one map** (final scene): a dev override so classic birds/animals, the volcanic tripods/octopi and
   fireflies all appear together, several of each, wandering in frame.
7. **Weapon variety** (scene 1): bots each holding a different weapon and switching — if bots converge on one weapon,
   a promo knob that assigns/rotates each bot's preferred weapon.
8. A **director** per scene in the capture script (camera framing the action; scene 4's zoom onto a bot entering a
   teleport and vanishing, then fade to black).
