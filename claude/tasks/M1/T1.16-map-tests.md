## Deliverable

**1. PNG dump** (`dump.rs`, feature-gated):
```rust
pub fn dump_map(map: &Map, path: &Path) -> std::io::Result<()>;
pub fn dump_surface(map: &Map, report: &TraversalReport, path: &Path) -> std::io::Result<()>;
```
- `dump_map`: solid pixels dark grey, air light blue, bedrock and walls darker,
  spawn points as green crosses, buried slots as yellow dots.
- `dump_surface`: the surface point set in white, the largest traversable component
  in green, everything else in red. This is the direct visual answer to "why did
  validation reject this map?".

A test writes one map per scale, plus 6 medium maps from fixed seeds, into
`target/mapdump/`.

**2. Golden hashes** (`golden.rs`):
A committed table of `(seed, scale) → blake3(mask)` for 12 fixed pairs, read from
`golden_hashes.txt`. The test regenerates and compares.

**3. The sweep** (`map_sweep.rs`), `#[ignore]`d by default because it is slow:
1000 seeds across the three scales, asserting for every one:
- `report.passed`
- `traversable_fraction >= MIN_TRAVERSABLE_FRACTION`
- `spawn_points.len() >= SPAWN_COUNT_MIN`
- `attempts <= 3`
- `used_safe_preset == false`
- borders hold
- `coarse.verify(&mask)` is `Ok`

On failure it prints the seed, so the case is immediately reproducible.

## Notes

**Do not put PNG writing behind the default features.** `game-core` must stay
dependency-light for the WASM build; the `png` crate has no business in the browser
bundle.

The golden table is a **regression detector, not a specification**. When a
generator change is intentional, regenerate the table and say so explicitly in your
report — the whole value is that an *unintentional* change cannot pass silently.
Provide a `GOLDEN_UPDATE=1` env check in the test that rewrites the file, so
regenerating is a deliberate one-liner rather than a manual edit.

The sweep is `#[ignore]`d so `cargo test` stays fast; `check.sh` does not run it.
It is run explicitly at the end of M1 and on demand afterwards.

If the sweep fails on tuning grounds — say `attempts <= 3` is violated for 2 % of
seeds — **report it rather than loosening the assertion**. That is the signal the
generation parameters in `docs/02-constants.md` need adjusting, and adjusting them
is a decision for the user, not a workaround.

## Tests

The three deliverables above are themselves the tests. Additionally:

- `dump_map` writes a file of the expected dimensions that opens as a valid PNG.
- The golden test fails when a single pixel of the generator's output is perturbed
  (verify by temporarily bumping a constant, then reverting).
- `GOLDEN_UPDATE=1` rewrites the table and the test then passes.

## Done when

```sh
cargo test -p game-core --features dump-png --release
cargo test -p game-core --release -- --ignored map_sweep
```
Both pass. Then open `target/mapdump/` and **look at the maps**. Report whether
they read as Worms-style levels — organic silhouette, caves, floating islands,
usable ledges — or describe what looks wrong. This human judgement is the real
acceptance criterion for M1, and no assertion replaces it.
