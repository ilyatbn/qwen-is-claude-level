## Deliverable

```rust
/// Stamp up to `params.bridge_count` solid spans between nearby island centres.
/// `islands` are the centres returned by `add_blobs`. Returns the spans actually built.
pub fn add_bridges(mask: &mut Mask, seed: u64, params: &GenParams,
                   islands: &[Point]) -> Vec<(Point, Point)>;
```

## Notes

- `substream(seed, "bridges")`.
- Sort island centres by `x` (ties by `y`) before pairing, so the result does not
  depend on the order `add_blobs` happened to produce.
- For each island in order, find the nearest **unbridged** partner whose horizontal
  distance is in `BRIDGE_MIN_SPAN..=BRIDGE_MAX_SPAN`. Stop after `bridge_count`.
- Endpoint y is the island's **top surface**: from the centre, walk up until the
  pixel above is air; if the centre is already air, skip the pair.
- The span sags: `y(t) = lerp(y0, y1, t) + BRIDGE_SAG * 4 * t * (1 - t)`.
- Stamp with the shared `stamp_circle(.., r = BRIDGE_THICKNESS / 2, solid = true)`
  every 3 px along the path. Never write a second rasteriser.
- `force_borders` at the end.

## Tests

- Determinism: same seed, same mask hash, 20 times.
- `add_bridges` never removes solid pixels.
- With `bridge_count = 0`, or fewer than two islands, the mask is unchanged and the
  returned vec is empty.
- Every returned span has horizontal length within `BRIDGE_MIN_SPAN..=BRIDGE_MAX_SPAN`.
- No island appears as an endpoint of two bridges built in the same call.
- After building a bridge between two islands on an otherwise empty mask, a
  4-connected flood fill from one island reaches the other.
- Borders still hold.
