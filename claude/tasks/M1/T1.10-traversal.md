## Deliverable

This is the task that makes "the map is never impossible to move on" a testable
property rather than a hope.

```rust
pub struct TraversalReport {
    pub total_points: usize,
    pub largest_component: Vec<usize>,     // indices into the surface point list
    pub traversable_fraction: f32,
    pub passed: bool,
}

pub fn analyse(mask: &Mask, surface: &[Point]) -> TraversalReport;

// Edge predicates, each independently testable:
fn can_walk(mask: &Mask, a: Point, b: Point) -> bool;
fn can_drop(mask: &Mask, a: Point, b: Point) -> bool;
fn can_jump(mask: &Mask, a: Point, b: Point) -> bool;
fn can_jetpack(mask: &Mask, a: Point, b: Point) -> bool;
```

Edge rules (from the doc's table):

| Move | Condition |
|---|---|
| Walk | `|ax−bx| <= SURFACE_SAMPLE_STEP`, `|ay−by| <= STEP_UP`, player box sweep clear |
| Drop | `|ax−bx| <= SURFACE_SAMPLE_STEP`, `by > ay`, vertical corridor clear |
| Jump | `b` inside the ballistic envelope from `a`, arc sampled every 8 px and clear |
| Jetpack | `dist(a,b) <= JETPACK_MAX_SPEED * JETPACK_MAX_FUEL * 0.6`, straight line clear |

`passed` is `traversable_fraction >= MIN_TRAVERSABLE_FRACTION` **and** the largest
component contains at least `SPAWN_COUNT_MIN` points separated by
`SPAWN_MIN_SEPARATION`.

## Notes

**Be conservative.** A false negative just means one extra regeneration attempt; a
false positive means a player is stranded for four minutes. When a check is
borderline, say no.

**Do not build a dense all-pairs graph.** With a few thousand surface points that
is millions of edge tests and it will dominate generation time. Bucket the points
into a spatial grid (cell size = the jetpack range) and only test pairs within
neighbouring buckets. Edges are undirected for component-finding purposes even
though `drop` is physically one-way — a stranded ledge you can only fall from is
still a connectivity problem worth flagging, and treating it as connected would
hide it.

Union-find over the edges is the simplest way to get components, and it avoids
materialising an adjacency list at all.

The jump envelope: max height `JUMP_VELOCITY²/(2·GRAVITY)` ≈ 66 px, max horizontal
distance at that speed ≈ `WALK_SPEED · 2·JUMP_VELOCITY/GRAVITY` ≈ 92 px. Sample the
actual parabola between `a` and `b` every 8 px and test the player box at each
sample — do not just check the endpoints against a bounding box.

The 0.6 factor on jetpack range is deliberate slack for the fact that flight is not
a straight line at full speed.

## Tests

Hand-built masks first, real maps second:

- Two flat platforms 20 px apart horizontally, same height: connected by walk.
- Two platforms 300 px apart with nothing between: **not** connected.
- Two platforms 60 px apart with a 40 px height difference: connected by jump, and
  assert specifically that `can_jump` is what connected them.
- Two platforms 200 px apart at the same height: connected by jetpack only.
- A platform under a solid ceiling with no route out: its points form their own
  component, and `passed` is false.
- A wall between two platforms blocks the jump arc even though the endpoints are
  within range — this is the test that proves the arc is actually sampled.
- `analyse` on a single flat floor: `traversable_fraction == 1.0`, `passed == true`.
- `analyse` on an empty surface list: does not panic, `passed == false`.
- On 20 real generated medium maps, `analyse` completes in under 200 ms each.
- Determinism: same mask and surface produce the same report, 20 times.
