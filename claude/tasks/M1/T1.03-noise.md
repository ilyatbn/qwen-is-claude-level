## Deliverable

```rust
/// Deterministic integer hash of a lattice point. No RNG state, no allocation.
fn hash2(x: i32, y: i32, seed: u64) -> u64;

/// Value at a lattice point, in 0..1.
fn lattice(x: i32, y: i32, seed: u64) -> f32;

/// Smooth 2D value noise, in 0..1. Bilinear interpolation with smoothstep easing.
pub fn value_noise(x: f32, y: f32, seed: u64) -> f32;

/// Fractal Brownian motion: NOISE_OCTAVES of value_noise, each at
/// NOISE_LACUNARITY× the frequency and NOISE_GAIN× the amplitude.
/// Normalised so the result is in 0..1 regardless of octave count.
pub fn fbm(x: f32, y: f32, seed: u64) -> f32;

/// Displace the sample point by a low-frequency fbm before sampling, so the
/// output does not read as axis-aligned. Returns fbm at the warped point.
pub fn warped_fbm(x: f32, y: f32, seed: u64) -> f32;
```

## Notes

**Hand-written value noise, not a crate.** Reasons: no licensing question, no
dependency, and — most importantly — it is directly unit-testable in a way an
opaque dependency is not. It is about 80 lines.

`hash2` must mix well. A weak hash produces visible grid artefacts in the terrain
that are very hard to attribute later. Use a 64-bit integer mix (splitmix64-style)
over `x`, `y` and `seed`; do not use `x * 374761393 + y * 668265263` alone.

`fbm` normalisation: divide by the sum of the amplitudes actually used
(`1 + gain + gain² + …`), not by the octave count. Skipping this makes the output
range depend on `NOISE_OCTAVES`, so `SOLID_THRESHOLD` would silently change meaning
whenever the octave count is tuned.

The warp uses **two independent offsets** (`seed_a`, `seed_b` derived from `seed`)
for x and y displacement. Using the same field for both collapses the warp onto the
diagonal and looks obviously wrong.

Reuse `smoothstep` from `math.rs` — do not write a second one.

## Tests

- `value_noise` is deterministic: same input, same output, 1000 times.
- Output is always in `[0, 1]` over 100 000 random samples, for `value_noise`,
  `fbm` and `warped_fbm`.
- **Smoothness**: `|value_noise(x, y) − value_noise(x + 0.01, y)| < 0.05` across a
  sweep. Noise that is not smooth produces speckled terrain that the CA pass then
  has to fix.
- At integer lattice points, `value_noise` equals `lattice` at that point.
- Different seeds produce different fields: mean absolute difference over a grid
  is > 0.1.
- `fbm` output range does not shift when `NOISE_OCTAVES` is varied (test the
  normalisation directly by calling the inner function with 1, 3 and 8 octaves).
- `warped_fbm` differs from `fbm` at the same point (the warp actually applies).
- `hash2` avalanche: flipping one input bit changes at least a quarter of the
  output bits, averaged over many samples.
