## Deliverable

The single public entry point everything else calls.

```rust
pub struct GenOutcome {
    pub mask: Mask,
    pub surface: Vec<Point>,
    pub report: TraversalReport,
    pub sealed_pockets: Vec<SealedPocket>,
    pub tunnel_paths: Vec<Vec<Point>>,
    pub seed: u64,             // the seed that actually produced this map
    pub requested_seed: u64,
    pub attempts: u8,
    pub used_safe_preset: bool,
}

/// Runs passes 1-7 with retries. Never fails: the safe preset is the floor.
pub fn generate_terrain(requested_seed: u64, scale: MapScale) -> GenOutcome;

/// One attempt, no retry. Exposed for tests and for the PNG dump.
pub fn generate_once(seed: u64, params: &GenParams) -> GenOutcome;
```

Loop:

```
for attempt in 0 .. MAX_GEN_ATTEMPTS:
    seed = requested_seed + attempt
    outcome = generate_once(seed, &GenParams::default_for(scale))
    if outcome.report.passed: return outcome with attempts = attempt + 1

// last resort
outcome = generate_once(requested_seed, &GenParams::safe_for(scale))
outcome.used_safe_preset = true
return outcome
```

`generate_once` runs, in order: `silhouette` → `add_blobs` → `carve_caves` →
`smooth` → `cleanup` → `extract_surface` → `analyse`.

## Notes

**The safe preset result is returned even if it also fails validation.** Generation
must never fail — a round has to start. `used_safe_preset` and `report.passed` are
both in the outcome, so the server can log a `warn` and the tests can assert this
never happens in practice. A `Result` here would push an impossible-to-handle error
up to the room loop.

`generate_terrain` does **no logging** — `game-core` is pure. The server logs from
the returned fields (`docs/61-logging-debug.md` §3).

Do not retain the intermediate labelling buffers. `cleanup` already drops them; make
sure nothing here holds them alive.

Add a cheap wall-clock guard in the test only, not in the function: if a single
medium-scale attempt exceeds 1 s, something has regressed badly.

## Tests

- Determinism: `generate_terrain(seed, Medium)` produces the same mask hash, 20
  times.
- `generate_once` with the same seed and params is identical, 20 times.
- The returned `seed` equals `requested_seed + attempts - 1` when the safe preset
  was not used.
- A seed known to need retries (find one during development and pin it) reports
  `attempts > 1` and still passes.
- Over 50 random seeds at medium scale: `used_safe_preset == false` for all, and
  `attempts <= 3` for all. If this fails, the generation parameters need tuning —
  report that rather than loosening the assertion.
- All three scales produce masks of the right dimensions.
- Borders hold on the final mask, at every scale.
- Timing: a medium-scale `generate_terrain` completes in under 1 s in release mode.
  Run this test with `#[cfg(not(debug_assertions))]` or a generous debug allowance.
- `sealed_pockets` and `tunnel_paths` are non-empty on a typical medium map (T1.13
  depends on them).
