## Deliverable

```rust
/// Run CA_ITERATIONS smoothing passes over the mask, in place.
pub fn smooth(mask: &mut Mask);

/// One pass. Exposed so tests can step it.
pub fn smooth_once(src: &Mask, dst: &mut Mask);
```

Rule:
```
n = count of solid pixels among the 8 neighbours
solid' = if solid { n >= CA_SURVIVE } else { n >= CA_BIRTH }
```

## Notes

**Double-buffer.** Smoothing in place reads already-updated neighbours and produces
a directional smear that looks like the terrain is melting toward one corner. Keep
two masks and swap; allocate the scratch once in `smooth`, not per iteration.

**Out-of-bounds neighbours count as solid.** This keeps the map edges stable — the
alternative erodes the walls from outside in, which then has to be repaired by
`force_borders` every iteration and produces a visible seam.

Call `force_borders` after the final iteration anyway, cheaply and defensively.

This is a 4.7-million-pixel loop run three times, so it is the second most
expensive thing in generation after the silhouette. Read neighbours with direct
`get` calls rather than constructing anything per pixel, and do not allocate inside
the loop. If you want it faster later, the row-window trick (keeping three row
sums) is the standard approach — but do not do it now, correctness first.

## Tests

- Determinism: same input mask produces the same output, 20 times.
- Idempotence tendency: a second `smooth` call changes far fewer pixels than the
  first (assert the second-pass change count is under 10 % of the first).
- **Speckle removal**: a mask with 200 isolated single solid pixels on empty
  background has all of them removed after one pass.
- **Hole filling**: a solid field with 200 isolated single air pixels has all of
  them filled after one pass.
- A large solid rectangle keeps its interior intact and only rounds its corners.
- A large air region stays air.
- Borders hold afterwards.
- `smooth_once` does not modify `src`.
- Total solid count changes by less than 15 % over the full `smooth` call — the CA
  should tidy the shape, not redefine it. A larger swing means the birth/survive
  values are wrong.
