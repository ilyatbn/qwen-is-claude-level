# T18.01 — The title screen stops after thirty seconds (v6)

Milestone: M18 · Depends on: nothing · Size: ~150 lines

## Read first
- `docs/74-amendments-v6.md` §E9

## Deliverable

The title screen draws a decorative background that needs **no `World`, no WASM core and
no server**, and it cannot take the menu down with it.

`AttractCore` and `Core.attract()` lose their only caller. Say so; do not delete them
silently.

## Notes

- **The cause is measured, not guessed** (§E9): `ATTRACT_HZ` is 20 while each step
  advances `SIM_DT` (1/60), so the attract world runs at **one third of real time**.
  `WARMUP_SECONDS` (10 simulated) lands at ~30 s of wall clock, and at that instant
  damage un-gates, the weather scheduler starts, item spawns start and teleports start
  together. At 45 s the scene tears the world down and rebuilds it from inside
  `update()`; a throw there leaves the DOM removed *and* stops Phaser's frame loop, which
  is why the button dies too.
- **Do not fix this by correcting the timestep.** The requirement is that the menu cannot
  be broken by the background, and a background that runs the game can always break it.
- Seeded and cheap. No `Math.random()` in the draw loop if the look is meant to be stable.
- Whatever it draws, the Start button must survive it — that is the acceptance criterion.

## Tests

- The menu is still interactive after a run longer than the old failure window — assert
  the button responds at t > 60 s, with a control at t = 1 s.
- **Pixel acceptance**: the background is drawing something, not a blank canvas, with a
  control region and a control frame.
- No WASM core is constructed by the title screen — `grep`, and assert the constructor is
  not called.
- An exception thrown inside the background's own draw does not stop the scene or remove
  the UI.

## Done when

```sh
npm --prefix client test -- --run title && node scripts/e2e.mjs title
```
