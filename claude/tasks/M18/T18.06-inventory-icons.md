# T18.06 — Inventory tiles show the item (v6)

Milestone: M18 · Depends on: nothing · Size: ~150 lines

## Read first
- `docs/74-amendments-v6.md` §E14
- `docs/50-sprites-skins.md` §8 (fallback order)

## Deliverable

An inventory tile draws the same art the world draws, resolved through the same key with
the same fallback order: packed atlas frame, else the procedural canvas from
`itemTextures.ts`, else text.

`SlotView` carries `slot`, `key` and `count`; it needs the sprite key too.

## Notes

- Today a tile is `tile.textContent = tileLabel(slot)` — the raw registry key as a
  string, wrapped in a 46 px box. The same item on the map is a 16 px sprite.
- `ensureItemTextures` already builds the procedural canvases and is called only from
  `ItemLayer`'s constructor. The inventory has no Phaser texture access today; decide how
  it gets one and say why — a second copy of the painter table is the wrong answer.
- Text stays as the last fallback, so an item with no art is still identifiable.
- The quick bar and the backpack are the same tile; build it once.

## Tests

- **Pixel acceptance**: a tile holding a bazooka renders pixels the bazooka sprite has
  and an empty tile does not, with an empty tile as the control region.
- The same item is the same art in the tile and on the map — sample both in one frame.
- An item with no atlas frame falls back to the procedural canvas; one with neither falls
  back to text and warns once, not per frame.
- The count badge survives the change.
