# T17.01 — A lobby is a room without a world (v6)

Milestone: M17 · Depends on: nothing · Size: ~250 lines

## Read first
- `docs/74-amendments-v6.md` §E1, §E8
- `docs/41-server-loop-rooms.md` §1, §3 (the phase machine this reshapes)
- `docs/72-amendments-v4.md` §C18 (which §E1 overrides in one clause)

## Deliverable

A room in `RoundPhase::Lobby` holds **no `World`**. It holds a roster, a code, and its
settings. The map, the round clock, the weather schedule and the item spawns are created
when the match starts.

- `Room` gains a lobby state that is valid before a world exists.
- Map generation moves out of `Room::new` into the transition to `Warmup`.
- `map_init` is no longer sent at seat time — it is sent to everyone seated when the
  match starts.

## Notes

- **This is the enabling change for the whole milestone.** A private lobby can only
  change map size because no map exists yet (§E1), and lobby creation stops paying
  `docs/71` §B2's 0.6–1.1 s generation cost.
- `Room::new_async` already generates on `spawn_blocking`; that is where match start
  should generate too, so the tick loop never blocks.
- **`tick` is still a clock.** `docs/72` §C18-clarified says a Lobby room must keep
  advancing `tick` even with no round. Do not regress that — `docs/72` §C27 records a
  determinism test that could not tell a round from an empty lobby.
- The seed rule is unchanged: `mix_seed(session_base(), room_id)` per room, so two
  lobbies never play the same map (`docs/71` §B13).
- Do not delete the mid-round catch-up encoder. T17.05 closes live matches to *new*
  players and deliberately leaves reconnection open.

## Tests

- A room in `Lobby` has no world, and asking it for one is a compile-time impossibility
  or an explicit error — not a panic.
- Seating a player into a lobby emits `welcome` and **no** `map_init`.
- Starting a match emits exactly one `map_init` per seated socket, and the map is the
  size the lobby's settings said.
- Two lobbies started with the same settings get different maps (seed mixing holds).
- A lobby ticks: its `tick` advances while `round_time` does not.
- Generation happens off the tick loop — the loop does not stall for the generation time.

## A note on the Done-when

`cargo test -p game-server --lib <pattern>` **matches zero tests and exits 0** when the
pattern names nothing, and `crates/game-server/tests/` is where the lobby tests already
live — `--lib` never runs an integration target. Five of these six Done-whens were
written in that vacuous form and are corrected here to name a `--test` target. **Create
that target.** If your Done-when passes before you have written anything, it is not a
Done-when; say so rather than reporting it green.
