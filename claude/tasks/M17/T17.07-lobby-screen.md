# T17.07 — The lobby screen holds the socket (v6)

Milestone: M17 · Depends on: T17.02 · Size: ~250 lines

- `docs/74-amendments-v6.md` §E1, §E6, §E7

## Deliverable

The lobby is a **menu screen with a live socket**, not a panel over a running game.

- `MenuScene` (or a `LobbyScene` beside it) opens the connection, sends the intent, and
  renders `lobby_state`: the roster, the capacity, the code, the countdown, ready.
- `map_init` is what moves the client to `GameScene`.
- `GameScene`'s `showLobby` / `hideLobby` / `showJoinCode` panels are **deleted**.

## Notes

- **This is the defect the user reported.** `MenuScene` builds `matching` and `lobby`
  screens and then calls `scene.start('Game')` in the same frame, so they are torn down
  before they render; the lobby you actually see is a DOM panel in `GameScene` drawn over
  a world you are already standing in.
- Leaving the lobby must actually leave — `leave_room`, then back to the menu, with the
  socket closed. A lobby you have left must not still count you.
- Ready and the map-size stepper are the same control surface as T17.08's menu; build
  them once.
- Show bots in the roster as bots. A roster that hides them is a roster that lies about
  who you are playing.

## Tests

- **Pixel acceptance** (`docs/72` §C2): the roster shows N names for N seated players,
  asserted on rendered pixels with a control frame before the join.
- The countdown displayed matches `starts_in`, and a second player joining does not reset
  it (the wire rule, seen through the UI).
- `map_init` moves the scene to `Game`; before it, the scene is the lobby.
- Leaving returns to the menu and the server no longer counts the player.
- `grep` proves `showLobby`, `hideLobby` and `showJoinCode` are gone from `GameScene`.
