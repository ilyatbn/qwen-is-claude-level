## Deliverable

```ts
export interface Theme {
  id: number; name: string;
  fill: CanvasImageSource; edge: CanvasImageSource; back: CanvasImageSource;
  skyTop: number; skyBottom: number; fogTint: number; lightTint: number;
  decorSet: Record<number, string>;    // decoration kind → atlas frame
}

export class ThemeLoader {
  static async load(id: number, textures: Phaser.Textures.TextureManager)
    : Promise<Theme>;
  /** Seeded value-noise textures, generated into canvases. No files needed. */
  static generateFallback(id: number): Pick<Theme, 'fill' | 'edge' | 'back'>;
}
```

Three themes: `grassland` (brown soil, green crust), `desert` (tan sandstone, pale
sand), `frost` (grey rock, pale blue ice). Textures: `fill.png` and `edge.png` at
256×256 seamless, `back.png` at 512×512 seamless.

## Notes

**Seamless tiling is the requirement that matters.** A texture with a visible seam
produces a grid across the entire map — the most obvious possible artefact, and the
chunk offset logic in T3.03 cannot hide it. Verify by tiling each texture 3×3 and
looking for lines.

Terrain textures are **not** from Kenney — the terrain is procedural, so it needs
tiling materials rather than sprites. Generate them with the procedural fallback and
commit the results, or hand-make them. Either is fine; say which you did.

**The procedural fallback must stay working** even after the PNGs are committed. It
is what let M3 through M6 run with no art at all, and it is the safety net if a
theme file is ever missing (`docs/51-assets.md` §5). Use the same value-noise
implementation the map generator uses, exposed through WASM, so the fallback is
seeded and reproducible rather than random per load.

Only the **active** theme's three textures load for a round
(`docs/51-assets.md` §7) — do not preload all nine.

The theme comes from `MapMeta.theme`, which is seeded, so a seed always looks the
same. That matters for bug reports with screenshots.

`decorSet` maps decoration kinds to atlas frames. A theme with no entry for a kind
skips it, so kinds and themes evolve independently
(`docs/50-sprites-skins.md` §6).

`fogTint` and `lightTint` feed the lightmap (T3.10) so night in the frost theme
reads blue and night in the desert reads warm.

## Tests

`client/src/render/themes.test.ts`:

- All three `theme.json` files parse and validate.
- Each theme directory has all three PNGs.
- `fill.png` and `edge.png` are 256×256; `back.png` is 512×512.
- **Seamlessness**: for each texture, the left column matches the right column and
  the top row matches the bottom row within a small tolerance. This is an automatable
  check and it is worth having.
- `ThemeLoader.load` with a missing file falls back to the procedural texture and
  logs a warning.
- `generateFallback` is deterministic for a given id.
- `generateFallback` produces tiling textures — same seamlessness check.
- Only the requested theme's textures are loaded (assert the load call count).
- An unknown theme id falls back to theme 0.
- Every decoration kind used by the generator has an entry in at least one theme's
  `decorSet`.

## Done when

```sh
npm --prefix client test -- --run themes
```
Then play three rounds in a row and confirm each looks visibly different, with no
tiling seams in the terrain.
