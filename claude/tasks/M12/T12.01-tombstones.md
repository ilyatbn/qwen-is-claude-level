## Deliverable

On death, a tombstone at the death position, lasting the round. `tombstone_spawn`
and `tombstone_despawn` per §B9; `tombstone_skin_id` joins `skin_id` in `join`,
`welcome` and `player_join`.

## Notes

- It is a **physics body** (`Body::sized`, 14 × 18) so it falls when the ground under
  it is destroyed — a tombstone hanging over a crater is the same lie `docs/32` §4
  rules out for crates, and this project has already shipped that bug once.
- **No collision with players**, no gameplay effect in v1.
- `TombstoneEffect` has one variant, `None`, and **nothing branches on it**. It is a
  seam for revive-here or explode-on-touch later, not a stub layer.
- Capped at `MAX_TOMBSTONES`, oldest first, so a long round does not accumulate
  unbounded entities.
- The server does not know what any skin id looks like (`docs/50` §1).
- **Announce existing tombstones on join** — §A39's pattern, seen five times: state
  that exists before a client connects is never sent to it. A mid-round joiner must
  see the graveyard.

## Tests

- A death places exactly one tombstone at the death position.
- It falls when its support is carved; it rests on bedrock.
- It never collides with a player (a control: the same body *does* collide with
  terrain).
- `MAX_TOMBSTONES + 1` deaths leave `MAX_TOMBSTONES`, oldest removed.
- A client joining mid-round receives every existing tombstone — assert the count
  against the server's, per §A39.
- An unknown `tombstone_skin_id` resolves to 0 without throwing.
