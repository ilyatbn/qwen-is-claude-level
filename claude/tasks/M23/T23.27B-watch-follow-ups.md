## As built (builder4, 2026-10-01)
1. **Cause, reproduced:** cargo decides freshness by mtime alone, so a changed source carrying an mtime older than
   the last build is never compiled. Planted `SPACE_MOON_ORBIT` 240 with `touch -d '2 days ago'`: `wasm-build.mjs`
   printed "ready" and the package read 238 (the previous build's). An edit *during* a build is not the cause (tried:
   cargo caught it). How T23.10B's 236 got an old mtime is not recoverable — a file copied in with its times kept
   (`cp -p`/rsync from a worktree) does exactly this. **Fix:** `scripts/lib/wasm-inputs.mjs` — `wasm-build.mjs` keeps a
   content manifest of both crates and the workspace files (`target/.wasm-build-inputs.json`, written only after a
   verified build) and bumps the mtime of every input whose content changed before building; no manifest bumps all
   once. Test: the same plant (241, old mtime) → the normal build recompiles and `__game.constants()` in a browser
   reads 241; a second build with nothing changed recompiles nothing (the control); `wasm-inputs.test.mjs` (node,
   2 tests). **For the coordinator:** `check.sh` (not in Touch only) should run `node --test
   scripts/lib/wasm-inputs.test.mjs` beside the other two lib tests.

   the next round starts on its own", the countdown "Next round in N s" / "Next round starting…", no vote rule line.
   Vitest with a one-human control.
