# T23.09 — Effects are the lights: one light list per frame, from game events

Milestone: M23 · Depends on: T23.07 · Size: ~200 lines · Rulings: R10, R13, R15

In F, explosions, lasers, muzzle flashes, jet plumes, rockets, fire, gates and crystals **are** the lighting. Today
`GameScene` already gathers `LightSource` lists (player FoV, `ordnance.lights()`, `fx.lights()`,
`weather-math.ts::ventLights`) for the MULTIPLY lightmap; this task turns them into the renderer's point lights.

## Do
1. One per-frame light list `{x, y, z, r, rgb, i}` with the mockup's values (`M23-RESEARCH.md` § 3 table:
   explosion z70 r460 i3.2 decaying, laser impact z30 r170 i2.4, muzzle z30 r120 i1.8 for 1–2 frames, jet plume
   z20 r100 i1.3, rocket z20 r120 i1.5, flamethrower z20 r150 i2.0, gate z30 r150 i1.6, crystal z20 r100–110
   i1.0–1.2) — **as named constants in the client look module, each citing the mockup file it came from.** Colours
   from `P`. Static lights (gates, crystals) from a spatial list; dynamic ones from the events the client already renders.
2. Cap, cull to view + radius, rank by intensity × on-screen coverage, decay over the source's life.
3. **Every source that emits a light has a production caller** — grep and list them in the journal (CLAUDE.md:
   a test calling the function is not a caller). Thruster plumes (T22.04) and lava vents included.
4. `lightmap.ts`'s effect-light role retires here; its vision role moves to T23.10.

## Tests
- vitest: an explosion's light decays to 0 by its end; cap holds at N with the brightest kept; a light outside view
  + radius is culled (and one just inside is kept — presence control).
- Browser check `effect-lights`: in the sandbox, firing the bazooka at rock raises the terrain luminance in a patch
  near the impact within the blast's life, and a patch far outside the light's radius does not change (control);
  repeat for a laser impact and a thruster plume.
