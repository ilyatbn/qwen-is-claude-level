# T23.28 — A clean round restart: nothing left over, nothing shown before it is loaded

Milestone: M23 · Owner, 2026-10-01 (watching `make watch`) · Size: medium, server + client

> *"when games restart all the tombstones and items leftover are still on the map and you cannot interact with them.
> you need to reset all the spawning items. also when you restart the game there are several seconds when there's a
> map with no textures visible but the player can already see it and move. it should first load fully, and only then
> the players should see it and the round should start."*

## Do
1. **Leftovers.** After a restart (`room.rs` `RoundOutcome::Restart` → new world), the client still draws the last
   round's tombstones and item pickups, which no longer exist on the server (can't be picked up). Find which client
   holder survives the new `map_init` (`net/worldMirror.ts`, the furniture/grave layers in `look/`, item pickups,
   anything keyed by id across rounds — ids are reused, so a stale entry can even alias a new one) and clear **every**
   per-round collection on a new round, in one place (a `resetRound()` every holder registers with, not N ad-hoc
   clears). Server side: confirm the new world starts with only its own initial items (no carry-over) and say so.
   Test: a browser check across a real restart — graves and pickups present in round 1, the restart, then the drawn
   set equals the server's set (count both ends), and a pickup in round 2 works. Control: round 1's own pickups.
2. **Load, then show, then start.** On a restart the client shows the new map untextured for several seconds and the
   player can already move. Required order: map arrives → client builds and bakes everything (chunks, terrain
   fields, textures — whatever `pending` / the world renderer's readiness reports) **behind a loading cover** → client
   reports `ready` → **the server starts the round (warmup clock and movement) only once every seated body is ready**
   (with the existing `READY_TIMEOUT` as the bound; bots are ready at once) → the cover lifts. Same rule for the first
   round. Spectators wait for their own load but never hold the round.
   Test: a check that photographs during the gap — no untextured frame is ever presented to the player (cover up
   until ready), and the player's position cannot change before the round clock starts (both ends: server says not
   started, client shows the cover).

3. **Owner, 2026-10-01:** *"when you die in full weapons mode you respawn and your inventory is empty until you click
   something in it (switch from 1 to 2 or something)."* — on respawn with the full-weapons start kit the client's
   inventory UI is empty until a slot change. Find whether the server sends the respawn inventory (the `inventory`
   event) or the client drops it, and fix at the cause. Test: die and respawn with the full kit; the hotbar shows the
   kit **before** any key press (pixels or `inventory()` + the DOM, both ends).
