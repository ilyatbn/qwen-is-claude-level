# T23.28 — A clean round restart: nothing left over, nothing shown before it is loaded

Milestone: M23 · Owner, 2026-10-01 (watching `make watch`) · Size: medium, server + client

> *"when games restart all the tombstones and items leftover are still on the map and you cannot interact with them.
> you need to reset all the spawning items. also when you restart the game there are several seconds when there's a
> map with no textures visible but the player can already see it and move. it should first load fully, and only then
> the players should see it and the round should start."*

## Do
1. **Leftovers.** After a restart (`room.rs` `RoundOutcome::Restart` → new world), the client still draws the last
   round's tombstones and item pickups, which no longer exist on the server (can't be picked up). Find which client
   holder survives the new `map_init` (`net/worldMirror.ts`, the furniture/grave layers in `look/`, item pickups,
   anything keyed by id across rounds — ids are reused, so a stale entry can even alias a new one) and clear **every**
   per-round collection on a new round, in one place (a `resetRound()` every holder registers with, not N ad-hoc
   clears). Server side: confirm the new world starts with only its own initial items (no carry-over) and say so.
   Test: a browser check across a real restart — graves and pickups present in round 1, the restart, then the drawn
   set equals the server's set (count both ends), and a pickup in round 2 works. Control: round 1's own pickups.
2. **Load, then show, then start.** On a restart the client shows the new map untextured for several seconds and the
   player can already move. Required order: map arrives → client builds and bakes everything (chunks, terrain
   fields, textures — whatever `pending` / the world renderer's readiness reports) **behind a loading cover** → client
   reports `ready` → **the server starts the round (warmup clock and movement) only once every seated body is ready**
   (with the existing `READY_TIMEOUT` as the bound; bots are ready at once) → the cover lifts. Same rule for the first
   round. Spectators wait for their own load but never hold the round.
   Test: a check that photographs during the gap — no untextured frame is ever presented to the player (cover up
   until ready), and the player's position cannot change before the round clock starts (both ends: server says not
   started, client shows the cover).

3. **Owner, 2026-10-01:** *"when you die in full weapons mode you respawn and your inventory is empty until you click
   something in it (switch from 1 to 2 or something)."* — on respawn with the full-weapons start kit the client's
   inventory UI is empty until a slot change. Find whether the server sends the respawn inventory (the `inventory`
   event) or the client drops it, and fix at the cause. Test: die and respawn with the full kit; the hotbar shows the
   kit **before** any key press (pixels or `inventory()` + the DOM, both ends).

## As built (builder4, 2026-10-01)

**Causes, measured before fixing** (headless repro, then the GPU): (1) `Room::restart` sent **no `map_init`** at all
(its doc said it did) — clients drew round one's map, graves and pickups (mirror `tomb 1, items 3` across the restart)
until a mask checksum disagreed ~5 s in and `resync_map` fetched the new map; round two ran meanwhile. Then (2) the new
map showed as Phaser's flat rock until the lit terrain painted. (3) The kit is re-granted after the respawn step by
`give`, which pushes no `inventory` event: the client's last word was the death's empty bag. Found on the way: (4) a
new world's own pickups (`place_initial`, inside `World::new`) were never announced to anyone seated when it was built —
every first round and every restart (server items `0,4,5,6,7,9,10`, client `10`); (5) `tick overrun lagging=3111` once
a second for all of round two (the lag clock not re-based when the world's tick restarts at 0).

**Fixes.** Server (`room.rs`): `await_load` clears every seat's `ready` when a map goes out (install and restart, one
function); the world is parked in `Lobby` and `tick_once`'s **load hold** advances only the tick (no step, bots, round
clock) until every seated **body** has sent `ready` for it (`awaiting_load`; spectators load but never hold; bots are
ready on seating; `sweep_unready`'s ready timeout is the bound), then `set_phase(Warmup)` on the release tick. The room
task, on `take_restarted`: `new_round` → `map_init` → inventories → `send_the_ground` (`session::catch_up_world`, the
joiner's list) → bots' `player_join`; the install path sends the ground and bots too. A respawn pushes `inventory`.
Client: `net/roundReset.ts` — every per-round holder registers (`mirror.resetRound`, `interp.reset`, the scene's
`resetRound`, the ordnance layer); `new_round` runs it. `ui/loadCover.ts` (opaque, z 15) is up while `!ready ||
!readySent || awaitingRound`; `ready` goes out once the map is painted (`terrainSwapPending`, after the renderer chunk
settles) or at once on a hidden page (else a backgrounded tab would hold everyone's round until swept).

**Assumptions for the coordinator.** A wire event `new_round {tick}` was added (docs/40 does not list it). The client
has no bound of its own on painting: a visible page whose terrain never paints is dropped by the 30 s sweep (no client
constant for READY_TIMEOUT exists to derive one from). The hold reuses `Seat.ready` (handshake = "holds the map in
force"), so tests that start a match now send each body's `ready` after the world exists (`awaiting_load`), as a
client does — 9 integration test files adjusted. Touched outside **Touch only**, each a consequence of the new contract:
`crates/game-server/tests/*` (the above), `scenes/gameScene-reset.test.ts` (reads `resetRound` too),
`scripts/checks/harness.mjs::inTheGame` and `round-over.mjs` (the match as presented = the cover lifted),
`look-match.mjs` (cast held empty for its static-frame controls: the newly announced pickups animate — measured top
rows max 117 with them, 0 without).

**Filed, not fixed (game-core, outside Touch only):** `items/world.rs::resolve_pickups`' `Partial` arm pushes
`item_pickup` while the remainder stays on the ground — every client deletes an item the server still holds (seen in
`round-restart`: a bot took part of a 120-round stack). `round-restart` asserts pickups client ⊆ server for that reason,
and exact at a round's start.
