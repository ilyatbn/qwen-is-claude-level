# T23.27 — Spectate a bots-only match; Tab switches who you watch

Milestone: M23 · Owner ask 2026-09-30 · Size: ~300 lines, server + client · Pairs with T23.26 (how the owner judges it)

> *"simulate a game with bots only with a full chrome ui so i can watch and comment. let me switch the camera between
> them (like a spectate mode) with tab."*

**Spec:** `docs/78` §A1 (overrides `docs/74` §E8). **Read `SWEEP-T23.26-T23.27.md` (T23.27 half) before
building** — it names ten server and six client landmines at the symbol: a spectator seat must not eat a bot seat
(`Seats::alloc`'s cap), one `Seat::has_body()` guard for `populate_world` and the in-match `Join`, the three readers of
`human_count`, the room **restarting on its own when only watched** (else `make watch` stops after one round), a replay
tag for the spectator's join, and one client `viewer()` function that all 39 `this.me` sites needing a viewpoint read
(land it with no behaviour change first; it is T23.10B F1's `seenAt` input). The HUD has no ammo for a remote (not on
the wire) — show the weapon only.

## Do
- **Server: a spectator seat.** A join flagged `spectate` takes a seat with **no body**: not in `world.players`, not
  counted toward `MAX_PLAYERS` or the round's "last one standing", sends no input, receives every snapshot/event a
  player does. A room whose humans are all spectators still starts with bots (`start_with_bots` / the lobby timeout).
  Unflagged joins behave exactly as today (wire-compatible; an old client never sends the flag).
- **Client: `?spectate=1`** joins that way. The camera follows a chosen living player (`world.rig.follow`), starting
  with the first; **Tab = next living player, Shift+Tab = previous** (in spectate mode only — Tab keeps the scoreboard
  in a normal match; in spectate the scoreboard moves to a held key and says which). When the watched one dies, stay
  on their death for ~1 s then move to the next. The HUD shows **the watched player's** name, health, energy, jet and
  weapon, and a small "SPECTATING <name> — Tab to switch" line. No crosshair, no inventory input. The kill feed,
  minimap and night view work as for a player (night view centred on the watched one).
- **`make watch`**: release server with `BOT_COUNT=6` (full room), vite, and a headed GPU Chrome (`scripts/play.mjs`) on
  `?spectate=1` — the owner's one command. Optional `WATCH_ENV` passes e.g. `DEV_BOT_FRENZY=1 DEV_LOADOUT=1`.

## Tests
- server: a spectator join is not in the world, does not block a round from ending, receives snapshots; an unflagged
  join still gets a body (control).
- a browser check `spectate`: joins spectating a bots-only room, asserts the camera centre sits on player A, presses
  Tab, asserts it moved to player B (pixel or `debug().watching` + camera centre, **both ends**), and that no body
  belongs to the spectator.

## As-built (builder2, 2026-10-01)

Built in the sweep's order (`SWEEP-T23.26-T23.27.md`, T23.27 half). Spec: `docs/78` §A1.

**Server** (`room.rs`, `round.rs`, `replay.rs`, `session.rs`, `registry.rs`):
- `Command::Spectate { name, reply }` — **a separate command, not a flag on `Join`**, so every existing `Join` and its
  replay tag mean what they meant (and ~25 test constructors stay untouched). `RoomHandle::spectate`.
- `Seat.spectator`, read only through `Seat::has_body()`: `populate_world` (the in-match `Join` path is the player's
  and unchanged), `lobby_state().players`, `roster()` (lobby branch), `settings_owner`, private "everyone ready".
- `Seats::alloc(max)` caps on **seats with a body**; `alloc_spectator()` has no cap but the id pool. A spectator in a
  full bot room kicks no bot (test + plant: cap on all seats → red).
- `human_count()` excludes spectators (its three readers: lobby fill, private ready, the vote); `spectator_count()`,
  `watched()`. `RoundController::tick(world, humans, watched, dt)`: **a watched room restarts at the window's close**
  (`docs/78` §A1, the sweep's option (a)). Test: two rounds back to Playing; control: a silent human → Lobby; plant
  (watched ignored) → red ("did not come back to Playing (now Lobby)").
- A spectator's `Input` is dropped unrecorded, its `VoteRestart` refused (a watcher's yes would otherwise count against
  `human_count`, which excludes it). Fire/heal hit no body (test).
- Replay: `ReplayCommand::JoinSpectator { name }`, **tag 24**, appended (no version bump); `to_command` → `Spectate`.
  `every_command` + the tag count (23) updated.
- `session.rs`: `"spectate": true` on the join payload; a spectator may join a started match (§E4 stands for
  players), gets no `player_join` broadcast. The mid-match catch-up block is live again for it (comment updated).
- `registry.rs`: `RoomEntry.humans` documented as sockets incl. spectators, on purpose.
- `arm_bot_timeout` shared by `Join` and `Spectate` (share the function), so a watched lobby starts as a played one.

**Client** (`GameScene.ts`, `net/connection.ts`, `net/spectate.ts`):
- `?game=1&spectate=1` → `Connection.connect(…, { kind: 'spectate' })`. (`?spectate=1` rides the dev `?game=1`
  entry: `main.ts` is outside Touch only; `MenuScene` was not needed.)
- **`viewer()` / `viewAt`: one viewpoint** — the predictor's drawn place (unchanged for a player) or the watched
  player's interpolated sample. Read by the camera, `renderRemotes`' seeing-rule circle (T23.10B F1's), the night
  view, the minimap and `ear()`. `renderRemotes` now takes the frame's one sample.
- Spectate: no core player, no predictor, no local view, no crosshair, no quick bar, no input sent (handlers guarded).
  The HUD bars read the watched player's snapshot row; `#spectate-line` names them and their held item (ammo is not on
  the wire for a remote). Tab / Shift+Tab step living players (`net/spectate.ts::stepWatch`, id order); scores on a
  held **S** (`SPECTATE_SCORES_KEY`). The camera stays on a death `SPECTATE_DEATH_LINGER_MS` (1000, client-only UI
  pace — assumption: not put in `constants.rs`, which is outside Touch only) then moves on.
- `debug()`: `spectating`, `watching`, `viewAt`, `cameraCentre`, `watchSteps`, `playerIds`.
