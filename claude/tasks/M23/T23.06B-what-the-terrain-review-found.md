# T23.06B — What the terrain review found (78d6889, ad9bb6c)

Milestone: M23 · Depends on: T23.06 · Size: ~600 lines across the findings (split by finding) · Rulings: R17, R22, R23 (new)

## Why
The review of T23.05B/T23.06 (`gate-review2306-*.txt`) planted **D** (no disposed guard: a late worker result
installs into the next map's core) and **E** (no replay: carves made while the job ran are lost) and both stayed
green — nothing tested `TerrainFields`' lifecycle. Plus: a disposed job kept the page's one worker busy, so the
next map queued behind it; the Large install was one 120–140 ms frame; a late joiner derived a different cave wall
than a round-start client wherever a carve opened the map build's ground fill; `context-budget` sampled three's
memory before the terrain existed; a carve diffed whole 256² chunks; the grass-fringe loop ran in open sky; a
version-skewed generator would install a wrong wall silently; `rederive`'s safe-preset branch was never run.

## Do

  install blocked), carve-during-job then install (replayed; `stats.replayed`), two carves in one frame, a carve
  across a chunk border. Plants D and E red.

## As built (builder, 2026-09-27)
- **F1:** 9 vitests (`terrainFields.test.ts`). Plants D, E, "cancel does not terminate", "no fallback on error" each
  turn exactly their test red (`gate-t2306b-plantsDE.txt`).
- **F2 — measured before building on it, and the naive fix was slower.** Terminate-and-recreate alone: the next job
  waited ~400 ms for a fresh worker (spawn, module graph, wasm instantiate) — more than the stale job had left, so
  rematch-to-installed went *up* (1.80–2.09 s queued vs 1.93–2.22 s terminated). Built instead: terminate + **a warm
  spare** made whenever a worker is promoted (it instantiates the main thread's compiled module, `wasmModule()`).
  Large, second map 200 ms after the first: **2.04–2.08 s → 1.66–1.73 s**; 0 ms after: 1.80–1.90 s (queued, measured
  with the terminate planted out) → 1.57–1.58 s — the job now ≈ its own worker time.
- **F3:** `TerrainLayer.ready` (`GameWorld.terrainReady()`, `debug().terrainReady`): true once every field strip is up
  and every tile painted for this map; a same-map resync keeps the GPU side, `ready` and the scorch (look-albedo §4:
  0 of 134 frames not ready; scorched px 1207 → 1207; plant "never keep" → 128/128 frames not ready, scorch → 0).
  Worker error → `renderFieldsFull` on the main thread, `debug().terrainWarning` says so. Map key = `map_init`'s
  fields + size (sandbox adds a regenerate epoch: a regenerate is a new map, a resync is not).
- **F4:** `gen::rederive_landform` = landform ∪ (generator mask + pass 8's fill, replayed by the same
  `meta::standing_furniture` / `fill_under_furniture` pass 8 now calls). Exact: the replayed mask == `generate_full`'s
  on 12 filled builds (plant: fill dropped → red). Late joiner == round-start client, byte for byte, 3 maps
  (control: T23.05B's landform → differs; with it the F9 guard would flag every filled map as skew: 685 strays).
- **F5:** `context-budget` samples each match again once `terrain().ready`: 15 textures at every match (11 + the four
  terrain ones), 22/49.5/88 MB by map size. Plant (field texture not disposed): textures 11→12→… red at titles,
  matches and installed matches.
- **F6:** Large worst frame **132–140 ms → 22–23 ms** (control, three off: 18–26 ms); what it took, each measured:
  install copy moved (15 → 2.4 ms), 48 MB upload → 8 strips (pump 62–75 → ≤ 7 ms), Chrome's lazy zero-fill paid at
  the map change (1-px touch + target clears), the passes warmed by a 1-px draw at the map change (the first tile
