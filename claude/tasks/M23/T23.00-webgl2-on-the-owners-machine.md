# T23.00 — WebGL2 on the owner's machine, and a clear message where there is none

Milestone: M23 · Depends on: nothing · Size: ~120 lines · Rulings: R1, R2

**This task gates the milestone.** The owner's WSLg Chrome falls back to Phaser's Canvas renderer today
(`M23-INVENTORY.md` § 9), and three.js 0.170 needs WebGL2 with no Canvas path. If the owner cannot get WebGL2,
nothing else in M23 should be built until R1/R2 are revisited — report that to the coordinator immediately.

## Do
1. **Measure, do not assume.** In the headed Chrome `make play` opens, and in the headless Chromium the browser checks
   use (`scripts/lib/browser-args.mjs`), print `!!document.createElement('canvas').getContext('webgl2')`,
   `WEBGL_debug_renderer_info` vendor/renderer strings, and `EXT_color_buffer_half_float` /
   `EXT_color_buffer_float` availability (the post chain renders to half-float targets). Paste all of it.
2. If headed Chrome lacks WebGL2, find launch flags that give it on WSLg (e.g. `--use-angle=vulkan`,
   `--use-gl=angle --use-angle=swiftshader`, `--ignore-gpu-blocklist`, `--enable-unsafe-swiftshader`) and put the
   working set in the `make play` launcher. Record the renderer string and a rough frame rate for a three.js
   full-screen shader page with each candidate.
3. A **full-screen "this game needs WebGL2" message** shown by `main.ts` before any scene boots when WebGL2 is absent,
   with the browser's own reason if it gives one. Real-player machines are the audience, not the dev box.
4. Add `three@0.170.x` (exact pin, matching `reference/mockup-src/package.json`) to `client/package.json`; nothing
   imports it yet. Note the bundle-size delta.

## Builder notes (T23.00 done, 2026-09-26)
- **`REQUIRE_WEBGL2 = false` (`client/src/webgl2.ts`) — the message is wired, not enforced.** R2 retires the Canvas
  world path only once three.js draws the world; until then Phaser still runs on Canvas, so blocking a machine
  without WebGL2 would take a working game away. `main.ts` calls `gateOnWebgl2` before `Core.init()` and any scene;
  with the flag false a missing WebGL2 only logs to the console. **`T23.03` flips the constant** (and the vitest
  `is not enforced until T23.03` line flips with it). Both states are tested.
- `make play` now launches with `GALLIUM_DRIVER=d3d12` + `--ignore-gpu-blocklist`; the old `--use-gl=swiftshader`
  pair is removed because it forces SwiftShader over the GPU. Consequence: the owner's window now runs **Phaser
  WebGL**, not Canvas (verified: sandbox at 60 fps, `getContext('webgl')` on the game canvas answers).
- `make probe` prints one `webgl` line: GPU/CPU + renderer. `scripts/webgl2-probe.mjs --all | --preset X | --checks`
  re-measures the table (dev tool; mapped to "nothing" in `lib/affected.mjs`, a one-line edit outside Touch only).
- Shared page reader: `scripts/lib/webgl-info.mjs::webglInfo` (check, probe tool and `probe.mjs`). Half-float is
  asserted by effect: a 2.0 clear into RGBA16F reads back 2; control RGBA8 clamps to 1.
- `three@0.170.0` exact. Bundle delta from three: **0** (nothing imports it; `THREE.WebGLRenderer` absent from the
  build). The whole commit: index js 1,821.66 → 1,823.22 kB (gzip 451.66 → 452.37) — that is `webgl2.ts`.
