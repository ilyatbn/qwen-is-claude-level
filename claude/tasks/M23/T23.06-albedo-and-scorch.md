# T23.06 — Painting the rock: albedo and relief on the GPU, scorch from explosions

Milestone: M23 · Depends on: T23.03, T23.05 · Size: ~250 lines · Rulings: R4, R5

## Do
1. Upload T23.05's fields into **one world-sized RGBA8 texture** (`texSubImage2D` on the dirty rect only). One
   texture, not per-chunk: the shader reads ~50 px away and chunk seams would show.
2. Port `world.js`'s albedo painting (strata, grain, Worley boulders, pebbles, cracks, soil and grass on upward-facing
   edges, grass fringe into the air) to a GPU pass that writes a world-sized albedo texture per dirty rect. The hash
   is integer (`Math.imul`) and **ports bit-exact to WebGL2 `uint`** — do that, so the look-lab reproduces F1's rock
   texel for texel.
3. **One palette, no themes (R5):** the albedo takes its colours from `P.terrain` only. Stop reading `MapMeta.theme`
   on the client for terrain.
4. **Scorch**: the mockup's static `spec.scorch` list becomes an accumulated scorch-mask texture written by the
   client's existing explosion events.
5. Hook carve events to dirty-rect updates within today's `CHUNK_REBAKE_MS` budget; measure and paste.

## Tests

- Browser check `look-albedo`: look-lab F1 with lighting forced flat (albedo only) vs the same render from the mockup

- Carving in the sandbox updates only the dirty rect (count texels changed outside it: 0), and the crater shows
  scorch where the explosion was (presence) and nowhere else (absence, with the pre-carve frame as control).

## As built (builder, 2026-09-27)
- **Fields → GPU:** one world-sized RGBA8 field texture + an R16UI **exact `dIn²`** texture (new in `render_fields.rs`:
  the ×4-in-8-bit `dIn` moved the soil/grass bands — 97.4 % of F1's albedo px exact with it, **99.63 %** exact / 100 %
  within 2 with it). `texSubImage2D` of the returned dirty rect only (`terrainGpu.ts::uploadFields`).
- **Albedo:** `albedo.ts::ALBEDO_FS`, `world.js::derive` branch for branch, `THEMES.dusk` only (R5; `MapMeta.theme` not
  read). Hash bit-exact: vitest (TS vs `world.js`, 10k) and `look-albedo` (GLSL read back vs `world.js`, 10k, 7495 with
  negative inputs). Scorch = R8 mask `1 − r/R`, MAX-blended per blast (`SCORCH_PER_BLAST_R` = 80/50, ARENA_E's).
- **Round start off the frame — a worker** (`fieldsWorker.ts`): landform derive + full field pass on a copy, installed
  (`render_fields_install`) and carves made meanwhile replayed. Measured (SwiftShader box): Medium worker 930–970 ms,
  install 10–22 ms on the frame; Large worker 1889 ms, install frame 87 ms (121 ms with the 48 MB upload) — the one
  hitch left. **Albedo full pass split across frames**: 256² tiles, 3.2 ms each on SwiftShader, 1/frame low tier, 4 full.
- **Carves:** `TerrainRenderer.onDirty` (every carve path) → each dirty chunk diffed against the fields' solid bit →
  tight rect → `render_fields_dirty` → upload + repaint grown by `ALBEDO_REACH`. Cost: 4.2–4.5 ms CPU (diff + wasm),
  ~20 ms to GPU completion on SwiftShader — **over `CHUNK_REBAKE_MS` (4) on SwiftShader; reported, not gated.** Owner-GPU
  number not taken (needs a headed session).
- **In game meanwhile:** the pipeline runs in `GameScene`/`SandboxScene` but draws nothing; Phaser's terrain stays until
  T23.07. `WorldRenderer.showAlbedo` (look-lab `only=albedo`, dev) draws it flat.
- **Touched outside the list** (reported): `render_fields.rs` (din2, install/wall/own-key/copies), `core/index.ts`
  (wrappers), `worldRenderer.ts` allocates both composer targets eagerly (context-budget read the redraw skip's frame
