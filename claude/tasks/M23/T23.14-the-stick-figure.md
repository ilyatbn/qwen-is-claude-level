# T23.14 — The stick figure: poses, run cycle, aim, scarf — driven by the sim

Milestone: M23 · Depends on: T23.13 (and F7 in `reference/`) · Size: ~250 lines · Rulings: R8, R9, R10, R15

## Do
1. Procedural animation from sim state, matching F7's pose sheet: stand, 8-phase run (phase driven by horizontal
   speed, two-bone IK legs to foot targets), jump, jet (standard gravity), space thrust, fall, land, melee swing,
   throw, hit reaction, dead. Arms and weapon rotate about the shoulder (`e_style.js::stick`'s `[1.2, −21.5]`) by the
   aim angle — continuous, not quantised. The scarf lags velocity (`stick`'s `jet` parameter curves).
2. Inputs are what `PlayerView` receives today (`playerView-math.ts::deriveAnimState`, `facingLeft`, aim, flags).
   Reuse those derivations; do not re-derive state the sim already sent.
3. **Space helmet (R9):** in space every figure wears F7's helmet with a visor in the player's colour; no picker.
4. **Boots and wings (items, R8)** get stick-figure versions (F4/F7 style) — they are gameplay, so a player must
   still be able to see who has them: rewrite `boots-visible` and `wings-visible` against the new figure.
5. Retire the sprite body: the `chars` atlas, `skins-math.ts` body frames, `canvasTint.ts`, the `PlayerView` sprite
   path (R15). Rewrite/retire `skins-ingame`, `canvas-tinted-skin`, `wasd`'s body-pixel arms in this commit.

## Tests
- vitest: the run phase advances with speed and stops at rest; aim maps to arm angle continuously (no two aims 1°
  apart produce the same cell key unless the cache quantisation says so — name that quantum as a constant).
- Browser check `stick-figure`: look-lab F7 vs F7 (Level A on each pose box); live: running moves the feet (leg patch
  changes over 8 drawn frames) while standing does not (control).
