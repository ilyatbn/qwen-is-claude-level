# T20.21 — Two things `apply_input` still reads that the mirror does not have (v8)

Milestone: M20 · Depends on: T20.19 (landed, `6aad66d`) · Size: ~150 lines

**Booked by T20.19's review.** T20.19 stated the rule as *"everything `apply_input` reads must
be identical on both sides"* and fixed the largest violation — the literal `1.0` where the
server passes `speed_multiplier()`. **Two violations of that same rule survive it.** Neither is
a regression; both are inside the rule the task set.

## 1. Health crosses the wire as a truncated `u8`

`game-server/src/codec.rs` encodes `b.push(p.health.clamp(0.0, HEALTH_CAP) as u8)` — `as u8`
truncates, it does not round — and `client/src/net/codec.ts` decodes `r.u8()`. So the mirror's
health is `floor(server_health)`, and that integer is what reaches `speed_multiplier()`.

Server health is routinely fractional: fall damage is
`(impact - FALL_SAFE_SPEED) * FALL_DAMAGE_PER_SPEED`, and poison and overheal decay are
per-second rates. **So the mirror sits up to 1.0 health below the server, permanently, always
in the same direction.**

Measured against the constants, not asserted:

```
d(multiplier)/d(health) = (1 - HEALTH_SPEED_MIN) / BASE_HEALTH = 0.25/100 = 0.0025
1.0 health           -> WALK_SPEED * 0.0025             = 0.375 px/s
RECONCILE_EPSILON_PX -> 2.0 / 0.375                     = one correction every 5.33 s
(before T20.19, at half health: 18.75 px/s -> every 0.107 s)
```

So T20.19 bought a **50×** improvement and this is the residual floor. **It is not urgent and
it is not nothing** — it is a correction every five seconds for as long as a player is hurt and
moving, and it will never converge.

**Why no test caught it: nothing in T20.19 goes through the codec.**
`game-wasm::walk_both_sides` sets `health` directly and hands the same `f32` to
`set_player_state`; `prediction.test.ts::walkReconciling` passes `h.snapshot` straight into the
reconcile object. Both bypass the `u8`. **Whatever you do here, the test must cross the codec**,
or it will pass for the same reason these did.

Two candidate fixes, neither pre-chosen: send sub-integer resolution for the local player's own
block, or **quantise the server's own `speed_multiplier()` input through the same `u8`** so both
sides read one number. The second is cheaper and makes the two sides equal by construction
rather than by precision, which is the property the rule actually wants.

## 2. The mirror has no `alive`, and `apply_inputs` gates on it

`world/mod.rs::apply_inputs` runs `if !self.players[idx].alive { continue; }` **before** it
computes `speed`. `game-wasm::apply_input` has no such gate, `set_player_state` never sets
`alive`, and `GameScene`'s update loop calls `pushInput` without an alive check.

**So a dead local player holding a direction is predicted walking while the server holds them
still** — the identical rubber-band T20.19 fixed, at full magnitude rather than a residual.

Pre-existing, not a regression. **It was discovered during T20.19 and not reported**, which is
the part worth noting: the fixture comment reads *"Not health 0: that is death, and
`apply_inputs` skips a dead player — the first run of this loop measured a corpse and read
20 px/s, exactly one tick of `WALK_ACCEL`."* The fixture was steered around the gap instead of
booking it. `CLAUDE.md` asks that a gap found be reported; this one was found and dropped.

**Decide which layer owns it** and say why: a gate inside `apply_input`, an `alive` field on the
snapshot, or `GameScene` not predicting a dead player at all. The third is cheapest and the
first is the one that cannot be forgotten by a future caller — *share the guard, or share the
function.*

## 3. Two test defects in T20.19, both live

- **The "two-sided pin" on `HEALTH_SPEED_MIN` has one side.**
  `game-wasm::the_client_predicts_a_hurt_player_where_the_server_puts_them` asserts
  `want > WALK_SPEED * HEALTH_SPEED_MIN && want < WALK_SPEED` and its comment claims dropping
  the floor fails the lower bound. It does not: with `want = WALK_SPEED * (m + (1-m)·f)`, the
  lower bound reduces to `(1-m)·f > 0`, true for **every** `m < 1` and `f > 0`. Set
  `HEALTH_SPEED_MIN` to 0.5 and it still passes. **Ask what it rules out: nothing on the low
  side.** Pin the floor where it is actually defined — assert `speed_multiplier()` at
  `health = 0.0` equals `HEALTH_SPEED_MIN`.
- **A hardcoded number with a comment claiming a derivation it does not perform.**
  `const SHELF_RUN: i32 = PLAYER_W as i32 + 96;` says it is "the furthest a full-speed
  quarter-second of walking can carry it", which is `WALK_SPEED * 15 * SIM_DT` = **37.5**, not
  96. `CLAUDE.md` forbids a bare literal in a test outright. Compute it, or name the tick count
  as a const.

## Tests

- The codec test crosses the wire: set a fractional server health, encode, decode, and assert
  the mirror's `speed_multiplier()` equals the server's. **A test that sets health on both sides
  directly reproduces T20.19's blind spot and proves nothing here.**
- A dead player holding a direction does not move on the client. Control: the same player alive
  does move — an absence needs a presence.
- The `HEALTH_SPEED_MIN` floor fails if the constant is lowered. Falsify it and paste the break.
