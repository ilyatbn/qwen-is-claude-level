# T20.22 — A room hop orphans the seat you left behind (v8)

Milestone: M20 · Depends on: nothing · Size: small fix, **large blast radius**

**Found by T20.14's load driver, and reproducible with one client and no concurrency.**
Booked, not fixed there: fixing it inside the driver would have hidden it.

## Reproduce

```sh
cargo run -p game-server --example loadgen -- --scenario rejoin
```

Measured at HEAD (`--seed 4242`, the default):

```
after the retry (control) room 1: humans=1 private=false roster=["R000"]
after the two hops        room 1: humans=1 private=false roster=["R000", "R000"]
                          room 2: humans=0 private=true  roster=["R000"]
capacity probe: 6 `join_room <code>` -> 5 seated, 1 refused {"full": 1}
```

The scenario's **first phase is its control**: two `quick_match` emits on one socket, which
the server documents as safe, and it reports nothing. Only the hop reports.

## The mechanism

`registry.rs::RoomRegistry::attach` moves a socket that is already in another room:

```rust
match self.sid_room.insert(sid, room) {
    Some(prev) if prev == room => return,
    Some(prev) => self.detach_from(sid, prev),
    None => {}
}
```

and `registry.rs::detach_from` is **the only leave path that does not tell the room task
anything**. It removes the socket from `RoomEntry::sessions` and decrements `humans`, and it
never sends `Command::Leave(id)`. Compare `session.rs`'s `leave_room` handler and its
`on_disconnect` handler: both send `Command::Leave` before calling `ctx.detach`.

The registry has no `PlayerId` to send — it holds `Sid`s — which is exactly why the guard was
dropped here. `e.sessions.player_of(sid)` answers it, on the line above the one that removes
the mapping. **This is the "share the guard, or share the function" rule**: `Leave` is the
invariant every other leave path maintains, and the third one does not.

Every verb that can select a *different* room takes this path: `create_room` always,
`join_room` by a code, and `quick_match` whenever the current room has started or filled.

## What it costs, measured

1. **A seat held by nobody, for the rest of the room's life.** The roster above still lists
   `R000` after every socket has gone.
2. **Charged against `max_players`.** Six fresh players `join_room` the private room the
   hopper abandoned; five are seated and the sixth is refused `full` — a room that reports
   itself full with nobody in it.
3. **Two seats in one room.** Hop away and back and `seat` allocates a second one, because
   `detach_from` removed the socket from the target room's `SessionMap` and the duplicate
   guard `sessions.player_of(socket.id).is_some()` therefore reads `None`. The roster above
   shows `["R000", "R000"]`.
4. Through `room.rs::settings_owner` — derived as the non-bot seat with the smallest
   `joined_at` — **an orphan that joined first owns the lobby settings and cannot be
   removed.** That is T20.01's user-visible symptom reached by a second route; T20.01 closed
   the sweep's version of it and this one is untouched. **Read as a code path, not measured**
   — confirm it before writing it into a fix's justification.

## Not to be confused with

`T20.23`, which leaks `RoomEntry::humans` rather than the seat, at a different call site, and
makes the room **unreapable**. Here `humans` is correct and the *seat* is stale. Two fields,
two defects; fixing either leaves the other.

## Notes

- **Check the tests that pin the current behaviour before changing it.** `registry.rs`'s
  attach tests assert idempotence for the same pair, which must survive.
- The fix must not send `Leave` for the idempotent same-room case, or a retry frees the seat
  it was retrying for — which is the bug `emit_until` in `tests/rooms.rs` exists to avoid.

## Done when

A regression test in `crates/game-server/tests/` seats a socket, moves it with `create_room`,
and asserts the first room's `roster()` is empty — **and fails when the new `Leave` send is
removed.**

```sh
cargo test -p game-server && ./scripts/check.sh
```
