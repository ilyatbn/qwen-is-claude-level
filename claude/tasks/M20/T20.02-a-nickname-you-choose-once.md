# T20.02 — A nickname you choose once (v8)

Milestone: M20 · Depends on: nothing · Size: ~120 lines

**No doc section governs this.** Reported: *"players should be prompted to set a nickname
(once, remember it in localStorage) when either joining or hosting a match. Don't just call
them 'dude'."*

## Read first
- `client/src/ui/skins.ts:13-17,26,48-58,60-77` — the storage keys, `MAX_NAME`, `cleanName`,
  `loadChoice`/`saveChoice`
- `client/src/scenes/MenuScene.ts:189-194` — `identity()`
- `client/src/scenes/SkinsScene.ts:184-186,204-207` — the name input that already exists
- `crates/game-server/src/session.rs:298-311` — `sanitise_name`

## What is actually there

**There is no "dude" in the repo.** The default is **`'Player'`**, and it is defined twice:
`skins.ts:26` (`DEFAULT_CHOICE`) and again inline at `MenuScene.ts:189-194`, which reads
`localStorage.getItem('deepcut.name') || 'Player'` **directly** — bypassing `loadChoice` and
`cleanName` and re-spelling all three keys. That is the live binding site for every lobby
verb.

Everything downstream already works: `identityPayload` (`lobby.ts:305-312`) →
`Connection.connect` sends `name` on all four verbs → `sanitise_name` (1–16 chars, control
characters stripped, `bad_name` refusal) → `Seats::set_identity`. Names reach the roster
(`lobby_state.players[].name`) and the HUD (`GameScene.ts:435-444`).

**A name input already exists** — `SkinsScene.ts:184-186` — but it is buried behind the
Skins button and nothing prompts for it.

## Deliverable

- **Prompt once**, on the first join or host, when no name has been stored. Not a nag: once
  stored, never asked again.
- Persist through the **existing** helpers. `MenuScene.identity()` must stop re-implementing
  the read — route it through `loadChoice`/`cleanName` so a stored `"  "` or `"<b>"` cannot
  reach the wire raw.
- Remove the duplicated default. One `DEFAULT_CHOICE`.

## Notes

- **Share the function, do not add a second reader.** The bug this fixes is that
  `MenuScene` already has its own copy of the read; a prompt that adds a third is worse
  than what is there now.
- `GameScene.ts:906` uses `params.get('name') ?? \`player${random}\`` for the `?game=1` dev
  path and never reads `deepcut.name`; `:935` reads `deepcut.skin` inline for the same
  reason. Decide whether those join the shared path or stay dev-only, and say which.
- The server already refuses a bad name (`bad_name`). The client should not be able to
  produce one.

## Tests

- With nothing stored, the prompt appears **once**; with a name stored it never appears —
  and the control: a stored name really is the one sent on the wire.
- `cleanName` is applied on the path the game actually uses, falsified by storing junk
  directly in `localStorage` and asserting what reaches `identityPayload`.
- A browser check: set a name, join, and read it **off the roster**, not out of
  `localStorage`.
