## Why the answer is not a new configuration

The control had **1/8 of margin at T11.16 while its own comment claimed zero**, then went
nine `#[ignore]`d milestones with nobody running it. A one-seed margin between configurations
differing on **two axes at once** (map scale *and* bot count) could never say which axis it
was sensitive to. **It was not measuring what it claimed even while green.**

So picking a new "before" and re-running until it passes is choosing the number that makes it
pass — on the instrument that just demonstrated the cost of that. **Do not.**

## Deliverable — replace the shape, not the value

1. **A structural gap, not a marginal one.** Choose a "before" where fighting is
   near-impossible for a reason you can state in one sentence. **Vary one axis, not two.**
2. **A population claim.** `CLAUDE.md`: *"a population claim needs more than one draw."* Eight
   seeds decided by a one-seed margin is a single draw wearing a sample's clothes. Aggregate,
   and assert on the aggregate.
3. **Record the measured margin** in the test, so the next person sees erosion rather than
   discovering exhaustion.

## Budget the clock before you start

The Done-when runs **all five** `#[ignore]`d tests in `balance.rs`, each documented
*"measurement: minutes in release"* — so it is a **multi-tens-of-minutes** command, and you
will run it more than once: at minimum a baseline, then each candidate control. Gating on the
real thing is correct and the four neighbours are cheap reports, but **do not discover the
wall clock at the end of a shift.**

While iterating, run the single test —
`--test balance the_shipping_configuration_produces_a_fight -- --ignored --nocapture` — and
keep the full command for the final proof. **And the idle box is a precondition on validity here, not hygiene.** The entire diagnosis is
a **6/8-vs-7/8 distinction — one seed.** A run taken with a vite or a `cargo run` alive cannot
separate erosion from load, on the instrument whose whole defect is that a one-seed margin was
a coin flip. Sweep for `cargo|rustc|node|vite|game-server` **and** read `uptime` before each
run.

That implies criterion 1 from the other direction: **the replacement control needs enough
margin that box load cannot flip it.** If a plausible amount of load could change the answer,
the gap is still marginal and you have rebuilt the same test.
