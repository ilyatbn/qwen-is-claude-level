# T20.18 — Seven copies of `connect` (v8)

Milestone: M20 · Depends on: nothing · Size: small

**Booked from T20.10's handoff**, which named `tests/common` as the durable fix and correctly
declined to widen into it mid-task.

## What was seen

Seven `game-server` integration tests carry their own copy of a socket `connect` helper.
T20.10 needed `emit_when_ready` retry behaviour in one of them and had to choose between
fixing one copy or seven.

## Deliverable — and it is three duplicated fixtures, not one

One shared module in `crates/game-server/tests/common/`. **Share the function, not the guard**
— the point is that the next fix lands once.

**`connect` is not the only one, and consolidating it alone leaves the other two to drift:**

- **`connect`** — seven copies.
- **`test_config()`** — **eight** copies, counted directly rather than from a filtered
  listing: `checksum.rs`, `in_progress.rs`, `integration.rs`, `join.rs`, `lobby.rs`,
  `room.rs`, `room_logging.rs`, `rooms.rs`. **`room.rs` is where T20.20's `fixed_seed: None`
  lives**, so that file is not optional.
  *(An earlier draft said five. The count came from a `grep | head -12` read as the whole
  set — `ls | tail` in other clothes. Verify with `grep -rln "fn test_config" crates/game-server/ | wc -l`,
  not with a filtered listing.)*
- **`BUDGET_MS`** — three copies, and **each is exactly a shipped constant** (10_000 against
  `LOBBY_BOT_TIMEOUT`/`WARMUP_SECONDS`; 30_000 against `READY_TIMEOUT_SECS`/`ROOM_EMPTY_TTL`).
  See T20.20. **Do not consolidate these to a shared literal — pin them to something that is
  not a state-transition boundary**, or you will have centralised the bug.

## Notes

- T20.10's `emit_when_ready` **retries any `Err`**, not the `IllegalActionBeforeOpen` it was
  diagnosed for. It weakens nothing (`wait_for("welcome")` keeps its own deadline, and it
  panics with the original error after `EMIT_READY_WINDOW`), but a genuinely refused emit now
  costs 5 s before it says so. **Narrow it while consolidating**, or state why not.
- Check the seven copies actually agree before merging them. If two have drifted, the
  difference is a finding — say which behaviour won and why.

## Tests

- The seven suites still pass, and a deliberate break in the shared helper reds **all** of
  them — otherwise "shared" is a claim rather than a fact.

## The duplication and T20.20's missing seed are one fact seen from two sides

Found while re-validating T20.20, and it changes what consolidating `test_config` is *for*.

**The eight files that share a fixture all inherit `fixed_seed: None`.** Verified per body,
not by a file-wide grep: `awk '/fn test_config/,/^}/' <file> | grep -c fixed_seed` returns
**0** for all eight — `lobby`, `join`, `in_progress`, `integration`, `room_logging`,
`checksum`, `rooms`, `room`. The `None` arrives through `..Config::default()`.

**The files that pin a seed are exactly the files with no shared fixture.**
`replay.rs:65,317,395,552` set `fixed_seed: Some(4242)`; `replay_run.rs:52,661` set
`Some(90210)` and `Some(31337)` — and **neither file defines a `test_config` at all**. They
pin inline at the call site, which is why they never needed one.

So this is not two problems. **The fixture is the thing that made the seed invisible**: eight
copies of a config nobody reads end-to-end, each inheriting a default that decides map layout,
and the one property a determinism-critical fixture must state is the one property none of
them states. T20.20's flake is the first bill; `commands_sent_between_ticks_are_all_applied`
fails when the seed happens to spawn a player against the right wall.

**What this adds to the task:** whatever shape the shared `test_config` takes, it must make
the seed an explicit, visible decision rather than an inherited default — and the six
`replay*` sites are working prior art for the idiom, in-tree. Copy their shape rather than
inventing one. This does **not** soften the warning above about `BUDGET_MS`: the seed should
be centralised, the timeout budgets should not, and the difference is that a seed's job is to
be identical everywhere while a budget's job is to be unlike the constant it waits on.

## Done when

**The gate below cannot see the requirement this task just gained**, so it is not sufficient
on its own. A consolidation producing one `test_config` that still inherits
`fixed_seed: None` passes `cargo test` and `check.sh` exactly as the eight copies do — the
seed decides map layout, and nothing in either command asserts that the decision was made.
That is the shape this repository keeps paying for: a criterion checked by something that
cannot report its violation. So run both, and both must pass:

```sh
# 1. the repository still works
cargo test -p game-server && ./scripts/check.sh

# 2. the seed is stated, not inherited — read the fixture body, not the file
#    (a file-wide `grep fixed_seed tests/` answers a different question and returns 6
#     from replay*.rs even when every fixture still inherits None)
for f in $(grep -rl 'fn test_config' crates/game-server/ --include=*.rs); do
  printf '%s %s\n' "$(awk '/fn test_config/,/^}/' "$f" | grep -c fixed_seed)" "$f"
done
```

Every line of (2) must start with a non-zero count. It reads **0** for all eight today, which
is the control: run it before you change anything and watch it be zero, or you cannot tell a
fixture that states its seed from one that merely compiles.

> **THE DONE-WHEN ABOVE WAS A TRAP AND IS SUPERSEDED. Recorded, not quietly deleted.**
>
> Command (2) greps each `test_config` body for `fixed_seed`. It was red before the work — 0 for
> all eight — which is what a control should be. **But it is also red after the correct fix**:
> once the eight delegate to `common::test_config`, the seed is one hop away and the grep reads
> 0 for all nine. A criterion the task's own deliverable makes unsatisfiable is not a control,
> it is a trap, and it would have pushed a builder to keep the duplication in order to pass it.
>
> **Red-before-the-work is necessary and not sufficient. Ask also what turns it green, and check
> that the intended fix is the thing that does.**
>
> Superseded by `common::assert_seed_is_stated`, a runtime guard on the config each fixture
> actually builds — 9 call sites, all red on one break in the shared fixture, all green when
> restored. **A guard that runs beats a grep that reads**: it survives the refactor the grep
> could not, because it asserts on the value rather than on the text that produces it.
>
> Reported by the builder rather than edited around, which is what `CLAUDE.md` asks for.
