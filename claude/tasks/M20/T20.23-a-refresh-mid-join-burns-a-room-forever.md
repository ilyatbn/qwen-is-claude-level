# T20.23 — A refresh mid-join burns a room forever (v8)

Milestone: M20 · Depends on: nothing · Size: small fix

**Found by T20.14's load driver.** Booked, not fixed there.

## Reproduce

```sh
cargo run -p game-server --example loadgen -- --scenario ghost
```

Measured at HEAD, 4 sockets per arm:

```
after the control arm           room 1..4: humans=0 private=true roster=[]
after the mid-handshake drops   room 1..4: humans=0 private=true roster=[]
                                room 5: humans=1 private=true roster=["G000"]
                                room 6: humans=1 private=true roster=["G001"]
                                room 7: humans=1 private=true roster=["G002"]
                                room 8: humans=1 private=true roster=["G003"]
reap past the TTL freed 4 room(s), 4 left
```

**4 of 4 against a control of 0 of 4.** The control arm is the same clients doing the same
`create_room` and disconnecting *after* their `welcome`; every one of their rooms returns to
`humans=0` and is reaped. Each client hosts its own private room, so the two arms cannot
contaminate each other — the first cut used `quick_match`, both arms landed in one lobby, and
the scenario correctly refused to conclude anything.

## The mechanism

`session.rs`'s `on_disconnect` calls `ctx.detach` **inside** the `if let`:

```rust
if let Some(id) = sessions.remove_sid(socket.id) {
    room.send(Command::Leave(id));
    ...
    ctx.detach(socket.id);
}
```

and `session.rs::seat` inserts into that map only *after* the room task has answered:

```rust
let Some(id) = room.join(name.clone(), look).await else { ... };
sessions.insert(id, socket.id);
ctx.attach(socket.id, room_id);
```

Every verb calls `ctx.attach` **before** `seat`. So between the attach and that `insert`
there is a full command round-trip through a task ticking at `SIM_HZ` — and a socket that
drops inside it is attached to a room that has no record of it. `remove_sid` answers `None`,
the whole block is skipped, and nothing ever decrements `RoomEntry::humans`.

**A room whose `humans` never reaches zero never gets an `empty_since`**, and
`registry.rs::reap` filters on exactly that field. The room ticks forever.

The comment above `seat`'s §E4 refusal already states the invariant this breaks — *"every
verb attaches before reaching here, so a refusal that does not detach leaves the registry
counting a player who was turned away"* — and adds `ctx.detach` at three of `seat`'s early
returns. The disconnect path is the fourth exit from the same window and has no such line.

## Why it matters more than it looks

`MAX_ROOMS` is **32**. Each burnt room is a permanent subtraction from the whole process's
capacity, recovered only by a restart, and the trigger is a page refresh at the wrong
half-second. T20.14's 48-client soak reached `32/32` rooms and **8367 `server_full`
refusals out of 10634 join attempts**, with rooms averaging under two players.

## Not to be confused with

`T20.22`, which orphans the *seat* while `humans` stays correct. This one leaks `humans`
while the seat may or may not exist. Fixing either leaves the other.

## Notes

- ~~The obvious shape — `ctx.detach(socket.id)` unconditionally in `on_disconnect`~~ —
  **MEASURED AND DISPROVED 2026-09-07, before it was built. It still reports 4/4.** Kept
  struck through rather than deleted, because it is the first thing anyone will think of.
  **Why it cannot work:** the window is not "the handler finds nothing". `seat` is *still
  awaiting* `room.join` while the disconnect handler runs to completion, so when that await
  returns, `seat`'s own `sessions.insert` and `ctx.attach` **put back everything the handler
  just took away**. A resurrection *after* the cleanup — the same await-gap shape as T19.21,
  where a fact read before an await is acted on after it.
  So the remedy is a **second caller, not a bigger first one**: one function freeing seat,
  session row and registry count, called by the handler *and* by `seat` itself immediately
  after its insert when `socket.connected()` is false. The two compose over the whole window —
  a drop before the insert caught by `seat`, a drop after it by the handler — and they are
  idempotent where they overlap. Checking *after* the insert is deliberate: from that line the
  handler can find the socket itself, so `seat`'s check only has to cover the window that just
  closed.
  **The `leave_room` parity hoist is real but unprotected**: putting the detach back inside its
  `if let` leaves the suite green. No test covers it; that is recorded at the line.
- **Falsify the fix at the live binding site**: the regression test must go red with the new
  detach removed, not merely green with it present.

## Done when

A regression test in `crates/game-server/tests/` attaches a socket, drops it before `seat`
completes, and asserts the room reaps — **with the control arm in the same test**, or the
assertion is satisfied by a server that reaps everything.

```sh
cargo test -p game-server && ./scripts/check.sh
```
