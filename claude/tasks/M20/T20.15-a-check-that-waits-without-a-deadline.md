# T20.15 — A browser check that waits without a deadline (v8)

Milestone: M20 · Depends on: nothing · Size: tiny, but read why it matters

**Found by T20.01's coder**, pre-existing and not caused by it.

## What was seen

`scripts/checks/lobby-start.mjs:201` reads `constants().LOBBY_BOT_TIMEOUT` and uses it to
build a `waitForFunction` timeout. **`LOBBY_BOT_TIMEOUT` is not in `constants_json`.** So the
read is `undefined`, the arithmetic is `NaN`, and the wait has **no deadline**.

## Why it is worth a task

This is `CLAUDE.md`'s *"an assertion on a field that does not exist cannot fail —
`undefined <= undefined` is false forever"*, in its other form: a **wait** built on a missing
field cannot time out. The check does not fail loudly when the thing it waits for never
happens; it waits, and something further up eventually kills it, and the failure is reported
as whatever that is.

It is also the second instrument defect found in this one check — see T20.01's journal for
the first, where `lobby-start` was passing while the only human had been swept out of the
match.

## Deliverable

- Either expose `LOBBY_BOT_TIMEOUT` through `constants_json` (the four-place treatment:
  `constants.rs`, `game-wasm`'s table, the `Constants` interface, the use site), or derive
  the deadline from something that exists.
- **Grep for the same shape elsewhere.** Any `constants().X` in `scripts/` where `X` is not
  in `constants_json` has this bug. That grep is the real deliverable; the one known site is
  the example.

## Tests

- The wait fails **loudly and on time** when the condition never becomes true — assert on the
  timeout itself, with a control that it still passes when the condition does become true.
- A guard that a `constants()` read which comes back `undefined` is an error rather than a
  silent `NaN`. Without it this recurs the next time somebody adds a constant to one side.

## Done when

```sh
node scripts/e2e.mjs lobby-start && ./scripts/check.sh
```
