# T20.07 — The flashlight is wired to nothing, and the new one is passive (v8)

Milestone: M20 · Depends on: nothing · Size: large — read the dead ends first

**This reverses a design `docs/72` §C13 specifies.** Today the flashlight *shrinks* ambient
sight and buys a cone; the wanted behaviour is the opposite. **Flag the conflict and
proceed** — the coordinator asked for the new behaviour explicitly, and this file records
what it overrides.

Wanted: *"when picked up, it increases your view/light radius by 50 % at night and makes the
heavy fog background 20 % more visible. It doesn't have to be the active item, just in the
inventory. It doesn't take energy."*

## Read first
- `crates/game-core/src/world/cycle.rs:83-93` — `fov_radius`, and `constants.rs:173-181`
- `client/src/render/lightmap-math.ts:42-50` — `fovRadius`, the **live** copy
- `client/src/render/weather-math.ts:181-183`, `client/src/render/weather.ts:138-151`

## The headline: the flashlight currently does nothing at all

Four separate "built and wired to nothing" defects sit on this path. **Fix them or the
change is invisible:**

1. `GameScene.ts:1484` and `:1552` both hardcode **`flashlightOn: false`** (and
   `health: BASE_HEALTH`). The client never asks whether the light is on.
2. `FLAG.flashlight` (`client/src/net/codec.ts:300`) has **no production reader** — only
   two test references.
3. `collectLightSources` (`lightmap-math.ts:120-181`), where the cone and remote cones are
   built, has **no production caller** — `GameScene.ts:1497-1510` builds `lights` by hand.
   This is the same defect **T19.20** books for the hazard path; coordinate, do not
   duplicate.
4. `Connection.sendToggleFlashlight` has **no caller**; `GameScene.ts:837` binds `keydown-F`
   to `sendFire()`. `button::FLASHLIGHT` and `flashlight_pressed` have **no server
   consumer**. The only live route is `G` → `use_item`.

## Which side owns the radius: the client

`game_core::world::cycle::fov_radius` has **no production caller** — only the wasm bridge,
used by a test to pin the TS copy. The real radius is `lightmap-math.ts:42` (`fovRadius`),
called from `GameScene.ts:1480-1485` and `:1548-1553`. The server *does* own the fog
number: `vision_multiplier` quantised to a byte at `codec.rs:312`.

## Deliverable

- **Held anywhere in the inventory**, not toggled and not the active slot. `flashlight_on`
  changes meaning from "toggled on" to "carries one".
- **+50 % radius at night**, gated on `night > 0` — a new constant replacing
  `FLASHLIGHT_AMBIENT_MULT`'s 0.65. **Both copies move together**: `cycle.rs:83` and
  `lightmap-math.ts:42` are pinned to each other by `lightmap-math.test.ts:227-240`.
- **Fog veil 20 % more visible.** Note this is a *second* number in a *different* place:
  `FOG_SCREEN_ALPHA` → `fogVeilAlpha` → `drawFog`, all client-side (T19.10's work), and
  `drawFog` takes only `strength` — it has no idea who holds what. Either `fogVeilAlpha`
  grows an argument or `GameScene` scales `strength` before passing it. **Pick one and say
  which; do not do both.**
- The client must learn who carries one: redefine wire flag bit 4 (`codec.rs:284`) from
  `flashlight_on` to "carries a flashlight", and read it at `GameScene.ts:1484/1552`.
- "Costs no energy" is **already true** — a Utility use touches neither battery nor stack.

## Tests that assert the opposite — these must be replaced, not deleted

- `lightmap-math.test.ts:63-68` — *"shrinks ambient sight when the flashlight is on"*,
  `on ≈ off × FLASHLIGHT_AMBIENT_MULT`. **Directly contradicts the new design.**
- `lightmap-math.test.ts:148-153` — *"it is a trade"*. Same.
- `:137-145` and `:157-170` — the cone and remote cones. **If the cone goes, decide
  deliberately**; it is a design change beyond the brief, so say so rather than deleting it
  in passing.
- `cycle.rs:199-215`; `combat.rs:1113-1126 the_flashlight_toggles_without_being_consumed`
  and `:1053`; `codec.rs:841,891,907,918`; `localInput-math.test.ts:34,52`.
- `replay.rs` tag 7 `ToggleFlashlight` — retiring the command is a `REPLAY_VERSION`
  decision (currently 4).

## Tests

- The veil is measurably lighter with one held: **rendered pixels**, control region, control
  frame.
- Falsify at the live binding site: put `flashlightOn: false` back and it goes red.
