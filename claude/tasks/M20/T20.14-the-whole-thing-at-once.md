# T20.14 — The whole thing at once: an exploratory load test (v8)

Milestone: M20 · Depends on: nothing · Size: **large, and open-ended by design**

Asked for directly: *"a very large simulation of some kind where many players attempt to
join several matches, have multiple matches running at the same time, some quit, some
choose to stay, some randomly do new private matches. I'm not sure this is even doable by
you. It's like an exploratory load test of everything at once to find bugs and
bottlenecks."*

**This task is not a fix. Its deliverable is findings**, and "found nothing" is a real
result if the instrument is shown to be capable of finding something.

## Read first
- `crates/game-server/tests/rooms.rs` — the existing multi-room server tests
- `crates/game-server/src/registry.rs` — `quick_match`, `create`, `reap`, `MAX_ROOMS = 32`
- `scripts/checks/harness.mjs`, `scripts/checks/e2e-two-clients.mjs` — the two-client shape
- `tasks/HANDOFF-M19.md` — the section on instruments, and the one on the retired flake
  hypothesis

## What to build

A driver that runs **many simulated clients against one server** and makes them behave like
people: join quick matches, host private ones, leave mid-round, vote to replay, exit to
title and immediately quick-match again, refresh, and idle in a lobby past
`READY_TIMEOUT_SECS`. Several matches live at once, up to and past `MAX_ROOMS`.

**Socket-level clients, not browsers.** Thirty Chromium instances measure the box, not the
server. `tests/rooms.rs` already drives real sessions in-process; that is the cheaper and
more honest instrument. If a browser is genuinely needed for something, say why.

**It must be deterministic enough to re-run.** A seeded scenario script that replays the
same sequence of joins, leaves and votes, so a failure can be reproduced rather than
described.

## What to look for — start here, but the point is to look

- **T20.13's split**: a replay vote plus a quick match yielding two rooms, one of which
  never starts. Reproduce it if you can; that alone justifies the task.
- The **T20.01** sweep: a lobby host swept at 30 s with nobody told.
- Room accounting: does `humans` ever drift from the truth? Does a room leak past `reap`?
  Does `MAX_ROOMS` behave at the boundary?
- Seat-id recycling: `Seats::free` + `SessionMap::insert` evicting by `*p != player` is a
  known-sharp edge (see T20.01).
- **Bottlenecks, not just bugs**: where does wall-clock go with 8 rooms live? Is any
  per-tick cost O(rooms²)?

## Notes

- **This is the instrument, so be hardest on the instrument.** M19 recorded **eight**
  cases where the measurement was the bug and not one was caught by a test going red. A load
  test that reports "no failures" while quietly failing to connect its clients is that
  pattern in its purest form. **Build a control first**: a scenario with a *known* fault that
  the harness detects. If it cannot catch a planted bug, its clean runs mean nothing.
- **Kill process groups**, and give every background process its own ceiling
  (`timeout --signal=KILL`). A leaked load generator saturated this machine for 3h47m in M19
  and silently confounded every measurement taken during it.
- **Check the box is idle before and for leaks after** — sweep for
  `cargo|rustc|node|vite|game-server`, and read `uptime`'s load, which has read 2.96 while
  the process table looked clean.
- Do not add anything to a known-flaky list. If this test is itself flaky, that is a finding
  about the test.

## Deliverable

- The driver, checked in and runnable, **not** wired into `check.sh` by default — it is an
  exploratory tool, and a 30-room run has no place in a gate that must stay fast and
  deterministic. Say how to run it.
- A **written report** of what was found: each finding with a reproduction, each booked as
  its own task rather than fixed here. Fixing anything inside this task hides the finding.
- Honest limits: what the driver does **not** simulate.

## Done when

```sh
# the driver runs its seeded scenario to completion, and the planted-fault
# control is detected; then:
./scripts/check.sh
```
