## Notes

- **Every broadcast is scoped to the socket.io room `room:<id>`.** A broadcast
  reaching another game is the multi-room form of the inventory leak in
  `docs/30` §6 — and is tested the same way, by asserting the negative.
- **Never iterate the registry to produce game output** (§A11 — `HashMap` order is
  randomly seeded per process). Lookup only. If something needs ordering, keep an
  explicit `Vec`.
- A room stops ticking as soon as its last **human** leaves, and is dropped after
  `ROOM_EMPTY_TTL`. Bots do not keep a room alive.
- Join codes exclude `I`, `1`, `O`, `0` — people read these aloud.
- The room task already owns its `World` outright; this task must not introduce a
  `Mutex` over game state (`docs/41` §1).

## Tests

- Two rooms run concurrently with different seeds; a carve in one does **not**
  appear in the other's mask — assert the checksum, not just an event count.
- **Negative:** a client in room A never receives any event emitted in room B.
  Falsify by removing the scoping and confirm it fires.
- A code round-trips; an unknown code gives `join_error`; codes are unique across
  200 creations and contain no ambiguous characters.
- The last human leaving stops the tick; the room is gone after the TTL; a room
  with only bots does not survive it.
- `MAX_ROOMS` refuses creation with a clear reason rather than panicking.
- 100 concurrent create/join/leave operations leave no orphaned room and no leaked
  task (assert the task count).
