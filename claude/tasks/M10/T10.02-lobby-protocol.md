## Deliverable

The §B9 message set: `create_room`, `join_room`, `quick_match`, `leave_room`,
`room_created`, `room_list`. `join` gains `tombstone_skin_id`.

## Notes

- Quick match fills the **fullest room that still has space**, so games start
  sooner and half-empty rooms drain rather than multiply.
- **There is no queue** (§B10). Filling the fullest room with space, plus
  `MIN_PLAYERS_TO_START = 1` and bots from the start, already gives the queue's
  outcome with no waiting state to be stuck in.
- A client must be able to leave and join another room without reconnecting the
  socket; `leave_room` unsubscribes it from `room:<id>`.
- **Fuzz every new decoder** (`docs/60` §3). These parse attacker-controlled input
  and a panic is a remote crash. A join code is attacker-controlled text.

## Tests

- Create → `room_created` with a code → a second client joins by that code and both
  are in the same room, verified by receiving the *same* `map_init` seed.
- Quick match with two waiting clients seats them **together**, not in two rooms.
- Quick match alone seats immediately into a room with bots — nobody waits.
- `room_list` reports players, capacity and bots (§B10), not an ETA.
- `leave_room` then `join_room` on the same socket works, and the client receives no
  further events from the old room — the negative, with a control proving events
  from the *new* room do arrive.
- Malformed and hostile codes (empty, 200 chars, control bytes, valid-looking but
  unknown) are rejected without a panic.
