# T10.03 — Title screen with a live attract mode

Milestone: M10 · Depends on: T6.14 · Size: ~220 lines

## Read first
- `docs/71-amendments-v3.md` §B3

## Touch only
- `client/src/scenes/TitleScene.ts`
- `client/src/ui/title.css` (or the existing DOM UI module)
- `client/src/main.ts` (scene registration, initial scene)

## Deliverable

The game's name, a **Start Game** button, and behind them a live attract mode: a
real generated map with **bots fighting each other**, running entirely client-side
in WASM against `game-core` — no server involved.

## Notes

- Reuse the bot controller (T6.14) and the sandbox's local stepping. This costs the
  server nothing and cannot fail because a server is down.
- It doubles as a continuous smoke test of the simulation that anyone can see: if
  the title screen is wrong, something in `game-core` is wrong.
- Pick a fresh seed each visit, and a random theme, so it does not look like a
  static image. Regenerate every `ATTRACT_ROUND_SECONDS` rather than running one
  map forever.
- The camera should follow the action — the bot with the most recent damage event
  is a cheap and good heuristic.
- **Do not let it eat the frame budget**: it is a background. Cap its sim rate and
  stop it entirely when the scene is not visible. Assert that stopping actually
  stops it (§A15 — assert the effect, not the intent).
- Keyboard reachable: `Enter` starts, `Esc` does nothing here (it is the root).

## Tests

- Headless: the title renders, the canvas is not a flat colour, and after 5 s the
  bots' positions have changed (assert displacement, not that a tick ran).
- Leaving the scene stops the simulation — assert zero ticks after the transition.
- Two visits produce different seeds.

node scripts/e2e.mjs title
