# T19.25 — `rematch`'s closing window needs real-time in two browsers (v7)

Milestone: M19 · Depends on: nothing · Size: unknown — **measure before designing**

**Booked from T19.20's gate work, with a rate rather than an anecdote.**

## What was measured

`rematch`'s final assertion drives **two Chromium instances at once**, walks both players right
for ~600 ms, and compares pixels. On an idle box it failed **1 run in 3**, caught by its own
control:

```
FAIL: the CONTROL frame is frozen too (delta 0.0) — the box stalled, so the leaver's
frame proves nothing
```

## The control is right; the structure is what is fragile

**Do not weaken that control.** It is doing exactly the job a control exists for — refusing to
conclude anything from a frame that never moved. Without it, a stalled box would have produced
a confident pass.

The problem is that when it fires, the check reports **red** rather than **inconclusive**, so a
box that stalled reads identically to a game that broke. `CLAUDE.md`: *a gate that fails on a
coin flip gates nothing* — and this one fails on load it cannot control, because two live
browsers rendering simultaneously is the measurement.

## Deliverable — measure first, then choose

Report the achieved frame cadence in both instances, idle versus loaded, before designing
anything. Only then choose, and say why:

- a longer window, so a stall is absorbed rather than fatal;
- a cheaper comparison than a two-browser pixel walk;
- or **separating "the box stalled" from "the game is wrong"** — an inconclusive verdict that
  retries rather than reddening the gate.

The third is the honest shape if the cadence turns out to be unattainable under a normal gate
load, but **do not pick it to make the red go away**: an inconclusive that fires often is a
check nobody reads.

## Tests

- Whatever lands, **the leaver-still-rendering claim survives unweakened** — that is what this
  check exists for, and it is the half a rematch bug would break.
- Any new bound is justified in a comment by a **measured** number, not the number that made it
  pass.
- Run it 5 consecutive times **inside a full suite**, not standalone. Standalone is the
  condition under which it already passes.

> **RECURRENCE AFTER THE FIX, recorded 2026-09-08 — read this before trusting the 5/5.**
>
> `rematch` fired its own stall detector again — *"the CONTROL frame is frozen too (delta
> 0.0)"* — in a full gate **after** this task was ticked. It passed 3/3 standalone immediately

> conclude. The 5/5 stands as recorded; it was five gates, not a proof of impossibility.
>
> **This is the inconclusive-versus-red question this task decided not to take**, and it is now

> this: a stalled box must report **inconclusive**, not red, so a killed measurement stops
