## Deliverable

Two independent failures that make `npm --prefix client test` unreliable. Neither is
caused by any M19 change; both were observed while landing T19.03.

- **`node scripts/wasm-build.mjs` fails on roughly alternate runs** with
  `invalid type: sequence, expected a string at line 7 column 11`. Every client test hook
  runs it first, so **the whole client suite is a coin flip**. Deleting the generated
  `pkg/package.json` beforehand changes nothing — that was tried and reverted rather than
  left in as a speculative fix. Find the actual cause. A build step that fails half the
  time is worse than one that fails always, because it teaches everyone to re-run.
- **`backdrop-real` times out at `Test timed out in 5000ms`** on a loaded box: 11 tests
  taking 5–32 s each against a 5 s budget. Confirmed identical at HEAD with M19 stashed.
  Either the budget is wrong for what these tests do, or the tests are doing too much per
  case. Decide which, with the measurement in hand.

- **`hud-timer` fails on load too**: +38.4 of redness against a +40 threshold in a full
  suite, +45.4 passing alone. Same family, same task. A threshold that is only met on an
  idle box is a threshold measured on an idle box.

## Notes

- **A gate that fails on a coin flip gates nothing** (`CLAUDE.md`). This is that rule
  applied to the gate's own machinery rather than to a test.
- Do not "fix" either by widening a timeout without first measuring what the time is spent
  on. If 32 s is legitimate work, the budget is the bug; if it is not, the budget is
  hiding the bug.
- The wasm error names a **line and column in a JSON document**. Print the document it is
  actually parsing before theorising — a generated file read while it is being written
  looks exactly like this, and so does a stale one.
- Interleave anything you measure across commits (D-65).
- **`backdrop-real` was green in T19.02's and T19.03's gates and is now red running
  alone on an idle box.** That is the most informative fact anyone has about it: the cause
  is drift on this machine, not a slow test that finally tipped over. Find what changed
  before assuming the budget is wrong.
- Three of the last four gate runs have carried a non-deterministic red. That is the
  argument for doing this task **before** the remaining feature work rather than after:
  every red from here on costs a human judgement about whether it is real, and D-65 is
  what happens when that judgement is made from a confounded measurement.
