# T19.18 — The lobby client never learns its inventory (found by T19.05)

Milestone: M19 · Depends on: nothing · Size: unknown until it is diagnosed

## What was seen

`GameScene.slots` is filled **only** by the server's `inventory` event
(`client/src/scenes/GameScene.ts:486`). For a client that reaches a match through the
**menu into a private lobby** — rather than through `enterBattle` — that event never
arrives.

Measured three times, most recently with a probe on both clients at once:

```
PROBE after 30.2s host slots = (nothing)
PROBE guest slots = (nothing)
```

— in a live match, with `DEV_LOADOUT=1`, while the round ticked at 60 Hz and every other
assertion in `m10-checkpoint` passed. The **server** has the loadout: the same check fires
and the terrain changes (`m10-checkpoint.mjs:203`, `ah.solid < dh.solid`). Only the client
never hears about it.

## Why it matters beyond one check

`harness.mjs::selectWeapon` reads exactly that array, so **no browser check that enters
through the menu can select a weapon by name**. `m10-checkpoint` presses `Digit2` for that
reason and says so at the call site. Every other check hides the bug because `enterBattle`
seats them another way.

It is also a real player-facing gap: a host who starts a private game has a quick bar the
client cannot render from, until something else forces an `inventory` event.

## Where to start

`events.rs` decides delivery scoping and T9.08 added "a joiner receives its own inventory
on join". `grant_dev_loadout` runs in `populate_world` at match start; `GameScene` is
constructed on `map_init`. The likely window is the event being emitted before that
client's scene exists to receive it — which is the shape `GameScene.ts:330-338` already
documents for snapshots and solves with `pendingSnapshot`.

Reproduce by adding a `waitForFunction` on `window.__game.debug().slots` to
`m10-checkpoint`, which is what produced the numbers above.

## Done when

A client that enters through the menu holds the same `slots` a client that entered through
`enterBattle` does, asserted at both ends, and `m10-checkpoint` can select by name.
