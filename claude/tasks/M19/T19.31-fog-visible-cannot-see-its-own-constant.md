# T19.31 — `fog-visible` is blind to `FLASHLIGHT_FOG_VEIL_MULT`, in two places (v7)

Milestone: M19 · Depends on: nothing · Size: small — **and it is T19.27's twin**

**Found by T19.27's prescribed sweep**, which asked for the shape rather than the instance: a
browser check that computes its expectation from the constant it is testing, and therefore
passes with the feature switched off.

**The sweep's result is the useful half: exactly one live instance, not a milestone.** Every
other `k.<CONST>`-derived expectation in `scripts/checks/*.mjs` and `e2e-two-clients.mjs` was
checked and is already guarded. Three near-misses are recorded at the foot of this file so
nobody re-checks them.

## The defect

`scripts/checks/fog-visible.mjs` is blind in **two places at once**, both on
`FLASHLIGHT_FOG_VEIL_MULT`:

```js
const want = k.FOG_SCREEN_ALPHA * lit.s * k.FLASHLIGHT_FOG_VEIL_MULT
// at 1.0 this is the unlit veil — exactly what `lit.a` would read anyway

const predictedGap = toClearFog * (1 - k.FLASHLIGHT_FOG_VEIL_MULT)
// at 1.0 this is 0, and the measured gap is ~0 too, so
// `|gap − predictedGap| > max(6, noise)` never fires
```

**Setting `FLASHLIGHT_FOG_VEIL_MULT = 1.0` — switching the feature off — should pass the whole
check.** The existing `toClearLit < noiseFloor` guard covers the *opposite* end (a flashlight
that removes the veil entirely), so there is a lower bound and no "strictly thinner" claim.

## Fix it the way T19.27 was fixed

**Keep the pinned assertions and add a structural one beside them.** T19.27 chose structural
over a basis pin deliberately — *a basis pin still agrees with a scene drawing the constant
twice* — and the same reasoning applies here. The claim the feature actually makes is that a
carried flashlight leaves the fog **strictly thinner** than no flashlight, which needs no number
and reds the moment the multiplier reaches 1.0.

**Falsify by neutralising the constant, not by breaking the code**: set
`FLASHLIGHT_FOG_VEIL_MULT = 1.0` and the check must go red. That is the exact case that passes
today. Then break the implementation and confirm the *pinned* assertion still fires — both
halves, two different failures.

**`night-combat` and this are one pair.** `night-combat.mjs`'s own comment names `fog-visible`
as the `GameScene` half of the same falsification pair, and T19.27 fixed the other half. They
want the same answer.
