# T19.08 — The private lobby's settings panel (v7)

Milestone: M19 · Depends on: T19.07 · Size: ~200 lines

## Deliverable

The three settings on the private lobby screen, in the shape map size already has:

- **Bots**: Enabled / Disabled.
- **Starting weapons**: None / Basic / All.
- **Timer**: minutes, stepping by `ROUND_SECONDS_STEP` between `ROUND_SECONDS_MIN` and
  `ROUND_SECONDS_MAX`, ends disabled at each bound.
- Every control is **disabled for a non-host** and enabled for the host, exactly as the
  map-size arrows are.
- The panel renders the values from `lobby_state`, so a guest sees the host's changes,
  and a change clearing the ready flags is visible in the roster.

## Notes

- These come off the wire, not from `localStorage`. Map size is remembered locally
  because it is also a main-menu preference; these three are not — a stale local timer
  overriding a lobby the player just joined is the bug this avoids.
- Show the timer in **minutes** and store seconds. One conversion, at the edge.
- Public lobbies show no panel at all (§F7). Assert that, or the panel appears in a place
  where every control would be refused.
- vitest is `environment: 'node'` with no canvas: a green unit run proves the reducer and
  says nothing about whether a control appears (D-26). The e2e half is not optional.

## Tests

- Unit: each setting's step function respects its bounds and step; the timer cannot leave
  `[MIN, MAX]`; the enum settings wrap or stop, whichever the map-size control does.
- Unit: the reducer applies a `lobby_state` carrying all three, and tolerates one that
  carries none (an older server).
- Unit: `canChangeSettings` gates all three, not just scale.
- e2e (extends `lobby`): host a private game, change all three, read the values back off
  **the screen**; a second browser joined to the code sees them change and finds its own
  controls disabled.
- e2e: a change clears the ready ticks in the roster.
