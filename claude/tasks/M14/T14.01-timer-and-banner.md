# T14.01 — The round timer and the event banner (v4)

Milestone: M14 · Depends on: T13.01 · Size: ~150 lines

## Read first
- `docs/72-amendments-v4.md` §C8

## Deliverable

- **Round timer, top-right, large and bold**, in a real display face — condensed bold
  or a mono. It turns **red** below `TIMER_WARN_SECONDS` (60).
- **Event banner, top-centre, large, red**: the active effect's name and its
  remaining time, shown during **telegraph and active**. The telegraph is the warning
  (`docs/13` §2) — three seconds is meant to be enough to get out of the open, and it
  only works if it is on screen.

## Touch only
- `client/src/ui/hud.ts` (+ test), `assets/fonts/`
- `crates/game-core/src/constants.rs` (`TIMER_WARN_SECONDS`)

## Notes

- **Ship the font with the game.** A runtime fetch fails offline and the game must
  start with no network (`docs/51` §5).
- The timer is driven by the server's round time from the snapshot, not a local
  stopwatch — a local one drifts, which is why §B4 made the death countdown
  server-driven.
- The banner needs the effect's **duration** to count down; `effect_start` carries it
  (`docs/40` §3).

## Tests

- The timer matches the server's round time within a tick.
- It is red below 60 s and not at 61 — assert both sides of the boundary.
- The banner appears on `effect_start`, counts down, and clears on `effect_end`; a
  control asserts it is absent with no effect running.
- **Rendered, not just present in the DOM** (§C2) — a hidden element is not a HUD.

## Done when

```sh
npm --prefix client test -- --run hud && node scripts/e2e.mjs hud-timer
```
