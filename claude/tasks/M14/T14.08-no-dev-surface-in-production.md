# T14.08 — The dev surface is compiled out (v4)

Milestone: M14 · Depends on: T14.07 · Size: ~150 lines

## Read first
- `docs/72-amendments-v4.md` §C17
- `docs/60-testing.md` §5 (which kept the sandbox in the build — now reversed)

## The problem, measured

Anyone can type `?sandbox=1` or `?e2e=1` and get a different game. The shipped
bundle contains `__game` (×3), `sandbox` (×2), `toggleOverlays` and `regenerate`,
and `import.meta.env` appears nowhere in the source — nothing is gated at build
time.

## Touch only
- `client/src/main.ts`, `client/vite.config.ts`
- the scenes that expose `window.__game`
- `scripts/checks/no-dev-surface.mjs` (new)
- `scripts/e2e.mjs`

## Deliverable

Wrap the dev surface in `if (import.meta.env.DEV)` (or a `__DEV__` define) so Vite
dead-code eliminates it: the dev scenes, every scene-selection query parameter,
`window.__game`, the debug overlays, the aim ring and direction line, the FPS
counter.

`vite build --mode e2e` re-enables the handle for a check that must drive a
production bundle. Plain `vite build` has none of it.

## Notes

- **Removal, not a runtime flag** (§C17). A server toggle still ships the code, so a
  modified client flips it back; and it needs a message, server state and a round
  trip that removal does not.
- Do not break the e2e suite: it drives the **dev server**, where `DEV` is true, so
  it keeps working unchanged. Verify that before changing anything, rather than
  assuming.
- Keep `Esc`, the HUD and the inventory — they are player features, not debug.
- Server-side dev flags (`DEV_LOADOUT`, `FIXED_SEED`, `RECORD_REPLAY`, `DEBUG_DUMP`)
  are environment variables a client cannot set. Leave them alone.

## Tests

- **Grep the built artifact** (§A15 applied to a build): a default `vite build`
  bundle contains none of `__game`, `sandbox`, `toggleOverlays`, `regenerate`, or
  any scene-selection parameter name. A test asserting the code sits inside an
  `if (DEV)` block passes for a build where the eliminator never ran — assert the
  bundle.
- **Control**: an `--mode e2e` bundle *does* contain them, or the grep passes for a
  build that produced nothing.
- Loading the production bundle with `?sandbox=1` shows the normal title screen —
  asserted from the rendered frame (§C2), not from the URL.
- The full e2e suite still passes against the dev server, unchanged.
- `make docker-up` serves a bundle with no dev surface — the deploy path is the one
  that matters.

## Done when

```sh
node scripts/e2e.mjs no-dev-surface && ./scripts/check.sh
```
