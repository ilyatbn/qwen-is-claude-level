# T14.07 — Debug mode, and the aim line leaves production (v4)

Milestone: M14 · Depends on: T13.01 · Size: ~150 lines

## Read first
- `docs/72-amendments-v4.md` §C12

## Deliverable

**`F1`** or `?debug=1` toggles debug mode: the aim ring and the direction line,
collision boxes, chunk bounds, surface points, teleport-pad radii, and an FPS
counter. **Off by default.**

The **crosshair stays** in normal play — it is the aiming affordance. The ring and
the black line go. Remote players never show an aim ring in either mode
(`docs/22` §5).

## Notes

- **FPS counter only if it is genuinely cheap.** Phaser's `game.loop.actualFps` is a
  smoothed average that under-reports for seconds after a stall — §A38 diagnosed a
  "performance regression" that was this counter lying. If shown, measure it from
  `requestAnimationFrame` deltas, and keep it debug-only.
- Fold the existing F4 overlays (T3.11) into this rather than leaving two debug
  toggles — two mechanisms for one job is how they drift.
- Debug mode must not change simulation behaviour. Assert that.

## Tests

- Default play shows no aim ring and no direction line — **sampled from the frame**
  (§C2), with a control that debug mode does show them.
- `F1` toggles, and the state survives a scene change.
- The FPS reading tracks real frame deltas, not a smoothed engine average — feed it
  known deltas and check the output.
- Enabling debug does not alter player position over a fixed input sequence.
