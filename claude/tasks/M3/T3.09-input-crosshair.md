## Deliverable

```ts
// localInput.ts
export class LocalInput {
  constructor(scene: Phaser.Scene);
  /** Sample the current frame into the wire format. */
  sample(seq: number, playerWorldPos: {x: number; y: number},
         camera: Phaser.Cameras.Scene2D.Camera): Input;
  readonly aimAngle: number;
  destroy(): void;
}
export interface Input { seq: number; buttons: number; aim: number; }

// crosshair.ts
export class Crosshair {
  constructor(scene: Phaser.Scene);
  update(playerX: number, playerY: number, aim: number): void;
  setVisible(v: boolean): void;
  destroy(): void;
}
```

Key map: `A`/`D` → LEFT/RIGHT, `W`/`S` → UP/DOWN, `Space` → JUMP, LMB → FIRE,
`F` → FLASHLIGHT. Bit values from `game-core`'s `button` module — **do not
redefine them in TypeScript**; export them through WASM or mirror them with a
comment pointing at `crates/game-core/src/player/input.rs`.

## Notes

**Convert the mouse to world coordinates before computing the angle.** Using screen
coordinates works perfectly until the camera scrolls, then aim is silently wrong
everywhere except the map origin. Use
`camera.getWorldPoint(pointer.x, pointer.y)`.

The `AIM_DEADZONE` (8 px) rule matters more than it sounds: without it the crosshair
spins wildly whenever the cursor passes over the player, which happens constantly.
Keep the previous angle when inside the deadzone.

Angle quantisation goes through the WASM helper, not a TypeScript reimplementation —
the server dequantises with the Rust version and the two must agree exactly.

The crosshair draws two things: a faint full ring at `AIM_RADIUS` (the visual cue
that aim is angular, not positional) and the crosshair sprite on the ring at the aim
angle. Both at depth 60, `scrollFactor` 1.

Right mouse button is reserved for the inventory (T4.14). Suppress the context menu
here if T0.06 did not already.

Sample input **every frame**, not on key events. Held state is what the wire format
carries (`docs/20-player-movement.md` §7); event-driven sampling loses the "still
held" information and produces a player who stops moving when nothing changes.

Do not use pointer lock — the crosshair is world-anchored and lock would fight the
inventory UI.

## Tests

`client/src/input/localInput.test.ts`, with the scene and pointer stubbed:

- Each key maps to its documented bit.
- Holding `A` and `D` sets both bits (the zeroing happens in `game-core`'s
  `move_dir`, not here — this file reports raw state).
- The aim angle for a pointer directly right of the player is 0.
- Directly below is `+π/2` (screen-space y is down).
- Directly left is `π` (or `−π`; assert via `cos`/`sin` rather than the raw value).
- A pointer 4 px from the player centre keeps the previous angle (deadzone).
- A pointer 12 px away updates the angle.
- The angle is computed from world coordinates: with the camera scrolled 500 px,
  the same screen position yields a different world angle.
- `sample` sets the returned `seq` from its argument.
- Crosshair position is exactly `AIM_RADIUS` from the player, for a sweep of angles.
