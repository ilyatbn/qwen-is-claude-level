## Deliverable

```ts
export interface OverlayFlags {
  collisionBoxes: boolean;
  coarseGrid: boolean;
  chunkBounds: boolean;
  surfacePoints: boolean;
  spawnPoints: boolean;
  fovRadius: boolean;
  buriedSlots: boolean;      // sandbox only — never in the networked game
}

export class DebugOverlay {
  constructor(scene: Phaser.Scene, core: Core);
  toggle(): void;                 // F4 cycles the whole overlay on/off
  setFlags(f: Partial<OverlayFlags>): void;
  update(camera: Phaser.Cameras.Scene2D.Camera, players: PlayerDebugInfo[]): void;
  destroy(): void;
}
```

Plus a performance readout in the sandbox: FPS, frame ms, bakes/frame, ms/bake,
pending chunk count, lightmap draws, and the player's movement state readout
(grounded, velocity, jetpack fuel, `MoveState`).

## Notes

**Draw only what is on screen.** The coarse grid at medium scale is 384 × 192 =
73 728 cells; drawing all of them freezes the tab. Compute the visible cell range
from the camera bounds and draw only those. The same applies to surface points,
which can number in the thousands.

Use a single `Phaser.GameObjects.Graphics` at depth 55 (above the lightmap so
overlays stay readable at night), cleared and redrawn each frame. Do not create
objects per cell.

`buriedSlots` is sandbox-only and must be gated on the scene, not just on a flag.
Buried slot positions are deliberately never sent to clients
(`docs/32-item-spawning.md` §5) — rendering them in the networked game would be a
straightforward wallhack. Add a comment saying so, so nobody "helpfully" enables it
later.

The movement state readout is what makes M2's physics debuggable by eye. Seeing
`grounded` flicker while walking down a slope, or `MoveState` stuck on `Jetpack`,
identifies in seconds what a headless test describes in a paragraph.

Track frame time with a rolling 60-frame average, not the instantaneous value —
instantaneous frame time is too noisy to read.

## Tests

`client/src/render/debugOverlay.test.ts`, with Graphics stubbed:

- `toggle` flips visibility and no draw calls occur while hidden.
- **Culling**: with the camera showing 1280×720 of a 3072×1536 map, the coarse-grid
  overlay issues draws only for visible cells — assert the count is bounded by the
  visible cell count, not the total. This is the test that prevents the freeze.
- Surface-point drawing is likewise culled.
- `setFlags` with a partial object leaves the other flags untouched.
- `update` with an empty player list does not throw.
- `destroy` clears and removes the graphics object.
- The frame-time average is a rolling mean over 60 samples.

## Done when

```sh
npm --prefix client test -- --run debugOverlay
```
Then in the sandbox, verify each overlay:
1. Collision boxes align with the player sprite's feet on the ground.
2. The coarse grid matches the terrain (empty cells over air, full over rock).
3. Chunk bounds show no seams in the baked fill.
4. Surface points sit on walkable ground and not on ceilings or 1-px spikes.
5. Spawn points are spread across the map, not clustered.
6. Walking down a slope shows `grounded` staying true — the T2.05 ground-snap check,
   now visible.
