## Deliverable

A thin `wasm-bindgen` shim over `game-core`. **No game logic of its own.**

```rust
#[wasm_bindgen]
pub struct GameCore { map: Map, players: Vec<LocalPlayer> }

#[wasm_bindgen]
impl GameCore {
    #[wasm_bindgen(constructor)]
    pub fn new() -> GameCore;

    pub fn generate(&mut self, seed_lo: u32, seed_hi: u32, scale: u8);
    pub fn load_mask(&mut self, w: u32, h: u32, rle: &[u8]) -> bool;   // from map_init

    // Terrain access — pointers into WASM memory, NOT copies.
    pub fn mask_ptr(&self) -> *const u8;
    pub fn mask_byte_len(&self) -> usize;
    pub fn width(&self) -> u32;
    pub fn height(&self) -> u32;

    pub fn carve(&mut self, cx: i32, cy: i32, r: i32);
    pub fn take_dirty_chunks(&mut self) -> Vec<u32>;

    // Local player prediction
    pub fn add_player(&mut self, id: u8, x: f32, y: f32);
    pub fn apply_input(&mut self, id: u8, seq: u32, buttons: u8, aim: u16, dt: f32);
    pub fn set_player_state(&mut self, id: u8, x: f32, y: f32, vx: f32, vy: f32,
                            grounded: bool, fuel: f32);
    pub fn player_state(&self, id: u8) -> Box<[f32]>;   // [x, y, vx, vy, grounded, fuel, state]

    // Metadata, as JSON — low frequency, so the serialisation cost is irrelevant
    pub fn meta_json(&self) -> String;
    pub fn mask_hash(&self) -> Box<[u8]>;
}
```

## Notes

**The mask is exposed as a pointer, never copied.** JS builds a `Uint8Array` view
over the WASM memory buffer once and re-reads it. Copying a 1 MiB mask across the
boundary on every chunk bake would dominate the frame budget.

Warn in a doc comment: the view is **invalidated whenever WASM memory grows**. The
TS wrapper (T3.02) must re-acquire it after any call that can allocate — practically,
after `generate` and `load_mask`.

The seed is split into two `u32`s because `u64` across the wasm-bindgen boundary
pulls in BigInt handling that is more trouble than it is worth. Reassemble as
`(hi as u64) << 32 | lo as u64`.

`take_dirty_chunks` returns chunk indices (`cy * chunks_x + cx`) and clears the set,
matching `Map::drain_dirty`.

`player_state` returns a flat `f32` array rather than a struct — crossing the
boundary with a struct means a serialisation step per call, and this is called every
frame.

Add `console_error_panic_hook` in the constructor. A Rust panic in WASM without it
surfaces as `unreachable executed`, with no indication of where.

Build with `--target web`, output into `client/src/core/pkg/` (gitignored).

## Tests

`wasm-bindgen-test` for the parts worth testing at the boundary:

- `generate` then `width`/`height` match the requested scale.
- `mask_byte_len` equals `(w * h + 7) / 8`.
- `carve` then `take_dirty_chunks` returns a non-empty list; a second call returns
  empty.
- `load_mask` with the RLE from a generated map reproduces the same `mask_hash`.
- `load_mask` with malformed bytes returns false rather than panicking.
- `apply_input` moves the player and `player_state` reflects it.
- `set_player_state` then `player_state` round-trips the values.
- `player_state` for an unknown id returns an empty array rather than panicking.

Native tests (plain `cargo test`) cover everything else — the logic is all in
`game-core` and already tested there.
