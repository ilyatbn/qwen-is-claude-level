## Deliverable

The primary development tool for the rest of the project: `game-core` running in the
browser with **no server**.

```ts
export class SandboxScene extends Phaser.Scene {
  create(): void;
  update(time: number, delta: number): void;
}
```

Features:
- Reads `?seed=<n>` and `?scale=small|medium|large` from the URL; defaults to a
  random seed and medium.
- A DOM control strip over the canvas: seed input, **Regenerate**, scale selector,
  carve-radius slider, and a set of overlay toggles (wired in T3.11).
- Generates a map through `Core`, builds the terrain, and places the camera at a
  spawn point.
- **Click to carve** at the cursor with the current radius, then rebake.
- Arrow keys / drag pans the camera when no player exists yet.
- An on-screen readout: seed, scale, generation ms, attempts, `used_safe_preset`,
  traversable fraction, chunk count, bakes/frame, ms/bake.

## Notes

Use plain DOM elements positioned over the canvas for the controls, not Phaser UI.
This is a dev tool; DOM inputs are five minutes of work and Phaser text inputs are
an afternoon.

**Regenerating must fully tear down the previous map** — call
`TerrainRenderer.destroy()` and increment the map generation counter before
building again. The texture-key collision described in T3.05 shows up here first,
and it shows up as the new map looking subtly like the old one, which is a confusing
symptom to chase.

Put the seed in the URL on regenerate (`history.replaceState`) so a map worth
discussing can be shared as a link. This is small and pays for itself immediately.

Display the **generation metadata prominently** — `attempts` and `used_safe_preset`
are the numbers that tell you whether the generator is healthy
(`docs/10-map-generation.md` §Pass 7d), and they are invisible unless you show them.

Click-to-carve is the fastest way to test both `carve` and the rebake path. Make the
radius slider go up to 200 so a large explosion's rebake cost can be observed
directly.

The scene stays in the build after M6, behind `?sandbox=1`. It is not throwaway
code — treat it accordingly.

## Tests

No unit tests; this scene *is* the test harness. Manual verification, and report on
each:

1. Load with no query string — a map generates and renders.
2. `?seed=12345` twice in a row produces a visibly identical map.
3. Regenerate ten times — memory does not climb without bound (check the browser's
   memory panel), which proves `destroy()` works.
4. Click-carve produces a clean circular hole with a correct grass rim on the new
   upward-facing surfaces.
5. A radius-200 carve rebakes without a visible hitch.
6. Chunk boundaries are invisible — no seams in the fill, no lines in the edge band.
7. Generation time for a medium map is under 1 s and is displayed.
8. Switching scale rebuilds correctly at all three sizes.

## Done when

All eight checks pass. **Report what the maps look like** — this is the first time
the generator from M1 is visible, and your assessment is the real acceptance
criterion. Include the generation time and the ms/bake figure.
