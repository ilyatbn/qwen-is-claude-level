## Deliverable

```ts
export class TerrainRenderer {
  constructor(scene: Phaser.Scene, core: Core, fill: CanvasImageSource,
              edge: CanvasImageSource);

  /** Create one CanvasTexture + Image per chunk and bake them all. Round start. */
  buildAll(): void;

  /** Queue chunks reported dirty by the core. */
  markDirty(chunkIds: Uint32Array): void;

  /** Called every frame: bake at most CHUNK_REBAKE_BUDGET chunks. */
  update(cameraCenter: Phaser.Math.Vector2): void;

  /** Free every texture and Image. Called on map change. */
  destroy(): void;

  readonly stats: { bakesThisFrame: number; lastBakeMs: number; pending: number };
}
```

## Notes

**One `CanvasTexture` and one `Image` per chunk**, all parented to a single
container at depth 0. Texture keys must be unique per chunk *and* per map —
`terrain_${mapGeneration}_${cx}_${cy}` — because Phaser's texture manager is global
and reusing a key across a regenerate leaves the old pixels in place. That produces
"the new map still shows bits of the old one", which is baffling if you have not hit
it before.

`destroy()` must call `scene.textures.remove(key)` for every chunk. Without it,
regenerating a map twenty times in the sandbox leaks a hundred megabytes of canvas
and the tab dies. This is the single most important line in the task.

**The rebake budget** is what keeps a meteor shower from stuttering. A dozen dirty
chunks spread over three frames is invisible; all at once is a 40 ms spike. Sort
pending chunks by distance from the camera centre and take the nearest
`CHUNK_REBAKE_BUDGET` (4) each frame.

Off-screen chunks are still rebaked — they are cheap and it avoids a visible pop
when the camera pans — but they sort last by virtue of the distance ordering.

Use a `Set<number>` for pending ids so repeated `markDirty` calls for the same chunk
before it is baked collapse into one bake.

Record `lastBakeMs` with `performance.now()` — T3.11 displays it, and it is how the
< 4 ms target from `docs/12-map-render.md` §8 gets verified.

## Tests

`client/src/render/terrain.test.ts`, with Phaser's scene and textures stubbed:

- `buildAll` creates exactly `chunksX * chunksY` textures for each scale.
- Texture keys are unique across two consecutive `buildAll` calls with different
  map generations.
- `destroy` removes every texture it created — assert the stub's remove count equals
  the create count.
- `markDirty` with duplicate ids queues each chunk once.
- `update` bakes at most `CHUNK_REBAKE_BUDGET` per call.
- With 20 chunks pending, five `update` calls drain them all.
- Pending chunks are baked nearest-camera first — queue chunks at known distances
  and assert the bake order.
- `markDirty` with an out-of-range chunk id is ignored rather than throwing.
- `stats.pending` reflects the queue length.
- Chunk id → world position round-trips (`id = cy * chunksX + cx`).
