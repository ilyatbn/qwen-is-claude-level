## Deliverable

**Part 1 — `GameScene`**, the networked counterpart to the M3 sandbox: connect,
receive the map, build terrain, run the `Predictor` for the local player, the
`RemoteInterpolator` for everyone else, render items and projectiles from the
`WorldMirror`, and show the HUD, inventory and scoreboard.

**Part 2 — the integration suite.** A real server on an ephemeral port, real
socket.io clients, real rounds.

## Notes

Use a shortened `ROUND_SECONDS` (5) and `WARMUP_SECONDS` (1) via config so the suite
runs in seconds rather than minutes. `FIXED_SEED` makes every run reproducible.

Drive clients with **scripted input sequences**, not random ones. A failing random
test that cannot be re-run is worse than no test.

The mask-agreement test is the most valuable one in the project: it exercises carve
rasterisation, event ordering, sequence handling and the checksum path all at once,
and it is the single check that the terrain replication design actually works.

Mark the whole suite `#[ignore]` if it proves slow, and run it explicitly at the end
of M6. Say in your report whether you did.

`GameScene` is not unit tested (`docs/60-testing.md` §7) — it is verified by the
manual checkpoint below.

## Tests

**Connection and lifecycle:**
- Client connects, joins, receives `welcome` then `map_init`, and decodes a mask
  whose dimensions match the configured scale.
- Six clients join successfully; a seventh gets `join_error { reason: "full" }`.
- A client disconnecting mid-tick does not panic the room and emits `player_leave`.
- A client that never sends `ready` is dropped after the timeout.

**Simulation:**
- 200 ticks of input yields ~66 snapshots (20 Hz), each of the expected size.
- Inputs sent at 60 Hz are all processed (check `last_input_seq` advances
  monotonically).
- **Two clients' mask hashes match the server's after 100 real fire commands.**
- A player's predicted position matches the server's within
  `RECONCILE_EPSILON_PX` over 600 ticks with no artificial latency.
- Damage, death and respawn propagate to every client.
- An item picked up by one client disappears for all.
- **Deterministic tie**: two clients contacting one item on the same tick — the same
  one wins, across 20 runs.

**Round flow:**
- Lobby → Warmup → Playing → Ended, with `round_state` at each transition.
- No damage lands during Warmup.
- A majority restart vote produces a new round with a different seed and zeroed
  scores.
- The full sequence runs end to end without a panic or a leaked task.

**Robustness:**
- A client sending malformed binary is not disconnected, and the server logs a
  `warn`.
- A client flooding 10 000 inputs in one tick does not stall the room.
- Killing a client process abruptly (drop the socket) emits `player_leave`.

## Done when

```sh
cargo test -p game-server --test integration -- --test-threads=1
```

Then the **manual milestone checkpoint**: run
`docker compose -f docker/docker-compose.yml up`, open two browser windows, and
confirm:

1. Both players see each other move smoothly.
2. Terrain destroyed by one appears identically for the other.
3. Kills and deaths update both scoreboards.
4. Items picked up by one vanish for the other.
5. Day/night and a weather effect run in sync.
6. The round ends and the restart vote produces a new map for both.
7. The browser console reports transport `websocket`, not `polling`.
