## Deliverable

**Rust:**
```rust

    -> Vec<u8>;
```

**TypeScript:**
```ts
export interface Snapshot {
  tick: number; roundTime: number; darkness: number;
  players: SnapshotPlayer[]; lastInputSeq: number;
}
export interface SnapshotPlayer {
  id: number; x: number; y: number; vx: number; vy: number; aim: number;
  health: number; flags: number; jetpackFuel: number; selectedItem: number;
}
export function decodeSnapshot(buf: ArrayBuffer): Snapshot;
```

Layout:
```
u32 tick   u16 round_time_ds   u8 darkness   u8 player_count
per player (14 bytes): u8 id, i16 x, i16 y, i16 vx, i16 vy, u16 aim,
                       u8 health, u8 flags, u8 jetpack_fuel, u8 selected_item
u32 last_input_seq
```
Flags: bit 0 alive, 1 grounded, 2 jetpack_active, 3 shield_active,
4 flashlight_on, 5 iframes, 6–7 reserved.

Total: `9 + n*14 + 4` bytes. Six players = 97 bytes.

## Notes

`last_input_seq` is **per recipient** — it is the highest input sequence the server
had processed *from that client* when the snapshot was built. That is why
`encode_snapshot` takes `for_player`. Everything else in the payload is identical
for everyone, so if this ever needs optimising, encode the common part once and
patch the last four bytes per recipient. Do not do that yet.

Quantisation:
- positions and velocities are `i16` pixels — the largest map is 4096×2048, and
  velocity is bounded well inside `±32767`. Clamp rather than wrap on the way in;
  a wrapped velocity teleports a player across the map.
- `health` is `u8`, so `HEALTH_CAP` (150) fits directly with no scaling.
- `jetpack_fuel` is `fuel / JETPACK_MAX_FUEL * 255`.
- `darkness` is `darkness * 255` (note: not `/ NIGHT_DARKNESS`, so full night
  encodes as 209 — be consistent between encoder and decoder).
- `selected_item` is the `ItemId` low byte, with 255 meaning none. There are 6 items,
  so this is safe; add a comment that it breaks past 254 items.

Velocities are sent so the client can extrapolate smoothly through a dropped
snapshot (`docs/42-netcode-prediction.md` §4). They are not optional.

Round time in **deciseconds** as `u16` covers 6553 s — plenty for a 240 s round.

## Tests

**Rust:**
- Encoded length is exactly `9 + n*14 + 4` for n = 0, 1, 6.
- Every field round-trips through a matching Rust decoder (write one for the test).
- Positions at the map's extremes encode and decode exactly.
- A velocity beyond `i16` range is **clamped**, not wrapped — assert the sign is
  preserved.
- Health of 150 encodes as 150.
- Every flag bit maps to the right field, tested independently.
- `last_input_seq` differs per recipient for the same world state.

**TypeScript:**
- `decodeSnapshot` on a Rust-generated fixture matches expected values field by
  field.
- A truncated buffer throws.
- A buffer whose length disagrees with `player_count` throws.
- Flags decode to the right booleans.
- `jetpackFuel` and `darkness` dequantise within 1/255 of the original.
- `selectedItem === 255` decodes to "none".
- **Fuzz**: 1000 random buffers are rejected without an unhandled throw.
- Six players decode to exactly six entries with unique ids.
