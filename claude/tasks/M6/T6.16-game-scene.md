## Why this task exists

T6.08 built `Connection` and `WorldMirror`; nothing consumes them. `scenes/` holds
Boot, Preview and Sandbox only, so the M6 checkpoint — two clients, one round,
terrain destruction visible in both — is unreachable. T8.06 and T8.08 both list
`client/src/scenes/Game.ts` under **Touch only** as though it already exists.

The planning error: every M6 task named a *mechanism* and none named the *scene
that runs them*. A milestone checkpoint that no task delivers is a gap, and it was
found by a builder noticing the checkpoint could not be driven — not by the plan.

## Deliverable

```ts
export class GameScene extends Phaser.Scene {
  // joins via Connection, decodes map_init, builds chunks, then emits `ready`
  // predicts the local body, interpolates remotes, applies carves in seq order
}
```

- Reuses the M3 render stack unchanged: chunk manager, camera rig, lightmap, sky,
  ordnance layer, HUD, inventory panel. **Extract** what Sandbox already has rather
  than copying it — two divergent render paths is how the sandbox stops predicting
  what the game does.
- Remote players are drawn from the interpolated snapshot buffer, never through
  `apply_input`. The local player is predicted and reconciled.
- Carves apply in `seq` order; a gap buffers and triggers `resync_map` after 2 s.
- Culls remote players outside your FoV, per `docs/14` §5.
- `?e2e=1` exposes the same `window.__game` debug handle the sandbox does, plus
  `players`, `rtt`, `pendingInputs`, `lastServerTick` and `maskChecksum`.

## Notes

- The scene must survive a `map_init` arriving **after** the first snapshot, and a
  snapshot arriving before the mask exists. Both happen on a mid-round join.
- Do not tick the sim from the render frame rate — fixed timestep, as Sandbox does.
- Joining mid-round is normal (`docs/41` §4), not an edge case.

## Tests

Driven headlessly through Playwright, two browser contexts against one server:

- Both clients join, both reach `ready`, both report the same `mapW`/`mapH`/seed.
- Each sees two players; the remote one moves when the other client holds a key.
- A rocket fired by client A produces the same solid-pixel count in both, and the
  same `maskChecksum`.
- A client joining 10 s into the round receives the already-damaged map and its
  checksum matches.
- Screenshots from both contexts, written to `shots/`, and **looked at**.
