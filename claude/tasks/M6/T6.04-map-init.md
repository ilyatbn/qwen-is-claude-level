## Deliverable

**Rust encode:**
```rust
pub fn encode_map_init(map: &Map) -> Vec<u8>;
```

**TypeScript decode:**
```ts
export interface MapInit {
  width: number; height: number; seed: bigint; scale: number; theme: number;
  wind: number; spawnPoints: {x: number; y: number}[];
  decorations: {kind: number; x: number; y: number; flags: number}[];
  rle: Uint8Array;
}
export function decodeMapInit(buf: ArrayBuffer): MapInit;
```

Layout, exactly as the doc:
```
u32 magic 0x4D415031 ("MAP1")   u32 width   u32 height   u64 seed
u8 scale   u8 theme   f32 wind
u16 spawn_count      then spawn_count × (i16 x, i16 y)
u16 decoration_count then decoration_count × (u16 kind, i16 x, i16 y, u8 flags)
u32 rle_byte_len     then the RLE payload
```
All little-endian.

## Notes

**Buried item slots are deliberately not included.** Sending them would put a
complete treasure map in every client's memory, which is a straightforward wallhack
for the game's most interesting mechanic. Put a comment saying so, because the
omission looks like an oversight to anyone extending the struct later.

`surface_points` are also not sent — they are large and the client does not need
them. The client can derive standability from the mask if it ever needs to.

The magic number catches version skew loudly. A client that receives a different
magic should log an error and refuse the map rather than decoding garbage.

The client feeds `rle` straight into `Core.loadMask` (T3.02), which decodes it in
Rust — the TypeScript side never decodes RLE itself. That keeps exactly one RLE
implementation in the project.

**Validate on the client**: `width`/`height` must be multiples of `CHUNK_SIZE` and
within the known scale sizes; `rle_byte_len` must match the remaining buffer length;
counts must be sane. A malformed `map_init` should produce a clear error, not a
half-built map.

At medium scale this message is roughly 20–60 KB. It is sent once per round, so no
further compression is warranted (socket.io's permessage-deflate takes another bite
anyway).

## Tests

**Rust** (`codec.rs` in-file tests):
- `encode_map_init` produces the magic number first.
- The byte length matches the layout for a known map.
- Spawn and decoration counts match the map's metadata.
- **No buried slot data appears anywhere in the payload** — search the bytes for
  each slot's coordinates and assert absence. This is the anti-wallhack test.

**TypeScript** (`codec.test.ts`):
- Round-trip: encode in Rust (via a committed fixture or a WASM call), decode in TS,
  and every field matches.
- The decoded `rle` fed to `Core.loadMask` yields a mask whose hash matches the
  server's.
- A wrong magic number throws a clear error.
- A truncated buffer throws rather than producing a partial object.
- `rle_byte_len` disagreeing with the remaining length throws.
- Dimensions that are not multiples of `CHUNK_SIZE` are rejected.
- Absurd spawn/decoration counts are rejected without allocating.
- **Fuzz**: 1000 random byte buffers are all rejected without an unhandled throw.
