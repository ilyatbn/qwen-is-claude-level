## Deliverable

```rust
/// Per-socket state, stored in the socketioxide extension map.
pub struct Session { pub player_id: Option<PlayerId>, pub name: String,
                     pub skin_id: u16, pub ready: bool, pub joined_at: Instant }

/// Register every socket.io handler on the namespace.
pub fn register(io: &SocketIo, room: RoomHandle, config: Arc<Config>);
```

Flow:
1. `on_connect` — create a `Session`, log at `info` on `game::net` with the socket id.
2. `join { name, skin_id }` — validate, assign a `PlayerId`, send `welcome`, then
   `map_init` (T6.04).
3. `ready` — the player enters the simulation.
4. Disconnect — send `Leave` to the room.

## Notes

**Validation on `join`:**
- name is 1–16 characters after trimming, and is sanitised (strip control characters
  and anything that would break the client's text rendering);
- the room is not at `MAX_PLAYERS` (6) — otherwise
  `join_error { reason: "full" }`;
- a second `join` on the same socket is ignored, not a second player.

Never trust `skin_id`. The server does not validate it against a list (it does not
know what skins exist — `docs/50-sprites-skins.md` §1); it just passes it through.
But do bound it to `u16` and log anything absurd.

**A client that never sends `ready` is seated but not simulated, and is dropped
after 30 s.** Track `joined_at` and sweep in the room loop. Without this, a client
that fails to decode the map holds a slot forever, and on a 6-player room that is
noticeable.

**Joining mid-round is allowed** (`docs/41-server-loop-rooms.md` §4) and matters —
a 4-minute round is too long to wait out. The joiner gets the *current, damaged* map,
an empty inventory, the current scoreboard, a safe spawn with i-frames, and score 0.

`PlayerId` is a `u8` and must be **reused** when a player leaves, since the snapshot
format only has 256 of them and a long-lived server would otherwise exhaust them.
Keep a free list.

The `welcome` payload is JSON and includes everything in `docs/40-net-protocol.md`
§3 — including `seed` and `scale`, which the client shows on the HUD so a bug report
carries a reproducible seed (`docs/61-logging-debug.md` §8).

## Tests

`crates/game-server/tests/join.rs`, with real socket.io clients:

- Connect → `join` → `welcome` arrives with a valid `player_id` and the round state.
- `welcome` includes `seed` and `scale`.
- A 7th client gets `join_error { reason: "full" }`.
- An empty name is rejected; a 17-character name is rejected or truncated (assert
  which you implemented).
- Control characters are stripped from the name.
- A second `join` on the same socket does not create a second player.
- Disconnecting frees the slot and a new client can then join.
- **Player ids are reused** after a disconnect.
- A player who never sends `ready` is dropped after 30 s and their slot is freed.
- A mid-round joiner receives the current damaged map, not a pristine one — carve a
  large hole first and assert the joiner's mask hash matches the server's.
- A mid-round joiner starts at score 0 with an empty inventory and i-frames.
- `player_join` is broadcast to existing players.
- `player_leave` is broadcast on disconnect.
