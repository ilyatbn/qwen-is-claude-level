# T13.06 — The round ends (v4)

Milestone: M13 · Depends on: T6.12 · Size: ~200 lines

## Read first
- `docs/72-amendments-v4.md` §C3

## The bug

`ROUND_SECONDS` elapses and **nothing happens**. The server's `Ended` phase exists
and the client ignores it — §A39 again: a mechanism with no consumer.

## Touch only
- `client/src/ui/results.ts` (+ test)
- `client/src/scenes/GameScene.ts`

## Deliverable

On `Ended`: input stops, and a **results screen** appears over the frozen field
showing the final scoreboard — name, score, kills, deaths — sorted per `docs/21` §6,
local player highlighted, ties shown as ties.

Two buttons: **Play again** (`vote_restart`, showing the vote count and the
`ENDED_SECONDS` countdown) and **Exit to title**.

Vote carries → new round, new seed, scores reset. Vote fails → title.

## Notes

- The server already freezes the sim in `Ended`; the client must stop *sending*
  input too, or it queues a burst that lands on the next round.
- Non-voters abstain, they do not veto (`docs/41` §3).
- A player joining during `Ended` sees the results screen, not an empty field.

## Tests

- A round played to `Ended` shows the screen — driven end to end on a shortened
  `ROUND_SECONDS`, asserting the **rendered** screen (§C2), with a control that it is
  absent during `Playing`.
- Scores on screen match the server's, reconciled against deaths observed during the
  round (the T9.06 technique).
- **Play again** starts a round with a different seed and zeroed scores.
- **Exit to title** leaves the room — the old room receives nothing further.

## Done when

```sh
npm --prefix client test -- --run results && node scripts/e2e.mjs round-end
```
