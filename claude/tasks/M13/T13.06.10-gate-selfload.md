# T13.06.10 — The gate breaks its own wall-clock assertions (v4)

Milestone: M13 · Depends on: T13.06.1 · Size: investigation, then a fix

## The finding

`a_room_whose_last_human_leaves_goes_back_to_lobby_despite_its_bots` fails inside
`cargo test --workspace` and passes **6/6 standalone** and **11/11 running the whole
lobby suite twice**. Measured, not assumed.

`lobby.rs` has 11 tests, each spawning a real socket server on a
`#[tokio::test(flavor = "multi_thread", worker_threads = 4)]` runtime, and cargo runs
them in parallel — 44 workers plus 11 servers on 16 cores. Every wait is a fixed
10 s `wait_for` loop. Under that load a wall-clock budget becomes a coin flip.

**This is §B23 from inside the gate.** Three earlier sessions blamed "contention" for
flakes that turned out to be self-inflicted process leaks; this time the load is
self-inflicted by the test runner itself.

## Do not just raise the timeout

§A28: a gate that fails on a coin flip gates nothing, and raising a budget treats the
symptom. Options, cheapest first — **measure the reproduction rate before and after**:

- Limit in-binary parallelism for the socket suites (`--test-threads`), the way
  T6.13's Done-when already does for `integration`.
- Give each server test fewer worker threads — 4 each is oversubscription at 11×.
- Make `wait_for` wait on the **effect** with an adaptive bound rather than a fixed
  wall-clock count.

## Notes

- The failure mode is silent and misleading: it reports "waited 10 s for 1 `welcome`,
  saw 0" — which reads as a broken handshake, not a busy box, and would send someone
  debugging the server. §B23 records that a *false failure* is the expensive kind.
- Do not fix this by marking the test `#[ignore]`. An ignored test that a person must
  remember to run is not a gate.

## Tests

- Reproduction rate stated before and after, over ≥10 workspace runs.
- The whole workspace gate passes repeatedly on an idle box.
- The fix does not make the suite meaningfully slower — state the before/after wall
  time.
