# T13.06.6 — Gun projectiles are still invisible (v4)

Milestone: M13 · Depends on: T13.03 · Size: investigation, then a fix

## Read first
- `docs/72-amendments-v4.md` §C23

## The bug

T13.03 shipped visible ordnance with a **passing pixel test**, and guns are still not
visible in play. That means the test is sampling something the player is not looking
at — so fix the test as well as the bug.

## Find out which class before changing anything

A bazooka rocket is a projectile; a pistol shot is a hitscan tracer. They take
different paths. Candidates, and the measurement that separates them:

- the tracer path never reaches `GameScene` — the §C0 shape a third time;
- tracers draw but 0.09 s is too brief to see;
- the projectile path covers *weapon fire* and not *server-spawned* projectiles
  (which is also §C22's meteor bug — if so, one fix covers both).

Count at both ends first (§A39): what the server has alive versus what is drawn.

## Notes

- **Do not lengthen the tracer to make it visible without first establishing it is
  drawn at all.** A brighter, longer tracer that is never created looks identical to
  one that is.
- §A3 already requires tracers to light their own path; that was verified in the
  sandbox and is a good place to compare against.

## Tests

- **Rendered, per delivery kind**: a frame during flight/fire shows the weapon's
  colour for a projectile weapon *and* for a hitscan weapon, each with a control.
- Both-ends counters for each kind.
- The T13.03 test is corrected so it would have caught this — falsify it against the
  broken build and show it goes red.
