# T13.06.11 — The room reaper has no caller (v4)

Milestone: M13 · Depends on: T13.06.1 · Size: ~90 lines

## The bug, observed live

A running server with **zero players** reported `rooms: 2` steady over 40 s. The log
shows both rooms correctly entering the TTL:

```
last human left; room is on the clock  room=2 ttl_s=30.0
last human left; back to lobby         room=1
```

…and then nothing ever removes them. `RoomRegistry::reap()` exists at
`registry.rs:373` and **every one of its five callers is a test** in that file's own
`#[cfg(test)]` module. Nothing in production calls it.

**Sixteenth instance of §A39** — a mechanism built, unit-tested, and wired to
nothing — found within an hour of the fifteenth.

## Why it matters

Rooms accumulate for the life of the process, each holding a generated map
(~648 KiB medium, ~1.2 MiB large — §B2). At `MAX_ROOMS` (32) the registry refuses to
create any more, so a long-running server eventually **cannot start a new game**, and
the symptom a player sees is "create game does nothing".

## Touch only
- `crates/game-server/src/app.rs` (the sweep task)
- `crates/game-server/src/registry.rs`

## Deliverable

A periodic sweep that calls `reap()` and shuts down the returned rooms. It belongs
beside whatever else ticks at the process level, not inside a room — a room cannot
reap itself.

## Notes

- `reap()` itself is correct and tested; **do not rewrite it**. The bug is the
  absence of a caller.
- Shut the room's task down, do not just drop the handle, or the tick loop survives
  its registry entry — which is the same leak one layer down.
- Interval: `ROOM_EMPTY_TTL` is 30 s, so sweeping every few seconds is ample. Do not
  sweep every tick.

## Tests

- **The test that would have caught it**: a server with a room whose last human left
  reports `rooms: 0` after `ROOM_EMPTY_TTL`, driven through the real server, not by
  calling `reap()` directly. **A test that calls the function is not a caller** —
  that is exactly how this shipped.
- A room with a human in it is never reaped.
- A `Lobby` room with bots and no humans **is** reaped (bots do not keep a room alive,
  §B1).
- The reaped room's task is gone — assert the tick stops, not just the registry entry.
- Falsify by removing the sweep call: the end-to-end test must go red.

## Done when

```sh
cargo test -p game-server --test rooms && node scripts/e2e.mjs lobby-start
```
