# T13.03 — Missiles, grenades and bullets you can see (v4)

Milestone: M13 · Depends on: T13.01, T13.02 · Size: ~180 lines

## Read first
- `docs/72-amendments-v4.md` §C4
- `docs/70-amendments-v2.md` §A3 (every shot is visible and every shot digs)

## The bug

No projectile is visible in the game. You cannot see what you fired or what is
being fired at you, which is the single most important thing a shooter draws.
`OrdnanceLayer` exists and is imported by `GameScene`; the projectiles never arrive
on screen.

## Touch only
- `client/src/render/ordnance.ts`, `ordnance-state.ts` (+ tests)
- `client/src/render/worldView.ts` (own the layer, per §C1)

## Deliverable

Every projectile draws as a coloured dot with the size and colour in §C4's table,
with a fading trail where the table says so. **Deliberately placeholder** — real
sprites replace these later without touching the layer, so keep the art behind one
lookup.

Every projectile is a **light source at night** (§A3).

## Notes

- Drive position from `projectile_spawn` / the local simulation between events, and
  remove on `projectile_despawn` or `explosion` (`docs/42` §5).
- Hitscan already has tracers (§A3) — make sure they reach the game scene too. A
  tracer is shorter than a screenshot round-trip, so the check must freeze or retry
  on the effect.
- Pool the sprites. A machinegun at 11 rounds/s must not allocate per shot.

## Tests

- **Pixel acceptance (§C2)**: a frame mid-flight contains pixels of the weapon's
  colour that the frame before does not, with a control region that does not change.
- Count at both ends (§A39): projectiles the server says are alive vs sprites drawn.
- Trail buffers never exceed `PROJECTILE_TRAIL_LEN`; `removeProjectile` on an
  unknown id is a no-op.
- At night, a projectile lights the terrain around it — sampled, not counted.
