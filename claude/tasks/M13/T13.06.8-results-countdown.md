# T13.06.8 — The results countdown counts down (v4)

Milestone: M13 · Depends on: T13.06 · Size: ~60 lines

## Read first
- `docs/72-amendments-v4.md` §C25

## The bug

The `ENDED_SECONDS` countdown on the results screen is static.

## Deliverable

It ticks, driven by the **server's** round time like every other timer (§B4) — a
local stopwatch drifts, and this one has a vote deadline attached.

## Notes

- The same rule already fixed the death countdown in T10.06: recompute against the
  server clock on every snapshot rather than running a local interval.
- At zero the vote resolves; the screen must agree with what the server then does.

## Tests

- The displayed value matches the server's remaining time within a tick, sampled at
  several points — not just at the start.
- It reaches zero exactly when the phase changes.
- **Rendered**: the number on screen differs between two frames a second apart (§C2),
  with a control that it does not change while paused on a non-`Ended` phase.

## Done when

```sh
npm --prefix client test -- --run results && node scripts/e2e.mjs round-end
```
