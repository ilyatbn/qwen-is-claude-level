# T13.01 — One render path, and the terrain rebake nobody wired (v4)

Milestone: M13 · Depends on: T6.16 · Size: ~250 lines

## Read first
- `docs/72-amendments-v4.md` §C0, §C1
- `docs/12-map-render.md` §5 (layer order), §6 (rebaking)

## The bug

`grep -c 'rebake\|markDirty\|dirty' client/src/scenes/GameScene.ts` → **0**.

`GameScene` decodes `carve`, applies it to the mask — so collision changes and the
minimap updates — and never calls `TerrainLayer.markDirty()`. **You walk through a
hole you cannot see.** `TerrainLayer.markDirty(chunkIds)` has existed since T3.05.

The cause is structural: `SandboxScene` was built first and grew every feature;
`GameScene` arrived in T6.16 with `WorldView`, which `SandboxScene` does **not**
use. The T9.02 journal entry recorded this exact hazard and it was never scheduled.

## Touch only
- `client/src/render/worldView.ts`
- `client/src/scenes/GameScene.ts`, `client/src/scenes/SandboxScene.ts`
- `client/src/render/worldView.test.ts`

## Deliverable

`WorldView.applyCarve(x, y, r)` applies to the mask **and** marks the touched chunks
dirty. Applying a carve without marking dirty is not reachable from a scene.

`SandboxScene` migrates onto `WorldView`. Sandbox-only controls (seed box, scale
switcher, weather triggers, overlays) become a **panel over a shared world**, not a
second world.

## Notes

- Do not fix this by adding a `markDirty` call to `GameScene`. That leaves two paths
  and the next feature pays again — which is the whole finding (§C0).
- The dirty set comes from the carve itself; `CarveResult.dirty_chunks` already
  exists in `game-core` and crosses the WASM boundary.
- Rebaking is budgeted (`CHUNK_REBAKE_BUDGET`, nearest-to-camera first) — a meteor
  shower dirties a dozen chunks and must not hitch (`docs/12` §6).

## Tests

- **The acceptance test is a sampled pixel** (§C2): carve a circle in the *game*
  scene and assert pixels inside it changed from rock, **with a control** that
  pixels outside it did not.
- Both scenes build the same layer set in the same depth order — assert on the
  resulting layers, not that both call `WorldView`, so a scene that adds one inline
  still fails.
- Falsify at the live binding site: remove the `markDirty` inside `applyCarve` and
  the pixel test must fail.
- A carve arriving while a rebake is pending does not lose either.
