## 2. Authority & tick model (locked)

- **Server-authoritative.** The server owns positions, physics, damage,
  inventory, round state. Clients never trust their own simulation.
- **Fixed tick: 20 Hz** (50 ms) server-side, driven by `server/src/tick.rs`.
  Each tick: apply queued inputs → step rapier world → update effects →
  update round timer → build snapshot.
- **Snapshots: 10 Hz** (every 2nd tick) broadcast to all players in the room.
  Snapshot = full state of all players + projectiles + active effects +
  day/night phase + round timer + scores. (6 players, small payload.)
- **Tile destruction events** are broadcast immediately as events (not in
  snapshots) so terrain updates feel instant.
- **Client**: sends input frames at 20 Hz (key state, not key presses).
  Renders remote players by linearly interpolating between the last two
  snapshots (render at 60 fps, 100 ms interpolation delay).
- **Determinism rule**: `game-core` must produce identical state for the
  same (seed, tick count, input sequence). The RNG wrapper (§4) is the only
  randomness source. Tests rely on this.

## 3. Data flow

```
client keys/mouse ──20Hz input──▶ server net.rs ──▶ tick.rs queue
tick.rs (20Hz): inputs ─▶ game-core.step(tick, inputs)
   └─ rapier step, effects, round, items, damage
   └─ produces: Snapshot (10Hz) + Vec<Event> (tile destroy, pickup,
              projectile, kill, effect start/stop, crate drop...)
server net.rs ──snapshot+events──▶ all clients in room
client: interpolate snapshots, apply events, render
```

## 4. Seeded RNG

- `game-core/src/rng.rs` wraps `rand::rngs::StdRng` (or `rand_chacha::ChaCha8Rng`)
  behind a `GameRng` struct. All randomness in `game-core` goes through it.
- One `GameRng` per round, seeded from the round seed (u64).
- The seed is generated by the server when a round starts (from system
  entropy) and included in the `round_start` message so clients/tests can
  replay the exact map. Dev override: `?seed=12345` query param or env
  `WIPGAME_SEED` for reproducible dev rounds.

## 5. Physics

- `rapier2d` inside `game-core`. World built per round:
  - Terrain: solid tiles merged into horizontal AABB segments → fixed
    colliders. On tile destruction, rebuild only affected segments.
  - Players: dynamic rigid bodies, small capsule/rectangle, low friction.
- Physics step is part of the fixed tick (dt = 0.05 s). No sub-stepping in v1.
- Collision groups: players hit players + terrain; projectiles hit terrain
  + players.

## 7. Conventions

- Rust: edition 2021, `thiserror` for errors, `tracing` for logs.
  `game-core` has ZERO dependencies on async/IO crates.
- TS: strict mode, no `any`. Protocol types in `src/protocol.ts` must stay
  in sync with `protocol.rs` (T0.2 defines both; later tasks change both
  together when a task says so).
- All tunable numbers (damage, speeds, durations) live in `*_config.rs` /
  config objects defined in the relevant doc, not scattered as literals.
- Naming: files snake_case (Rust), PascalCase (TS classes/scenes).
